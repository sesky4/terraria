# 投射物与战斗判定

> 代码根：`decompiled/Terraria/Terraria/`，下文所有 `文件:行号` 均相对该目录。
> 反编译代码里大量 `num3` / `flag2` / `num6` 是 IL 局部变量槽，本文一律翻译成工程含义；能用命名方法判断的地方优先引用命名方法。

## 一句话结论

Terraria 的战斗是**多条并行结算链**：玩家近战挥砍在 `Player.ItemCheck_MeleeHitNPCs` 里直接判定并结算；近战/远程武器生成的弹幕在 `Projectile.AI()` 里跑完位移后调用 `Projectile.Damage()`，用「弹幕矩形 vs NPC 矩形」做命中，再统一走 `NPC.StrikeNPC` 的「防御减伤 → 暴击翻倍 → 承伤倍率 → 击退衰减」链；而玩家被怪物打则是另一条 `Player.Hurt` 链（「闪避 → 减伤 → 无敌帧 → 护盾分流 → 最小伤害」）。三条链共享的只有 `Main.CalculateDamage*` 这条最朴素的「伤害 − 防御×系数」公式。

## 执行流程

### 1. 弹幕每帧驱动：`Projectile.Update`

`Projectile.Update(int i)`（`Terraria/Projectile.cs:16765`）是整个弹幕子系统的根循环，其中一层 `while (numUpdates >= 0)` 就是 **`extraUpdates`（每帧额外子步）** 的实现：

1. `Terraria/Projectile.cs:16781`：`numUpdates = extraUpdates`，进入循环先 `numUpdates--`，因此一个游戏帧里 AI 会被执行 `extraUpdates + 1` 次。高速箭矢的「多段插值」靠它，而不是靠射线检测。
2. `Terraria/Projectile.cs:16790-16804`：出界处理 —— 普通弹幕直接 `active = false`；若 `minion` 且主人 `active && !dead`，则把 `Center` 拉回 `player.Center` 并**直接结束本帧 `Update()`**（`Terraria/Projectile.cs:16799`，剩余子步与 `Damage()` 都不执行）；否则（非 minion、或是 minion 但主人不 active / 已死）走 `active = false`。
3. `Terraria/Projectile.cs:16881`：子步内调用 `AI()`。
4. `Terraria/Projectile.cs:17185`：子步收尾统一调用 `Damage()`。**每个子步都做一次命中检测**，这正是高速穿透弹能在 1 帧内命中多个目标的原因。
5. `Terraria/Projectile.cs:17304-17316`：存活判定 —— 先处理「DD2 炮台在被围城时续命」（`timeLeft++`），再 `timeLeft--`；`timeLeft <= 0` 或 `penetrate == 0` 都触发 `Kill()`（`Terraria/Projectile.cs:17309` / `Terraria/Projectile.cs:17313`）。
6. `Terraria/Projectile.cs:17329-17350`：只有 `owner == Main.myPlayer` 的客户端负责 `NetMessage.SendData(27, ...)` 同步弹幕位置，并有 `netSpam` 限流。

> 网络模型：弹幕伤害**只在所有者客户端计算**。`NewProjectile` 开头断言 `Main.netMode == 0 || Owner == Main.myPlayer`（`Terraria/Projectile.cs:10870`），不满足直接 `return 1000`（越界索引，即「生成失败」）。所以 `Damage()` 里 `Damage_PVE` / `Damage_PVP` 只在 `owner == Main.myPlayer` 分支执行（`Terraria/Projectile.cs:12516-12523`），而 `Damage_EVP`（怪物弹幕打玩家）则要求非专用服务端（`Terraria/Projectile.cs:12525`）。

### 2. AI 分派：一条约 1.4 万行的 if-else 链

`Projectile.AI()`（`Terraria/Projectile.cs:23405`）的形式是：

```csharp
if (aiStyle == 1) { AI_001(); }
else if (aiStyle == 2) { /* 内联：受重力抛射物 + 大量 type 特判 */ }
else if (aiStyle == 3) { AI_003_Boomerang(); }
...
else if (aiStyle == 210) { AI_210_YoyoShots(); }
```
（链头 `Terraria/Projectile.cs:23405-23413`，链尾 `Terraria/Projectile.cs:37401-37459`）

设计上分三层，阅读时要按层定位：

- **aiStyle 层**：约 200 种行为模板（箭、回旋镖、魔法追踪弹、链枷、鞭子、召唤物……），分派点集中在 `Terraria/Projectile.cs:23405-37459`。
- **type 层**：同一 aiStyle 下的具体弹幕差异，靠 `if (type == N)` 或 `switch (type)` 内联。典型是 `aiStyle == 2`（受重力抛射物）里针对 909/162/968/304/510 等的特判（`Terraria/Projectile.cs:23463` 起）。
- **命名函数层**：复杂 aiStyle 被抽成 `AI_0xx_名称()`，例如 `AI_003_Boomerang`（`Terraria/Projectile.cs:39547`）、`AI_009_MagicMissiles`（`Terraria/Projectile.cs:43955`）、`AI_120_StardustGuardian`（`Terraria/Projectile.cs:45412`）。

`aiStyle == 2` 分支开头（`Terraria/Projectile.cs:23417`）会叠加 `Main.windPhysics` 风力，是「全局环境耦合进 AI」的例子。

**语法糖提示**：各 `AI_xxx` 内部是「状态机 = `ai[0]` 计时器 + `if (timer > N) 切换阶段`」的手写展开，不是 async 状态机；`Projectile.Update` 里的 `numUpdates--; continue;`（`Terraria/Projectile.cs:16787`）就是普通 `while` 的 `continue`，不是状态跳转。

### 3. 伤害入口：`Projectile.Damage()` 的四路分流

`Terraria/Projectile.cs:12502-12531`：

1. `Terraria/Projectile.cs:12511`：`Damage_CanDealDamage()` 先做**反向黑名单**（`Terraria/Projectile.cs:12461`）。这里是一长串 `type == N` / `aiStyle == N` 的「何时不造成伤害」判断，例如宠物（`Main.projPet[type]`，`Terraria/Projectile.cs:12495`）默认不造成伤害。**改任何弹幕的伤害行为，第一站都是这张表。**
2. `Terraria/Projectile.cs:12514-12517`：友好弹幕顺手 `CutTiles()`（镐类/近战弹幕砍草、藤蔓）。
3. `Terraria/Projectile.cs:12519-12524`：`owner == Main.myPlayer` 时依次跑 `Damage_PVE`（打怪）与 `Damage_PVP`（打玩家，仅 hostile 模式）。
4. `Terraria/Projectile.cs:12525-12528`：非专用服务器的客户端执行 `Damage_EVP`（怪物弹幕 → 玩家）。

伤害倍率在这里统一取得：`Damage_GetProjectileSpecificDamageMultiplier()`（`Terraria/Projectile.cs:14502`），按弹幕类型给出倍率，例如「火箭对本目标双倍」（`Terraria/Projectile.cs:14506`）、「静止地雷三倍」（`Terraria/Projectile.cs:14510`）、「链枷抛出态 2 倍」（`Terraria/Projectile.cs:14533`）、「泰拉之刃剑气按玩家速度 0.1~1.0 缩放」（`Terraria/Projectile.cs:14537`）。

### 4. 命中判定：AABB 兜底，特例用线段/圆/扇形

#### 4.1 遍历与四道免疫闸门

`Damage_PVE`（`Terraria/Projectile.cs:12572`）遍历全部 `Main.maxNPCs`，对每个 NPC 先过 `Terraria/Projectile.cs:12595` 的判断（局部变量 `flag2` 表示「本次允许命中」）：

```csharp
bool allowed = (!usesLocalNPCImmunity && !usesIDStaticNPCImmunity)
            || (usesLocalNPCImmunity && array[i] == 0)
            || (usesIDStaticNPCImmunity && IsNPCIndexImmuneToProjectileType(immunityIdentity, i));
```
（`Terraria/Projectile.cs:12595`，变量名已按语义重写）

注意 `IsNPCIndexImmuneToProjectileType`（`Terraria/Projectile.cs:606`）返回的是 `perIDStaticNPCImmunity[...] <= Main.GameUpdateCount`，即「解禁时刻已过 → 可以命中」。字段名带 `Immune` 但语义是「当前允许」，别被名字骗到。

紧接着 `Terraria/Projectile.cs:12596-12598` 还有「玩家本体近战冷却」闸门：`usesOwnerMeleeHitCD` 为真时要求 `Main.player[owner].CanHitNPCWithMeleeHit(i)`（即 `meleeNPCHitCooldown[i] <= 0`，`Terraria/Player.cs:44579-44582`）。这是**最容易被忽略的第四种命中免疫**：它属于玩家而不是弹幕。

`Damage_PVE_Inner`（`Terraria/Projectile.cs:12615`）的判定顺序值得背下来：

1. `Terraria/Projectile.cs:12622-12626`：阵营判定 —— 友好方是 `!targetNPC.friendly`，外加几个硬编码例外；再叠加 `CanNPCBeHitByPlayerOrPlayerProjectile`（`Terraria/Player.cs:20671`，小动物默认免疫玩家弹幕，但召唤物/哨兵弹幕能打）。
2. `Terraria/Projectile.cs:12632-12633`：`NPC.immune[owner] != 0` 直接返回 —— 通用免疫闸门。
3. `Terraria/Projectile.cs:12638-12655`：陷阱/无敌 NPC 特判（例如 `immortal && npcProj` 视为不可命中）。
4. `Terraria/Projectile.cs:12669-12675`：**核心判定** `Colliding(projRectangle, targetNPC.getRect())`。
5. `Terraria/Projectile.cs:12681-12691`：电击水母类 NPC 的反击分支（弹幕打到水母会让玩家掉血）。
6. `Terraria/Projectile.cs:12781-12789`：反弹判定，`targetNPC.reflectsProjectiles`（专题种子下 `ReflectStarShotsInForTheWorthy` 的 955/728 也置真）`&& CanBeReflected() && targetNPC.CanReflectProjectile(this)` → `ReflectProjectile` 后提前 return。

#### 4.2 `Projectile.Colliding`：特例优先、AABB 兜底

`Projectile.Colliding(Rectangle myRect, Rectangle targetRect)`（`Terraria/Projectile.cs:15421`）形式上是一个巨大的「可选特例优先，通用 AABB 兜底」函数：

- **通用兜底**在 `Terraria/Projectile.cs:15974-15978`：`myRect.Intersects(targetRect)`，即标准 AABB 相交。
- 兜底**之前**是一长串按 type/aiStyle 的特例：
  - `aiStyle == 15`（链枷）：把「目标点到玩家挂载点的向量」按某个系数缩放后求长度，本质是**椭圆距离判定**（`Terraria/Projectile.cs:15425-15439`）。
  - `type == 121..126 / 597`（宝石法杖光弹）：用前几帧位置 `oldPos[]` 构造多个历史矩形做**连续碰撞**，防止高速穿过（`Terraria/Projectile.cs:15445-15484`）。
  - `aiStyle == 19`（矛）：先取 `AI_019_Spears_GetExtensionHitbox` 给出的延伸框，再沿玩家中心到延伸框中心**分步采样**多个矩形（`Terraria/Projectile.cs:15898-15927`）。
  - `aiStyle == 190`（天顶剑一类）：用 `IntersectsConeSlowMoreAccurate` 做**扇形命中**（`Terraria/Projectile.cs:15932-15952`）。
  - `type == 923`：从中心沿朝向发射 510/660/800 三段、宽度递减的线段，等同于**三段锥形长条**（`Terraria/Projectile.cs:15788-15813`）。
  - 鞭子：`ProjectileID.Sets.IsAWhip[type]` 分支用 `FillWhipControlPoints` 生成控制点，两套（正常帧与 `frameOffset = -1`）控制点两两 `Rectangle.Union` 后与目标相交（`Terraria/Projectile.cs:15805-15821`）。
  - 长枪/长矛类：`Collision.CheckAABBvLineCollision`，即**线段与 AABB 的精确求交**（如 `Terraria/Projectile.cs:15994-15999`、`Terraria/Projectile.cs:16018-16023`）。

`AI_019_Spears_GetExtensionHitbox`（`Terraria/Projectile.cs:46983`）据此说明：动画进度用 `Utils.Remap(itemAnimation, itemAnimationMax, itemAnimationMax/3, 0, 1)` 求得，延伸起点 10 像素、长度按武器 type 取 30/50/40 再除 `meleeSpeed`；动画进度不到 1/3 时直接返回 false（`Terraria/Projectile.cs:46986-46989`），即「矛还没伸出来时没有判定」。

**设计取舍**：默认分支完全不做「隧道效应」处理，高速弹靠 `extraUpdates` 多子步 + `oldPos[]` 历史矩形补救 —— 这也解释了为什么鞭子和矛必须各自写一套特例。

### 5. 伤害计算链

#### 5.1 近战挥砍（玩家本体，不经过弹幕）

`Player.ItemCheck_MeleeHitNPCs` 的循环（`Terraria/Player.cs:44589-44600`）有三个与门：`NPC.immune[whoAmI] == 0`、`CanHitNPCWithMeleeHit(i)`、`attackCD <= 0`。通过后进入 `ProcessHitAgainstNPC`，伤害来源依次为：

- `Terraria/Player.cs:44648-44652`：暴击 `Main.rand.Next(1, 101) <= GetWeaponCrit(sItem)`。
- `Terraria/Player.cs:44654-44657`：怪物旗帜加成（`GetBannerBuffEffect` 的 `DamageDealt` 按当前难度采样）。
- `Terraria/Player.cs:44660-44663`：破防增益 `parryDamageBuff` 使伤害 ×5 并清掉。
- `Terraria/Player.cs:44694`：`Main.DamageVar(damage, luck)` 做 **±15% 随机浮动**；幸运为正时再抽一次取大值，为负时再抽一次取小值（`Terraria/Main.cs:67068-67096`）。
- `Terraria/Player.cs:44761`：`nPC.checkArmorPenetration(...)` 把护甲穿透折算回伤害。
- `Terraria/Player.cs:44764`：最终 `nPC.StrikeNPC(num3, knockBack, direction, crit, fromNet: false, whoAmI)`。

即：**武器伤害 × 职业加成 × 旗帜 × 破防 × 幸运随机 在进入 `StrikeNPC` 之前就已算好**，`StrikeNPC` 只负责「防御与暴击倍数」。

#### 5.2 弹幕打怪：`NPC.StrikeNPC` 内部

`Terraria/Projectile.cs:13703` 调用 `targetNPC.StrikeNPC(dmg, knockBack, hitDir, crit, fromNet: false, ownedBySomeone ? owner : 255)`（弹幕无主时 `whoAmI` 传 255）。`StrikeNPC`（`Terraria/NPC.cs:81894`）是「发起 + 同步 + 结算」的包装：

1. `Terraria/NPC.cs:81896-81900`：`owner < 0` 时归到本机玩家。
2. `Terraria/NPC.cs:81904-81908`：`!active || life <= 0` 直接返回 0 —— 已死 NPC 不再吃伤害。
3. `Terraria/NPC.cs:81915-81941`：非 `fromNet` 时先 `NetMessage.SendData(28, ...)` 通知所有端。
4. `Terraria/NPC.cs:81944-81957`（`StrikeNPC_Inner`）：

```csharp
int num = (int)Math.Max(1.0, Main.CalculateDamageNPCsTake(Damage, defense) * (crit ? 2 : 1));
if (RedHatSkeletronAdjustmentsEnabled()) num = Math.Max(1, (int)(num * 0.7f));
if (takenDamageMultiplier > 1f) num = (int)(num * takenDamageMultiplier);
num = Math.Max(1, num);
```
（`Terraria/NPC.cs:81944-81957`，变量名已按语义重写）

结算顺序 = **防御减伤 → 暴击 ×2 →（专题种子）×0.7 → 承伤倍率 → 保底 1**。

5. `Terraria/NPC.cs:81962-81992`：飘字（区分友方/敌对、本机/他人）、`justHit`、城镇 NPC 受击逃跑与 AI 复位。
6. `Terraria/NPC.cs:82074-82092`：扣血。`realLife >= 0`（有主从血条的怪，如毁灭者）时扣主实体并同步，否则扣自己；`immortal` 为真时整段跳过。
7. `Terraria/NPC.cs:82093-82131`：击退衰减 —— `knockBack * knockBackResist`（`onFire2` 再 ×1.1），超过 8 / 10 / 12 / 14 的每一档再乘 0.9 / 0.8 / 0.7 / 0.6，然后 `> 16` 硬截断为 16；最后暴击时再 ×1.4（在截断之后，所以暴击击退可以超过 16）。

**防御公式**（`Main.CalculateDamageNPCsTake`，`Terraria/Main.cs:67097`）：`max(1, Damage - Defense * 0.5)`。专家/大师难度**不改变打怪公式**，只改变打玩家公式。

#### 5.3 怪物弹幕打玩家：`Damage_EVP` 与无敌通道

`Damage_EVP`（`Terraria/Projectile.cs:14847`）先选择**无敌帧通道**：默认 `ImmunityCooldownID.General`，而 452/454/455/462/871-874/919-924 等归到 `ImmunityCooldownID.BossNoCheese`（`Terraria/Projectile.cs:14853-14870`）。通道的意义是：BossNoCheese 伤害不会触发普通无敌帧，可以连续出伤。PVP 则走 `Damage_PVP`（`Terraria/Projectile.cs:14638`），其进入条件包含 `Main.player[Main.myPlayer].hostile`（`Terraria/Projectile.cs:14640`）与双方 `player.immune` 检查（`Terraria/Projectile.cs:14651`），最终调用 `player.Hurt(..., pvp: true, ...)`（`Terraria/Projectile.cs:14742`）。

### 6. 玩家受伤：`Player.Hurt` 的完整链条

`Player.Hurt`（`Terraria/Player.cs:38477`）的顺序如下，每一步都影响「最终掉多少血」：

1. `Terraria/Player.cs:38479-38486`：微光形态 / 创造模式免伤 → 返回 0。
2. `Terraria/Player.cs:38488-38493`：**无敌帧检查**。首选通道看 `immune`，其它通道看 `hurtCooldowns[通道]`；`flag2` 表示「远程/他人的伤害表现」，它会让本地判定不受无敌帧限制。
3. `Terraria/Player.cs:38494-38516`：闪避饰品（神圣护符/黑带 1/10、克脑 1/6、忍者/暗影闪避），任意成功即返回 0 —— **闪避在减伤之前，不耗血、不进入后续流程**。
4. `Terraria/Player.cs:38527`：`num2 = Main.CalculateDamagePlayersTake(Damage, statDefense)`。
5. `Terraria/Player.cs:38528-38531`：`if (Crit) num *= 2;`。注意这里翻倍的是 `num`，而 `num2` 已经用未翻倍的 `num` 算完，之后 `num2` 也没有再乘 2 —— **这段逻辑的最终效果较反直觉，本任务未做运行验证，以实际游戏行为为准**。
6. `Terraria/Player.cs:38585`：`endurance` 减伤（`(1 - endurance) * num2`）。
7. `Terraria/Player.cs:38586-38599`：日耀护盾（`ConsumeSolarFlare`）再减 20%，并生成爆炸弹幕 608。
8. `Terraria/Player.cs:38603-38621`：甲虫防御（`beetleDefense && beetleOrbs > 0`）每颗甲虫 15% 减伤并消耗一颗。
9. `Terraria/Player.cs:38621-38651`：圣骑士盾牌分流 —— `defendedByPaladin` 且通道允许时，把伤害的 25% 交给最近的队友（`ImmunityCooldownID.PaladinsShield` 通道），自己只承受 75%。
10. `Terraria/Player.cs:38659-38664`：联网时发送玩家受伤包（`NetMessage.SendPlayerHurt`）。
11. `Terraria/Player.cs:38661-38664`：`Math.Max(1, num2)` 保底，随后 `Terraria/Player.cs:38667` 扣 `statLife`。
12. `Terraria/Player.cs:38669`：**无敌帧长度** `num10 = pvp ? 8 : (num2 != 1 ? (longInvince ? 80 : 40) : (longInvince ? 40 : 20))`。含义：PVP 8 帧；非 PVP 正常伤害 40 帧（`longInvince` 时 80）；若被压到保底 1 点则时长减半（20 / 40）。
13. `Terraria/Player.cs:38670-38678`：General 通道写 `immune` / `immuneTime`（38670-38674），其它通道写 `hurtCooldowns[通道]`（38675-38678）。

**防御公式**（`Main.CalculateDamagePlayersTake`，`Terraria/Main.cs:67117`）：普通 `Damage - Defense * 0.5`；**专家** `Damage - Defense * 0.75`；**大师** `Damage - Defense`（`Terraria/Main.cs:67123-67132`）。这就是大师难度防御更值钱的原因。

### 7. 穿透、追踪、召唤物

#### 7.1 穿透

命中后的收尾在 `Terraria/Projectile.cs:14137-14212`：

- `Terraria/Projectile.cs:14032-14038`：`usesIDStaticNPCImmunity` 分支 —— 写 `perIDStaticNPCImmunity[immunityIdentity, victimIndex] = GameUpdateCount + idStaticNPCHitCooldown`，并把 `NPC.immune[owner]` 清 0（不靠通用免疫拦截）。
- `Terraria/Projectile.cs:14178-14180`：`usesLocalNPCImmunity` 分支 —— 写 `immuneArray[victimIndex] = localNPCHitCooldown`。
- `Terraria/Projectile.cs:14181-14184`：**默认分支** —— `targetNPC.immune[owner] = 10`。不配任何免疫表时，同一弹幕每 10 帧才能再打同一目标一次。
- `Terraria/Projectile.cs:14190-14205`：`penetrate--`；减到 0 时若 `stopsDealingDamageAfterPenetrateHits` 则 `penetrate = -1; damage = 0`，否则只结束本轮遍历，由 `Update` 里的 `penetrate == 0 → Kill()` 收尾（`Terraria/Projectile.cs:17313`）。
- 特例：`type == 866`（`Terraria/Projectile.cs:14142-14171`）在穿透耗尽后**自动寻找下一个视线内目标**并改速度，是「弹跳/回旋类」的典型写法。

**核心洞察**：所谓「穿透」不是对同一目标连续判定，而是「每个子步遍历所有 NPC，各自过独立闸门」。决定多段命中频率的是 **`extraUpdates` × 免疫表参数**。

#### 7.2 追踪

`AI_009_MagicMissiles`（`Terraria/Projectile.cs:43955`）是最典型的「先跟随鼠标、松手后自动锁敌」：

- `Terraria/Projectile.cs:43981-43995`：按住时 `ai[0]` 存目标点 X、`ai[1]` 存目标点 Y + 逐层偏移，**每帧**从 `Main.MouseWorld` 刷新。
- `Terraria/Projectile.cs:44012-44039`：松手后先把 `ai[0] = -1`、`ai[1] = -1`，再调用 `FindTargetWithLineOfSight()`（`Terraria/Projectile.cs:44017`，用默认 `maxRange = 800f`）把目标 NPC 索引写进 `ai[1]`；找不到则沿原方向匀速飞行。紧随其后的 `Terraria/Projectile.cs:44032-44039` 是补锁分支：只要 `ai[1] == -1` 就再试一次索敌。
- `Terraria/Projectile.cs:44048-44060`：锁定后按距离算插值系数 `t`（`Utils.GetLerpValue` 组合），距离越近转向越柔和。
- `Terraria/Projectile.cs:44083-44093`：`velocity = Vector2.Lerp(velocity, 目标速度, t)`（目标速度 = 指向目标的单位向量 × 飞行速度上限），速度低于 4 时额外偏转加速，速度出现 NaN 则 `Kill()`。

**追踪的通用基础设施**是 `FindTargetWithLineOfSight(maxRange, ignoreTargets)`（`Terraria/Projectile.cs:46415`）：

- `Terraria/Projectile.cs:46430`：`nPC.CanBeChasedBy(targeter)` 过滤。
- `Terraria/Projectile.cs:46431-46434`：**已命中过的目标不再选**（`localNPCImmunity[i] != 0`），防止追踪弹绕回去打同一只。
- `Terraria/Projectile.cs:46438`：`Collision.CanHit(...)` 做视线检测，无遮挡才算候选，并按距离取最近。

召唤物另有「**预判拦截**」：`AI_066_TryInterceptingTarget`（`Terraria/Projectile.cs:43111`）调用 `Utils.GetChaseResults`，在约 35 帧的拦截窗口内解「以固定速度追上运动目标」的追逐解，把解出的速度写进 `velocity`，超出窗口则保持原速。这比纯 `Lerp` 追踪更适合打高速移动目标。

#### 7.3 召唤物

召唤物有两条与「伤害数值」无关但决定生死的机制：

1. **槽位（slots）而非单纯数量**：`Terraria/Projectile.cs:16815-16848`。`minion` 在最后一个子步重算占用；若 `slotsMinions + minionSlots > maxMinions` 且属于本机玩家 → `Kill()`。也就是**超出上限时是召唤物自杀**，而不是拒绝生成。`maxMinions` 在 `Terraria/Player.cs:1243`，`slotsMinions` 在 `Terraria/Player.cs:1247`。
2. **伤害随主人实时重算**：`Terraria/Projectile.cs:16810-16813`，`damage = originalDamage * player.minionDamage`（每个子步刷新），所以召唤增伤饰品对已存在的召唤物立即生效；`originalDamage` 是生成时写入的基准伤害。
3. **出界即归位**：`Terraria/Projectile.cs:16790-16804`，`minion` 一旦出界或坐标 NaN，若主人存活则 `Center = player.Center` 并结束本帧 `Update()`；主人不 active / 已死时改为 `active = false`。

哨兵（`sentry`）与召唤物共用同一条 `damage` 重算逻辑，但不消耗召唤槽位。

### 8. 弹幕生成：`Projectile.NewProjectile` 的固定流水线

`Terraria/Projectile.cs:10864-11104`：

1. `Terraria/Projectile.cs:10866-10872`：Owner 默认 255，并断言「只能在所有者客户端 / 单人生成」。
2. `Terraria/Projectile.cs:10876`：`NewProjectileSetup()` 从 1000 个槽位找空位；没空位时 `FindOldestProjectile()`（`Terraria/Projectile.cs:10810`，挑非 netImportant 且 timeLeft 最小者）顶掉 —— 这就是「弹幕池满时新弹幕挤掉旧弹幕」。
3. `Terraria/Projectile.cs:10876-10878`：`SetDefaults(Type)` → `Terraria/Projectile.cs:699`，重置全部状态，包括 `localNPCHitCooldown = -2`、`idStaticNPCHitCooldown = -1`、`usesLocalNPCImmunity = false`、`usesIDStaticNPCImmunity = false`（`Terraria/Projectile.cs:714-721`）。

## 设计要点与取舍

1. **伤害在投递前算好，结算只查防御**。武器倍率、药水、旗帜、幸运、随机浮动都在 `ProcessHitAgainstNPC` / `Damage_PVE_Inner` 的前半段完成；`StrikeNPC` 是唯一的「防御 + 暴击 + 承伤倍率」收口，让近战、弹幕、PVP 复用同一张表。
2. **四类命中免疫并行且互不等价**：`NPC.immune[玩家]`（通用，默认 10 帧）、`Projectile.localNPCImmunity[]`（每实例一份）、`perIDStaticNPCImmunity[类型, NPC]`（同类型共享）、`Player.meleeNPCHitCooldown[]`（玩家本体近战）。调试「打了不掉血」时四条都要查。
3. **命中判定：特例优先、AABB 兜底**。鞭、矛、扇形剑气、长枪都自己写几何，通用分支只保证基本正确；因此只改形状不改 `Colliding`，就会出现视觉与判定错位。
4. **`penetrate` 复用为死亡哨兵**：`-1` 表示已失效，`0` 表示穿透耗尽、本帧结束即死。`penetrate == 0` 与 `== -1` 语义完全不同，是阅代码最容易踩的坑。
5. **无敌帧是按通道的稀疏资源**。`hurtCooldowns[]` 让「Boss 弹幕不吃普通无敌」变成纯数据配置（`ImmunityCooldownID.BossNoCheese`），而不需要给 Boss 单写代码。
6. **数值在客户端算**。这是反作弊/服务端模组需要额外处理的原因：客户端是「官方真相」的来源，服务端主要转发 `SendData(28)` 与 `SendPlayerHurt`。
7. **召唤物用「逐帧重算伤害 + 槽位自杀」**。代价是每帧读 `Main.player[owner]`，换来饰品切换无需重建召唤物。
