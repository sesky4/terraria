# 渲染管线

> 适用版本：Terraria v1.4.5.8 反编译源码；路径相对 `decompiled/Terraria/`。

## 一句话结论

Terraria 的渲染是"**按层串行的多趟重绘**"：`Main.DoDraw`（`Terraria/Main.cs:62625`）用几十个独立的 `SpriteBatch`/`TileBatch` 区段，按固定优先级（星河→远景背景→背景水→墙与黑边→非实心瓦片→瀑布→实心瓦片→NPC→玩家→弹幕→物品/雨/血/尘→水→电线→叠加层与 UI）逐段提交；瓦片走自研的 `TileBatch`，用"图层栈 + 纹理"排序合批；角色走"层函数收集 `DrawData` → 统一提交给 `SpriteDrawBuffer`"；粒子走对象池加两个全局 `ParticleRenderer`；瀑布是"每 30 帧扫描视野附近液体边缘，再用瓦片贴图逐格叠出来的伪流体"。地形/水/背景可缓存进 RenderTarget，仅在相机移出缓存范围时整块重画（仅限非逐帧光照模式）。

## 执行流程

### 步骤 1：一帧的入口 `Main.DoDraw`

`Main.DoDraw`（`Terraria/Main.cs:62625`）先决定直画屏幕还是画到离屏目标：`Lighting.UpdateEveryFrame` 为真则 `drawToScreen = true`，否则 `false`（`Terraria/Main.cs:62669-62676`），并按需 `ReleaseTargets/InitTargets`（`Terraria/Main.cs:62677-62684`）。这一位同时决定采样器：`Main.DefaultSamplerState` 在非直画时返回 `PointClamp`、直画时 `LinearClamp`（`Terraria/Main.cs:2870-2879`）。

非直画时先调 `RenderToTargets()`（调用点 `Terraria/Main.cs:62770`，函数在 `Terraria/Main.cs:58147`）：按 `renderCount` 轮流刷新三档，第一档 `waterTarget`（`Terraria/Main.cs:58153-58156`），第二档 `backWaterTarget` + `backgroundTargetSwap`，后者 `UpdateContent(RenderBackground)` 后置 `backgroundTargetSwapPending = true`，把结果挂起待换（`Terraria/Main.cs:58157-58162`），第三档 `wallTarget/tileTarget/tile2Target`（`Terraria/Main.cs:58163-58168`）。之后对每个目标做离屏检查：`tileTarget/tile2Target/backWaterTarget/wallTarget/waterTarget` 一离屏就重画；背景目标则只看 `backgroundTarget.IsPartiallyOffscreen`，命中时先 `ApplyPendingBackgroundTargetSwap()` 交换纹理，若交换后仍离屏才重画（`Terraria/Main.cs:58169-58196`）。背景双缓冲（`backgroundTargetSwapPending`）避免同一帧读写同一张纹理。

### 步骤 2：背景三段与场景入口

实体段从 `Terraria/Main.cs:63107` 左右开始（版本号渐变叠色之后）：

1. 直画时 `DrawWaters(isBackground: true)`，否则贴 `backWaterTarget.Texture`（`Terraria/Main.cs:63109-63115`）。
2. 直画时 `DrawBackground()`，否则贴 `backgroundTarget` 并按 `caveParallax` 做水平视差偏移（`Terraria/Main.cs:63124-63133`）。
3. `ScreenDarkness.DrawBack`（`Terraria/Main.cs:63137`）之后 `PlayerInput.SetZoom_World()`，再 `DoDraw_WallsTilesNPCs()`（`Terraria/Main.cs:63144`）。

更早的星空/日月/远景（`DrawStarsInBackground`@`Terraria/Main.cs:63959`、`DrawSunAndMoon`@`Terraria/Main.cs:63776`、`DrawBG`@`Terraria/Main.cs:64911`）在 `Terraria/Main.cs:63004` 起的区段里完成；主菜单走 `PreDrawMenu`（`Terraria/Main.cs:53077`）后直接 `return`（`Terraria/Main.cs:63036-63043`），不进游戏场景。

### 步骤 3：墙、黑边、两层瓦片与瀑布 —— `DoDraw_WallsTilesNPCs`

`Terraria/Main.cs:64197` 是场景绘制主干，顺序即深度：

1. `CacheNPCDraws / CacheProjDraws` 收集本帧 NPC/弹幕条目，先画 `DrawCacheNPCsMoonMoon`（月亮领主等"压在最底下"的 NPC）。
2. `DoDraw_WallsAndBlacks`（`Terraria/Main.cs:64368`）：直画时先 `DrawBlack()`（`Terraria/Main.cs:58828`）再 `DrawWalls()`（`Terraria/Main.cs:58920`），非直画只贴 `wallTarget`。黑边在墙之前，是为了让"未光照区"垫在墙体下面。
3. `DrawWoF`、背景血 `DrawBackGore`、月亮领主死亡特效、`DrawCacheNPCsBehindNonSolidTiles`。
4. `DoDraw_Tiles_NonSolid`（`Terraria/Main.cs:64290`）：画非实心层瓦片（平台、藤蔓、草、树）或贴 `tile2Target`；之后 `DrawTileEntities(solidLayer: false)`，末尾再 `spriteBatch.Begin`（`Terraria/Main.cs:64313`）恢复批次。
5. `DoDraw_Waterfalls`（`Terraria/Main.cs:64242`）：单独 `tileBatch.Begin(Rasterizer, Transform)` → `waterfallManager.Draw()` → `tileBatch.End()`。瀑布夹在非实心瓦片与实心瓦片之间。
6. `spriteBatch.End()`（`Terraria/Main.cs:64219`）——上面的代码没有对应 Begin，实际沿用上游批次，读反编译代码时按"成对"补齐即可。
7. `DoDraw_DrawNPCsBehindTiles` → `DoDraw_Tiles_Solid`（`Terraria/Main.cs:64254`）→ `DrawPlayers_BehindNPCs` → `DoDraw_DrawNPCsOverTiles`。
   - `detectCreature`（猎手感知）为真时，`DoDraw_DrawNPCsBehindTiles` 被挪到**实心瓦片之后**（`Terraria/Main.cs:64222-64231`），用以实现"隔墙看见怪物"。
   - `DoDraw_Tiles_Solid` 贴完瓦片或 `tileTarget` 后，再画 `hitReplace/hitTile` 的裂纹动画（`Terraria/Main.cs:64276-64284`）。
8. 最后重新 `spriteBatch.Begin(Deferred, AlphaBlend, DefaultSamplerState, None, Rasterizer, null, Transform)`（`Terraria/Main.cs:64242` 之后的末尾），为调用方留下打开的批次。

### 步骤 4：`Main.DrawTiles` → `TileDrawing.Draw`

`Main.DrawTiles`（`Terraria/Main.cs:22017`）只有 `TilesRenderer.Begin(...)` → `TilesRenderer.Draw(...)`（`Terraria/Main.cs:22023`）→ `finally { TilesRenderer.End(); }`。`Begin` 同时打开 `Main.tileBatch` 与 `Main.spriteBatch`（`Terraria.GameContent.Drawing/TileDrawingBase.cs:18-24`），`End` 两边都 End 并把 draw call 数记进 `TimeLogger`（`Terraria.GameContent.Drawing/TileDrawingBase.cs:26-34`）。

`TileDrawing.Draw`（`Terraria.GameContent.Drawing/TileDrawing.cs:470`）：

1. 依据 `Main.gfxQuality` 算出高低两档"光照阈值"与 `Main.martianLight` 的辉光色（`Terraria.GameContent.Drawing/TileDrawing.cs:484-502`）；构造 `DrawBlackHelper`，主片预置图层 `Layer_Tiles`（`Terraria.GameContent.Drawing/TileDrawing.cs:502`）。
2. `GetScreenDrawArea`（`Terraria.GameContent.Drawing/TileDrawing.cs:6661`）按 `Main.Camera.ScaledPosition/Size` 加 `Main.offScreenRange` 求包围盒，Y 多 5 行、X 多 1~2 列，并夹到世界边界内。
3. 双层循环遍历格子（`Terraria.GameContent.Drawing/TileDrawing.cs:510-512`）。`+4/+2` 是为了让高物件（树、门）能伸进视野边缘。
4. 层过滤：`IsTileDrawLayerSolid(tile.type) != solidLayer` 直接跳过（`Terraria.GameContent.Drawing/TileDrawing.cs:521`）。`IsTileDrawLayerSolid`（`Terraria.GameContent.Drawing/TileDrawing.cs:4509`）优先取 `TileID.Sets.DrawTileInSolidLayer`，否则回退 `Main.tileSolid`——这是"画在哪一层"的唯一权威。
5. 实心层先画"瓦片后液体"：`SetLayer(Layer_LiquidBehindTiles, 0)` + `DrawTile_LiquidBehindTile`（`Terraria.GameContent.Drawing/TileDrawing.cs:527-528`、`Terraria.GameContent.Drawing/TileDrawing.cs:3856`）；随后 `SetLayer(Layer_Tiles, 0)` 作为本格主片默认层（`Terraria.GameContent.Drawing/TileDrawing.cs:531`）。
6. 特殊物件只登记不绘制：大量 `switch (type)` 分支把树/藤/多格草/特殊方块写入 `_specialPositions[TileCounterType.xxx]` 并 `continue`（`Terraria.GameContent.Drawing/TileDrawing.cs:540-730`）。例如瓦片 34 只在 `frameX % 54 == 0 && frameY % 54 == 0` 时登记一次（`Terraria.GameContent.Drawing/TileDrawing.cs:552-558`）；`CrawlToTopOfVineAndAddSpecialPoint`（`Terraria.GameContent.Drawing/TileDrawing.cs:733`）从当前格向上爬到可附着点后登记根节点，避免同一根藤重复绘制。
7. 其余格子走 `DrawSingleTile`。
8. 收尾：`drawBlackHelper.EndStrip()` 批量刷出黑块（`Terraria.GameContent.Drawing/TileDrawing.cs:733`）→ `RestartLayeredBatch()` 立即提交瓦片批（`Terraria.GameContent.Drawing/TileDrawing.cs:734`）→ 实心层再 `DrawTileCracks`（`Terraria/Main.cs:62451`）并 `RestartSpriteBatch`（`Terraria.GameContent.Drawing/TileDrawing.cs:737-739`）→ `DrawSpecialTilesLegacy` → 放置预览 `TileObject.DrawPreview`（`Terraria.GameContent.Drawing/TileDrawing.cs:740-750`）。

### 步骤 5：单瓦片 `DrawSingleTile` 与图层选择

`Terraria.GameContent.Drawing/TileDrawing.cs:872` 起：

1. `GetTileDrawData` 计算几何、帧偏移、发光层，填进 `TileDrawInfo`。
2. 选层（`Terraria.GameContent.Drawing/TileDrawing.cs:886-896`）：`tileTop < 0` → `Layer_OverTiles`；`tileTop + tileHeight <= 16` → `Layer_Tiles`；否则 `Layer_BehindTiles`。即"向下凸出超过一格"的物件必须压在下方瓦片之上。
3. 危险感知/寻宝/生物群系透视：直接抬高 `tileLight` 的 RGB 下限并按概率撒尘（`Terraria.GameContent.Drawing/TileDrawing.cs:900-980`），属于"染色式高亮"，不改贴图。
4. `DrawTiles_EmitParticles`（`Terraria.GameContent.Drawing/TileDrawing.cs:6803`）仅在 `!Lighting.UpdateEveryFrame` 或以 `FastRandom(TileFrameSeed)` 哈希抽样命中时执行（`Terraria.GameContent.Drawing/TileDrawing.cs:984`）。
5. `flag` 决定"这格是否真的产生 sprite"：有 glow/flame、任一光照通道 ≥1、背景墙 318 或 `fullbrightWall` 任一成立即为真；`!IsVisible` 时强制为假（`Terraria.GameContent.Drawing/TileDrawing.cs:987-996`）。`flag` 为假时先 `CacheSpecialDraws_Part1(..., skipDraw: !flag)` 仍登记特殊物件（`Terraria.GameContent.Drawing/TileDrawing.cs:1001`），再在 `!flag && flag2 && TileDrawingBase.DrawOwnBlacks` 时调 `drawBlackHelper.DrawBlack`（`Terraria.GameContent.Drawing/TileDrawing.cs:997-1000`）——**被完全照黑的瓦片不产生 sprite，只在允许自绘黑块时留一块黑**（`!IsVisible` 连黑块都不画）。
6. 斜坡/半砖：邻接半砖时额外画 8 像素高的补片，补片只用普通 `tileBatch.Draw` 追加、不调 `SetLayer`，沿用当前图层（通常是主片的 `Layer_Tiles`），不做 stack 细分（`Terraria.GameContent.Drawing/TileDrawing.cs:1606-1648`）；斜坡叠加才切换到 `SetLayer(Layer_BehindTiles, 0)`（`Terraria.GameContent.Drawing/TileDrawing.cs:1546`，stack 为 0）。`SetLayer(..., 1)` 出现在 1383、1402、1416，那里铺的是斜坡/平台填充，与半砖补片无关。`TileID.Sets.HasSlopeFrames` 的瓦片走整帧分支（`Terraria.GameContent.Drawing/TileDrawing.cs:1566`）。

### 步骤 6：瓦片之外的装饰 —— `PostDrawTiles`

`Terraria.GameContent.Drawing/TileDrawing.cs:419`：`PostDrawTiles(false)` 自己 `Begin(Deferred, AlphaBlend, DefaultSamplerState, None, Main.Rasterizer, null, Main.Transform)`，依次 `DrawMultiTileVines → DrawMultiTileGrass → DrawVoidLenses → DrawTeleportationPylons → DrawMasterTrophies → DrawGrass → DrawAnyDirectionalGrass → DrawTrees → DrawVines → DrawReverseVines`（`Terraria.GameContent.Drawing/TileDrawing.cs:427-436`），`End` 后交给 `_natureRenderer.DrawAfterAllObjects(beginner)`（`Terraria.GameContent.Drawing/TileDrawing.cs:438`）。`PostDrawTiles(true)` 只画衣帽架与展示人偶（`Terraria.GameContent.Drawing/TileDrawing.cs:441-447`）。

这些函数都只是遍历步骤 4 登记的点：`DrawVines` 用索引 4（`TileCounterType.Vine`）逐根 `DrawVineStrip`（`Terraria.GameContent.Drawing/TileDrawing.cs:9058-9071`），`DrawGrass` 用索引 1（`Terraria.GameContent.Drawing/TileDrawing.cs:8488-8492`）。索引与枚举 `TileCounterType`（`Terraria.GameContent.Drawing/TileDrawing.cs:21-35`）一一对应。

风由 `TileDrawing.Update`（`Terraria.GameContent.Drawing/TileDrawing.cs:371`）驱动：把 `|Main.WindForVisuals|` 映射到 0.08~1.2 再归一化，按不同基频推进 `_treeWindCounter / _grassWindCounter / _sunflowerWindCounter / _vineWindCounter` 四个相位，步长随风力线性增大。`DrawTrees` 里另有 `0.08f` 与 `0.06f` 两档摆幅（`Terraria.GameContent.Drawing/TileDrawing.cs:8198-8199`）。`NextNatureRenderer` 先把每个 `DrawNature` 调用压进 `_entries`（`NextNatureRenderer.cs:23-33`），最后在 `DrawAfterAllObjects`（`NextNatureRenderer.cs:71`）里统一按日出/日落时段加逆光染色后批量提交。

### 步骤 7：玩家 —— 分层收集再统一提交

`Main.DrawPlayers_BehindNPCs`（`Terraria/Main.cs:22491`）与 `DrawPlayers_AfterProjectiles`（`Terraria/Main.cs:22499`）分别处理 `_playersThatDrawBehindNPCs` / `_playersThatDrawAfterProjectiles` 两个集合，药水回程的残影先由 `PotionOfReturnRenderer` 画（`Terraria/Main.cs:22494`、`Terraria/Main.cs:22502`），再交给 `PlayerRenderer.DrawPlayers`（`Terraria/Main.cs:22503`）。玩家因此可以被"钉"在两个深度上，NPC 绘制两次以包夹。

`LegacyPlayerRenderer.DrawPlayer`（`LegacyPlayerRenderer.cs:132`）是完整流水线：

1. `_drawData/_dust/_gore.Clear()` 后 `BoringSetup`（`PlayerDrawSet.cs:266`）填上下文，解析手持弹幕 `SelectedDrawnProjectile`。
2. `DrawPlayer_UseNormalLayers`（`LegacyPlayerRenderer.cs:163`）按硬编码顺序调用约 40 个层函数，顺序即深度：卷风衣 → 坐骑后 → 飞毯 → 坐垫 → 电击/禁忌法阵/蛛网/洗发水 → 背包 → 尾巴 → 翅膀 → 后发 → 背饰 → 后脑 → 气球 → 手持（`BehindBackArm`）→ 外套 → 皮肤 → 鞋/绑腿 → 长袍 → 躯干 → 腰/颈 → 头部 → 面部 → 坐骑前 → 吊索 → 盾 → 日耀盾 → 手持 → 手臂 → 手套 → 前景配件 → 冰冻/电击前景 → `36/37/38` 各种前景特效。`drawInfo.weaponDrawOrder`（`WeaponDrawOrder.BehindBackArm/BehindFrontArm/OverFrontArm`）决定手持物品插在何处（`LegacyPlayerRenderer.cs:182-183`、`:216-218`、`:225-227`）。
3. `DrawPlayer_TransformDrawData`（`PlayerDrawLayers.cs:4218`）给所有 `DrawData` 施加 `fullRotation` 绕 `rotationOrigin` 的旋转（`ignorePlayerRotation` 的除外），并同步旋转 `DustCache/GoreCache` 实体的世界坐标。
4. 可选 `DrawPlayer_ScaleDrawData`（`PlayerDrawLayers.cs:4251`）以脚底中心为锚整体缩放（残影用）。
5. `DrawPlayer_RenderAllLayers`（`PlayerDrawLayers.cs:4303`）：先把整份缓存 `item.Draw(spriteBuffer)` 灌进缓冲（`PlayerDrawLayers.cs:4307-4313`），再顺序 `spriteBuffer.DrawSingle(i)`（`PlayerDrawLayers.cs:4337`）；当 `i == drawinfo.projectileDrawPosition` 时先 `Unbind` 再 `DrawHeldProj`（`PlayerDrawLayers.cs:4318-4326`）——手持剑气/箭矢是"嵌"在玩家精灵序列中间画的，插入点由 `DrawPlayer_27_HeldItem` 记录（`PlayerDrawLayers.cs:3156`）。着色器切换在 `PlayerDrawLayers.cs:4320-4323`。

每个层函数只做"往 `DrawDataCache` 里塞 `DrawData`"。例如 `DrawPlayer_01_BackHair` 依据 `hideHair/fullHair/hatHair` 三选一，贴 `PlayerHair` 或 `PlayerHairAlt`，并写入染料索引 `hairDyePacked`（`PlayerDrawLayers.cs:199-217`）。

`SpriteDrawBuffer` 本质是"自管顶点缓冲的 SpriteBatch"：预填充索引（`SpriteDrawBuffer.cs:76-96`），`DrawRange` 里临时 `Bind()` 抢占顶点/索引缓冲（`SpriteDrawBuffer.cs:99-108`），画完 `Unbind()` 还原（`SpriteDrawBuffer.cs:110-119`）。这样即使外层是 `SpriteSortMode.Immediate`，也能跳过 SpriteBatch 自身排序，以精确顺序绘制各层。

采样器：普通玩家用 `camera.Sampler`；骑乘且 `fullRotation != 0` 时换 `MountedSamplerState`（非直画 `AnisotropicClamp`、直画 `LinearClamp`，`LegacyPlayerRenderer.cs:22-30`、`LegacyPlayerRenderer.cs:265-270`），减少旋转坐骑的锯齿。

### 步骤 8：粒子

`ParticleOrchestrator.RequestParticleSpawn`（`ParticleOrchestrator.cs:52`）是统一入口：填 `IndexOfPlayerWhoInvokedThis` → 本地 `SpawnParticlesDirect` → 若 `!clientOnly && Main.netMode == 1` 再发包给服务器。另有 `BroadcastParticleSpawn`（`ParticleOrchestrator.cs:66`）与 `BroadcastOrRequestParticleSpawn`（`ParticleOrchestrator.cs:79`）处理服务器侧的转发。

`SpawnParticlesDirect`（`ParticleOrchestrator.cs:162`）是一个巨型 `switch (type)`，每个 `ParticleOrchestraType` 对应一个 `Spawn_Xxx` 函数（如 `Spawn_ArmletOfRuinRecharge`@`ParticleOrchestrator.cs:418`），函数体开头几乎都是 `if (Main.netMode != 2)`，专用服务器不生成。函数从静态池取粒子再 `Add` 到全局 `ParticleRenderer`。

> 这个 `switch` 有数百个分支，反编译输出极长；阅读时请脑内折叠成"类型 → 生成函数"的映射表。

全局只有两个渲染器：`Main.ParticleSystem_World_BehindPlayers` 与 `Main.ParticleSystem_World_OverPlayers`（`Terraria/Main.cs:2207-2209`），每帧更新在 `Terraria/Main.cs:4003-4004`。绘制时机：

- 弹幕画完之后、玩家之前，设 `Settings.AnchorPosition = -screenPosition` 后以 `SpriteSortMode.Immediate` 画 BehindPlayers（`Terraria/Main.cs:63171-63174`）。
- 玩家之后画 OverPlayers（`Terraria/Main.cs:63176-63180`）。

`ParticleRenderer.Draw`（`ParticleRenderer.cs:54`）顺序遍历、逐个 `IParticle.Draw`，无排序——粒子前后顺序完全由生成顺序决定。池由 `ParticlePool.RequestParticle`（`Terraria.Graphics.Renderers/ParticlePool.cs:32-51`）提供：找 `IsRestingInPool` 的空位，无空位就直接 new，**不设上限**。

### 步骤 9：瀑布

`WaterfallManager` 两段式：

1. **`FindWaterfalls`**（`WaterfallManager.cs:107`）：`findWaterfallCount` 每帧递增，未 `forced` 时**攒满 30 帧才扫描一次**（`WaterfallManager.cs:110-113`）。扫描范围是屏幕外扩 `waterfallDist = 75 * Main.gfxQuality + 25` 格（`WaterfallManager.cs:116`），Y 下沿只多 20 以便发现远处源头（`WaterfallManager.cs:126`）。判定：半砖上方液体格液面达标，且左右某邻格 `liquid > 160`（`minWet`，`WaterfallManager.cs:24`）而另一侧是空的——"水正要溢出边缘"（`WaterfallManager.cs:160-180`）；液格种类决定 type：岩浆 1、蜂蜜 14、微光 25（`WaterfallManager.cs:180-196`）。瓦片 196/460/717 下方空格则生成固定类型 11/22/26（`WaterfallManager.cs:204-256`）。结果受 `qualityMax = maxWaterfallCount * gfxQuality` 限制（`WaterfallManager.cs:117`）。
2. **`Draw`**（`WaterfallManager.cs:1165`）：先把所有条目 `stopAtStep` 重置为 `waterfallDist`、清 `Main.drewLava`，再按 `Main.liquidAlpha` 的索引 0、2~10、12、13（共 11 项，跳过 1 和 11）逐个调用 `DrawWaterfall(style, alpha)`（`WaterfallManager.cs:1173-1220`）——液体渐隐时瀑布同步淡出。
3. **`DrawWaterfall`**（`WaterfallManager.cs:325`）：从起点向下最多 `waterfallDist` 格，每格往 `TileBatch` 塞背景层 + 前景层两张 16×16 贴图；遇固体 `break`，遇已有液体则把源矩形高度裁掉 `(liquid/255*16) & 0xFE`（`WaterfallManager.cs:504-510`）；**每下降一格 X 交替 ±1**（`WaterfallManager.cs:511-521`）造成蛇形流淌感。
4. 图层：`Layer_Rain = 0`、`Layer_Waterfall = 1`（`WaterfallManager.cs:70-72`）；雨/雪/岩浆雨在 0 层（`WaterfallManager.cs:457`），普通瀑布在 1 层（`WaterfallManager.cs:734`），保证大瀑布压在细流之上。
5. 动画：`UpdateFrame`（`WaterfallManager.cs:257`）维护 `regularFrame`（每 3 帧一步）、`slowFrame`（每 7 帧一步，岩浆/蜂蜜/微光用）以及雨、岩浆雨、雪各自的前景/背景帧计数。**所有瀑布共用同一组帧号，因此全场流动是同步的。**

## 设计要点与取舍

1. **"两层瓦片"是最大简化。** 只有实心/非实心两遍（`Terraria.GameContent.Drawing/TileDrawing.cs:521`），层内靠 4 个图层 + `stack` 细分实现遮挡：真正的 z 排序不可能，但一次遍历就能凑出可合批的四边形，draw call 极少。
2. **黑块替代透明：** 完全无光的瓦片不产生 sprite，只把矩形塞给 `DrawBlackHelper`（`Terraria.GameContent.Drawing/TileDrawing.cs:997-1000`）。既省 sprite，又保证"看不见就是纯黑"而非"露出背景或无底洞"。
3. **特殊物件两遍走：** 第一遍只登记坐标与类型，第二遍在 `PostDrawTiles` 统一画。好处是藤蔓/树/草可自由跨格伸展，不必在扫描时处理邻接顺序；代价是多一次列表遍历，且每类最多 9000 个特殊点（`MAX_SPECIALS`，`Terraria.GameContent.Drawing/TileDrawing.cs:66`），极端情况下会截断。
4. **玩家"收集-变换-提交"三段式：** 40 个层函数都是纯函数 + `ref PlayerDrawSet`，可任意组合；旋转只做一次全局变换；最后用 `SpriteDrawBuffer` 抢占硬件缓冲精确绘制，绕开 SpriteBatch 排序。代价是每个玩家一次 Bind/Unbind 和较多 draw call。
5. **`SpriteSortMode.Immediate` 用于需要中途换 shader 的场合：** 粒子（`Terraria/Main.cs:63171`）与玩家（`LegacyPlayerRenderer.cs:269`）都用 Immediate，因为 Deferred 会攒到 `End()` 才画，无法在序列中间切换 `Main.pixelShader` 参数（`PlayerDrawLayers.cs:4320-4323`）。代价是几乎无法合批。
6. **瀑布"低频发现 + 高空绘制"：** 30 帧一次的扫描把边缘检测从每帧整屏液体遍历里剥出来；`waterfallDist` 随画质缩短（`WaterfallManager.cs:116`），低画质靠"少画几格"而不是"少画几帧"降负载。
7. **粒子池无上限：** `RequestParticle` 找不到空位就 new（`Terraria.Graphics.Renderers/ParticlePool.cs:47-50`），保证不因池满丢特效；代价是极端场景下渲染列表与 GC 压力上升，只能靠各特效自身的数量控制兜底。
8. **RendererTarget 缓存的代价是"整屏重画"：** 相机移动导致 `IsPartiallyOffscreen` 时，整个目标纹理要重绘一帧（`Terraria/Main.cs:58169-58196`），所以高画质（逐帧光照）干脆关掉缓存、直接画屏幕（`Terraria/Main.cs:62669-62676`）。这是 Terraria 在"瓦片几乎全静态"这一前提下的特有取舍。
