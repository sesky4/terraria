# 启动流程与主循环

> 源码基线：Terraria v1.4.5.8 反编译产物，路径均相对 `decompiled/Terraria/`。
> 本版把引擎从 XNA 迁到了 FNA（`Program.IsFna = true`，Terraria/Program.cs:23），但 `Main` 仍直接继承 `Microsoft.Xna.Framework.Game`（由 FNA 提供的兼容层），所以 "FNA Game.Update/Draw" 的语义就是 "XNA Game 的 Update/Draw 回调"。

## 一句话结论

启动是一条**单线程、分三段**的流水线：`MacLaunch.Main` → `Program.LaunchGame`（解析参数、设存档路径、挂崩溃日志）→ `Program.RunGame`（初始化语言与社交层，new Main 后 `main.Run()` 进入 FNA 帧循环）；进入帧循环后，**游戏逻辑并不由 FNA 的固定步长驱动，而是由 `Main` 自己在 `DoUpdate` 里用一个 60Hz 的时间累加器做"软固定步长"**，每凑够 1/60 秒才跑一次 `DoUpdateInWorld`，世界内的 Update 顺序被硬编码为玩家→刷怪→NPC→Gore→弹幕→物品→尘埃→文本→时间，各子系统共享同一个 `Main.rand`（按阶段"换种子"以保持随机序列稳定）。

## 执行流程

### 1. 进程入口与参数解析

1. 程序集入口是 `MacLaunch.Main`（Terraria/MacLaunch.cs:9）。它做两件事：注册 `AssemblyResolve`，从嵌入资源里就地加载缺失的 DLL；设置环境变量 `FNA_WORKAROUND_WINDOW_RESIZABLE`；最后调用 `Program.LaunchGame(args, monoArgs: true)`（Terraria/MacLaunch.cs:26）。
   - 注意：`Program` 类本身**没有 Main 方法**，真正的入口在 `MacLaunch`。这个类名是历史遗留（早期为 macOS 包一层），现在是通用入口。
2. `Program.LaunchGame`（Terraria/Program.cs:184）：
   - 命名当前线程为 "Main Thread"；`monoArgs` 为真时先把 Mono 风格的参数转成 .NET 风格（Terraria/Program.cs:188-191）。
   - `Utils.ParseArguements` 解析成 `LaunchParameters` 字典；`SavePath` 取 `-savedirectory` 或平台存储路径下的 "Terraria"（Terraria/Program.cs:193-194）。
   - `ThreadPool.SetMinThreads(8, 8)`（Terraria/Program.cs:195）—— 之后资源异步加载依赖线程池，这里预先保证有足够线程，避免加载期线程饥饿。
   - `InitializeConsoleOutput` → `SetupLogging`（可选 `-logfile`/`-minidump`/`-fulldump`，Terraria/Program.cs:156-178）→ 关闭 Windows 控制台 QuickEdit（否则鼠标选中控制台会冻结主循环）→ `RunGame()`。

### 2. RunGame：构造 Main 并进入引擎循环

`Program.RunGame`（Terraria/Program.cs:197）：

1. 设置默认语言；按平台给 `Main.OnEngineLoad` 挂回调（macOS 隐藏鼠标，Windows 注册鼠标接入通知，Terraria/Program.cs:200-218）。
2. `using Main main = new Main();`（Terraria/Program.cs:221）。构造函数（Terraria/Main.cs:6489）做的事很少：
   - `instance = this`（全局单例，后续静态代码大量使用 `instance`）；
   - 挂 `Exiting` 事件；
   - 非专用服务器时：建 `Map`（世界地图位图）、`Configuration.Load()`、创建 `GraphicsDeviceManager`、挂载 Content 目录。
   - 构造函数里**没有任何实体分配**，真正的初始化在后续 `Initialize()` 中。
3. 依次 `Lang.InitializeLegacyLocalization()`、`SocialAPI.Initialize()`、`LaunchInitializer.LoadParameters(main)`（解析 `-j`/`-join`、`-pass`、`-host` 等启动即联机的参数，Terraria.Initializers/LaunchInitializer.cs:10-45）。
4. `Main.OnEnginePreload += StartForceLoad`（Terraria/Program.cs:227）：后台线程遍历**整个程序集**的类型做 JIT 预热并强制跑静态构造（Terraria/Program.cs:52-80）。这是为了让"进游戏时的首次卡顿"提前到加载界面。
5. `Main.dedServ` 为真则走 `main.DedServ()`（Terraria/Main.cs:5319）：设置 `netMode=2`、`showSplash=false`，**手动调用 `Initialize()`**，随后进入控制台交互循环选世界；不再进入下面的图形化主循环。之后仍会调用 `main.Run()`，但专用服务器版的 `Game` 实现来自 Terraria.Server/Game.cs（独立实现，自带 `IsFixedTimeStep`/`SuppressDraw`）。
6. 客户端路径：`main.Run()` 是 FNA `Game` 的标准入口，内部依次触发 `Initialize` → `LoadContent` → 帧循环（`Update`/`Draw` → `EndDraw`）。

### 3. Initialize：构造全局状态（不含内容资源）

`Main.Initialize`（Terraria/Main.cs:6591）：

1. 断言 `npcFrameCount.Length == NPCID.Count`（数据表与枚举不同步会当场炸掉，Terraria/Main.cs:6593）；`dedServ` 时置 `netMode=2`。
2. 建全局 RNG 字典 `_rngs`（Terraria/Main.cs:6610），建 `waterfallManager / _windowMover / sittingManager / sleepingManager` 等全局管理器。
3. `ContentSamples.Initialize()`、`PlayerInput.Initialize()`（Terraria/Main.cs:6621-6622）。
4. 挂 `WorldGen.Hooks.OnWorldLoad`（Terraria/Main.cs:6624-6632）：**每次载入世界**都新建 `AmbienceServer`、`GolfState`，并清空光照。也就是说世界相关的环境音/高尔夫状态是"随世界重建"的，而非全局常驻。
5. 若是专用服务器，直接 `Initialize_AlmostEverything()` 后 return（Terraria/Main.cs:6644-6648）。
6. 客户端：`LoadContent_TryEnteringHiDef()` —— FNA 下**强制**切到 HiDef 图形配置（Terraria/Main.cs:10969-10972）；然后 `ClientInitialize()`（Terraria/Main.cs:10757：绑定消息事件、初始化 IME、`LoadSettings()`、应用分辨率、建 AchievementManager、Chroma 等）；最后 `base.Initialize()` 把控制权交回 FNA（FNA 紧接着会调 `LoadContent`）。

### 4. LoadContent + 分帧加载 + 启动画面

1. `Main.LoadContent`（Terraria/Main.cs:10907）：创建资产仓库、`SpriteBatch/TileBatch`、声音系统，加载着色器，然后 `_gameContentLoadProcess = LoadContent_Deferred()`（Terraria/Main.cs:10942）—— **这是一个 C# 迭代器（yield 状态机），不是线程**。反编译后看到的那一堆 `IEnumerator` 变量和 `MoveNext()` 调用，脑内折叠回 `IEnumerator` + `yield return null` 即可。
2. `LoadContent_Deferred`（Terraria/Main.cs:10976）：先 `QuickLoad.Load()`，然后**逐帧推进**音乐加载（`LoadMusic_InSteps`，每帧 `yield return null`，Terraria/Main.cs:10981-10996），音乐就绪后 `splashTimer.Start()`，再 `AssetInitializer.Load(asyncLoad: true)` 异步加载所有贴图，最后创建若干离屏渲染器（TownNPC 头像、Boss 头像、物品图标）。
3. 加载期间 `Main.showSplash == true`（Terraria/Main.cs:744）。此时：
   - `DoUpdate` 一开始就检测 `showSplash`（Terraria/Main.cs:17000-17008），只更新焦点/音频/全局时间段后直接 return，**完全不跑游戏逻辑**。
   - `DoDraw` 检测到 `showSplash` 只调 `DrawSplash`（Terraria/Main.cs:62638-62644）。
   - `DrawSplash` 每帧 `_gameContentLoadProcess.MoveNext()` 推进一步（Terraria/Main.cs:53302），并等到 `Assets.PendingAssets == 0` 且后台 JIT 线程 `Program.LoadedEverything` 为真时才置 `_isAsyncLoadComplete`（Terraria/Main.cs:53321）。满足后调用 `Initialize_AlmostEverything()` + `PostContentLoadInitialize()`，再 `showSplash = false`（Terraria/Main.cs:53375-53380）。
   - 结论：**"内容加载"和"游戏规则初始化"是分离的**，`Initialize_AlmostEverything`（Terraria/Main.cs:6684）在客户端是在 splash 结束时才执行（内含 TileObjectData、Recipe、商店、网络初始化器等），所以专用服务器必须手动提前调用它。
4. `DoDraw` 首次绘制主菜单时置 `IsEngineLoaded` 并触发 `Main.OnEngineLoad`（Terraria/Main.cs:49011-49016）—— 这是"窗口已可绘制"的语义，不是"加载完成"。

### 5. 帧循环骨架：Update / Draw / EndDraw

`Main.Update`（Terraria/Main.cs:16943）：

```csharp
// Terraria/Main.cs:16945-16961，节选
if (!IsEnginePreloaded) { IsEnginePreloaded = true; OnEnginePreload?.Invoke(); }
if (!_isDrawingOrUpdating) {
    _isDrawingOrUpdating = true;
    DetailedFPS.Begin(DetailedFPS.OperationCategory.Update);
    DoUpdate(ref gameTime);
    CinematicManager.Instance.Update(gameTime);
    ConsumeAllMainThreadActions();
    DetailedFPS.End();
    _isDrawingOrUpdating = false;
}
```

要点：

- `IsEnginePreloaded` 保证 `OnEnginePreload`（即后台 JIT 预热线程 `StartForceLoad`）**只触发一次**，而不是每次 Initialize。
- `_isDrawingOrUpdating` 是**重入保护**：Update 与 Draw 共享它（Draw 处 Terraria/Main.cs:62564 检查），防止在回调内部再次进入（例如录制回放、嵌套游戏循环）导致重复推进。
- `ConsumeAllMainThreadActions`（Terraria/Main.cs:16934）在**每帧 Update 末尾**清空主线程任务队列 —— 这就是 `Main.RunOnMainThread`（Terraria/Main.cs:16914）的实现机制：任意后台线程把委托入队，下一帧主线程执行完逻辑后顺序执行。
- `DetailedFPS` 把一帧切成 `Idle/Update/Draw/Present/GC/End` 若干时间片（Terraria.Testing/DetailedFPS.cs:16-27），供诊断面板使用，与逻辑无关。

`Main.Draw`（Terraria/Main.cs:62562）在重入保护下依次：`EnsureRenderTargetContent()` → `DoDraw` → `OnPostDraw` 事件 → `Assets.TransferCompletedAssets()`。后者是异步资产加载的收尾：后台加载完成的资产统一在主线程换入，避免在绘制中途替换纹理。

`Main.EndDraw`（Terraria/Main.cs:62578）是 **FNA 引擎层面的帧尾**（在 `GraphicsDevice.Present` 之前）：

- 若 `CollectGen0EveryFrame` 则非阻塞回收第 0 代；
- 若为"改进的 Subtle 帧跳"（`improvedSubtleFrameSkip`，默认值 true，见 Terraria/Main.cs:67591），进入一个**自旋等待环**：用 `Stopwatch` 测两次 Present 的间隔并累加到 `UpdateTimeAccumulator`，直到累加器 ≥ 帧时间 ×599/600 才退出（Terraria/Main.cs:62595-62611）。等待期间若有富余时间（累加器 < 0.9 帧）会做一次非阻塞 GC 第 2 代回收。
- 最后 `base.EndDraw()`（真正 Present）+ `DetailedFPS.StartNextFrame()`。

> 这段是后期版本引入的"提高 GPU 利用率"改造：用 Present 间隔反推真实帧时长，把垂直同步的空闲时间挪去做 GC，并在逻辑上"关闭"了 FNA 自己的固定步长（见下一节）。

### 6. DoUpdate：软固定步长 + 优先级分层

`DoUpdate`（Terraria/Main.cs:16997）是全文件最长的函数，按"能否跳过"分成以下几层：

**第 0 层：每帧必做（无论暂停/菜单）**

- 记录 `gameTimeCache`；`showSplash` 短路（见上）；
- `GlobalTimeWrappedHourly` 取 `TotalGameTime % 3600` 秒（Terraria/Main.cs:17005），**它来自游戏时间而非真实时钟**，`GlobalTimerPaused` 时冻结；
- `UpdateCreativeGameModeOverride`（创造模式难度滑杆覆盖）、`UpdateWorldPreparationState`（Terraria/Main.cs:4025）；
- 推进 `DelayedProcesses` 迭代器队列（Terraria/Main.cs:17022-17028）—— 同样是 `IEnumerator` 状态机，每帧 `MoveNext` 一步，完成后移出列表；
- 处理主菜单 UI 状态、`AchievementAdvisor.Update`、`PlayerInput.ResetInputsOnActiveStateChange`、`OnTickForThirdPartySoftwareOnly` 事件、待切换的 netmode、`Netplay.UpdateInMainThread()`；
- 若正在录屏（`CaptureManager.Instance.IsCapturing`）则**整帧直接 return**（Terraria/Main.cs:17057-17061）；
- 自动保存 `DoUpdate_AutoSave()`（不在生成世界时）。

**第 1 层：帧率控制与软固定步长（仅客户端）**（Terraria/Main.cs:17119-17208）

1. 设定 `base.IsFixedTimeStep` 与 `graphics.SynchronizeWithVerticalRetrace`（Terraria/Main.cs:17120-17128）：
   - `FrameSkipMode.Off` 或 `Subtle` → `IsFixedTimeStep = ThrottleWhenInactive && !IsActive`（只在窗口失焦时启用固定步长用于降频）；
   - `FrameSkipMode.On` → `IsFixedTimeStep = true`，让 FNA 自己管节奏。
   - 注意这里**只设置不读取**：FNA 的 `Game.Tick` 本身已按 `IsFixedTimeStep` 决定是否调用 Update，而本文件里把"逻辑步长"完全交给下面的累加器，这是一种"双控制"——FNA 负责窗口失焦时的粗粒度降频，`Main` 负责正常游玩时的精细节奏。
2. `updatesCountedForFPS++`，每满 1 秒统计一次 `frameRate`（Draw 次数）与 `updateRate`（Update 次数），并据此**动态调整画质 `gfxQuality`**（Terraria/Main.cs:17134-17171）：帧率高于 `30 + 30*gfxQuality` 就小幅提升，低于 `29 + 30*gfxQuality` 就一次扣 0.1。这是自适应画质，不是自适应逻辑步长。
3. 软固定步长本体（Terraria/Main.cs:17173-17199）：
   - 若 `FrameSkipMode` 为 `Off` 或"未启用改进 Subtle"的 `Subtle`：`UpdateTimeAccumulator += 本帧 ElapsedGameTime`；累加器 < 1/60 时**直接 return**（`Subtle` 或录屏时再 `SuppressDraw()`，即"不更新也不画"）；否则把 `gameTime` **改写成固定 1/60 秒**（Terraria/Main.cs:17184）—— 这就是"固定步长"的关键：下游所有代码都认为一帧就是 1/60 秒。
   - 然后 `UpdateTimeAccumulator -= 1/60`，并 clamp 到 `[0, 3/60]`（Terraria/Main.cs:17188-17189）。clamp 到 3 帧意味着：**卡顿超过 50ms 时，最多只补 3 个逻辑帧，其余时间被丢弃**（避免死亡螺旋）。
   - `num3 = 0`，条件 `++successiveSkippedDraws <= num3` 恒为假（Terraria/Main.cs:17190-17198），所以该分支**永远走 else**：不跳过绘制。也就是说本版本实际上关闭了"落后就跳一帧不画"的老式跳帧，改为"先更新、后由 EndDraw 里的自旋把时间还回去"。
   - 若 `FrameSkipMode.On`：既不进上面的累加器，也不改写 `gameTime` —— 逻辑步长等于真实帧时长（受 FNA 固定步长约束），属于"传统可变步长"。
4. 因此**同一份世界更新代码会在两种时间模型下运行**：Off/Subtle 下每次逻辑步恒为 1/60；On 下随帧率变化。而世界更新代码**根本不读取时间增量**（见下），而是"一次 Update = 一个逻辑步"，`dayRate` 才是逻辑步到游戏时间的倍率。

**第 2 层：与玩法无关的"演算用"更新（菜单里也要跑）**

`uCount++` 之后依次：`UpdateUIStates`、特效 Filters/Overlays 场景更新、`LiquidRenderer.Update`、`UpdateAudio`、通知/物品槽/合成特效、背景动画、`Animation.UpdateAll`、按 `gfxQuality` 重设 `maxDustToDraw`（Terraria/Main.cs:17235，6000 封顶、1000 保底）、`Gore.goreTime`、`Liquid.cycles/curMaxLiquid`、光照渲染阶段数、天空 `SkyManager.Update`、各种"纯视觉"的 `DoUpdate_Animate*`（光标颜色、地砖光晕、迪斯科灯、瀑布、墙）。

**第 3 层：输入**

`DoUpdate_HandleInput`（Terraria/Main.cs:17331，实现于 Terraria/Main.cs:18547）依次：`PlayerInput.UpdateInput()`、`UpdateViewZoomKeys()`、UI 导航、`oldKeyState = keyState`，再读 `Keyboard.GetState()` 到 `keyState`（失焦时不读，返回空键盘状态）。注意：**键状态在 Update 里采集一次并缓存**，`WorldUpdateStepper` 等调试逻辑读的就是这两个静态字段。

**第 4 层：各"提前返回"闸门（按顺序）**

| 位置 | 条件 | 效果 |
|---|---|---|
| Terraria/Main.cs:17295 | 窗口失焦需要暂停 | 只更新菜单（若在菜单）并置 `gamePaused`，return |
| Terraria/Main.cs:17335 | `gameMenu && netMode != 2` | 更新主菜单后 return（单人/客户端在主菜单不跑世界） |
| Terraria/Main.cs:17347 | `!CanUpdateGameplay && netMode != 2` | 由 `ToggleGameplayUpdates`（Terraria/Main.cs:3162）控制的全局玩法开关，用于世界生成/载入 UI 时冻结玩法 |
| Terraria/Main.cs:17366 | `CanPauseGame()` | 暂停态：只跑 `DoUpdate_WhilePaused` 后 return |
| Terraria/Main.cs:17447 | `ShouldUpdateEntities() && WorldUpdateStepper.ShouldUpdateWorld()` | 只有两者都为真才推进世界 |

`CanPauseGame`（Terraria/Main.cs:17467）只在 `netMode == 0`（单人）时可能为真：打开了选项窗口/控制菜单/成就界面，或 `autoPause` 下打开了背包、告示牌、任意 InGameUI —— 多人（netMode 1/2）永远不因 UI 暂停。这是"多人必须持续 tick"的直接体现。

### 7. DoUpdateInWorld：世界内部的硬编码 tick 顺序

`DoUpdateInWorld`（Terraria/Main.cs:17900）本身是一个壳：

1. `RecordReplay.RecordOrReplayInput()` 抓输入快照；
2. `using (SwapRandom("DoUpdateInWorld"))` —— 进入"世界级 RNG"域；
3. `try { DoUpdateInWorld_Inner(); } finally { 快照回滚（可为 null）; 计时记录 }`（Terraria/Main.cs:17904-17915）。快照回滚是回放系统的状态还原，正常运行时为 null。

`SwapRandom` 的机制（Terraria/Main.cs:3300）：按 key 从 `_rngs` 取一个以世界种子初始化的独立 `UnifiedRandom`，用 `RandomSwap`（Terraria/Main.cs:104）把 `Main.rand` 换成它，`Dispose` 时换回。效果是：**每个子系统有自己的随机流**，只要某子系统内部消耗的随机数个数不变，别的子系统改动不会改变它的随机结果（稳定复现/回放）。非主线程调用会抛异常（Terraria/Main.cs:3302-3305）。

`DoUpdateInWorld_Inner`（Terraria/Main.cs:17918）的顺序（每个步骤都包在 `using (SwapRandom("<名字>"))` 里）：

**为什么是这个顺序？** 直接读代码能确认的因果：
- 玩家先、NPC 后：NPC 的 AI 需要读玩家最新位置（例如追击目标）；并且 `UpdateWorld_NPCs` 开头会把所有玩家的 `nearbyActiveNPCs` 清零再用它统计（Terraria/Main.cs:18074-18077），说明它假定玩家已更新完。
- NPC 先、弹幕后：NPC 的 AI 会生成弹幕；弹幕又需要撞到已移动的敌人。
- 弹幕先、尘埃后：弹幕/物品在移动时会发射尘埃。
- 物品在弹幕之后：物品的"被弹幕击中"判定需要弹幕位置最新。
- `tileSolid[379] = false` ... 之后恢复 `true`（Terraria/Main.cs:17926 / 17973）：在整个实体更新期间把某一特定图格临时设为非实心，实体更新结束后恢复。**这是硬编码的特例 hack**，读代码时不要当成通用机制。
- `WorldGen` 更新（图格/液体/沙落）放在所有实体之后：实体先移动，再结算地形变化。

各子系统的实现要点：

- **玩家** `UpdateWorld_Players`（Terraria/Main.cs:17998）：`CheckBossIndexes()` → 清空坐/睡锚点 → 遍历 `i < 255` 的 `player[i].Update(i)`（`Player.Update` 在 Terraria/Player.cs:24542，开头把重力/跳跃/移速等**重置为默认值**再按装备修正，这是"每帧从基线重算属性"的典型写法）→ 统计活跃/睡眠玩家写入 `CurrentFrameFlags` → 客户端再做区块 `ActiveSections.CheckSection`（决定哪些区块需要更新/绘制）。
  - 单人为主机（`netMode != 2`）且创造模式无敌时，主玩家三围直接拉满（Terraria/Main.cs:18030-18040）。
  - 单个玩家 Update 抛异常时，`ignoreErrors` 为真则吞掉**继续循环**（Terraria/Main.cs:18019-18027）。
- **NPC** `UpdateWorld_NPCs`（Terraria/Main.cs:18072）：清 `nearbyActiveNPCs`、`CheckBossIndexes`、更新"已发现活跃 NPC"集合、Bestiary 世界扫描（客户端不做）、`NPCDamageTracker`；然后遍历 `k < maxNPCs` 调 `npc[k].UpdateNPC(k)`（Terraria/NPC.cs:91257）。单体异常时**直接把该槽位替换成 `new NPC()`**（相当于"删掉这个坏的"），这是与玩家的"跳过"不同的容错策略，因为坏掉的 NPC 留在世界会持续报错。
- **弹幕** `UpdateWorld_Projectiles`（Terraria/Main.cs:18170）：`LockOnHelper.SetUP()` 标记锁定阶段开始 → 前处理 hook（洞穴探险、诱饵桶）→ 遍历 1000 个 `projectile[i].Update(i)`（Terraria/Projectile.cs:16765），并把当前索引写进 `ProjectileUpdateLoopIndex` 供回调反查 → `SetDOWN()`。
- **物品** `UpdateWorld_Items`（Terraria/Main.cs:18198）：遍历 400 个 `item[i].UpdateItem(i)`（Terraria/WorldItem.cs:343）。注意池子里实际是 `WorldItem` 而非 `Item`（Terraria/Main.cs:1696），`Item` 是背包里的数据结构。
  - 服务端有"槽位冷却" `timeItemSlotCannotBeReusedFor`，冷却归零时回发 151 号包通知客户端；客户端出现该值非零则断言失败（Terraria/WorldItem.cs:347-359）。
- **尘埃** `UpdateWorld_Dust`（Terraria/Main.cs:18220）：调用 `Dust.UpdateDust()`（Terraria/Dust.cs:423），内部循环 `i < 6000`，但**只更新 `i < Main.maxDustToDraw` 的部分**（Terraria/Dust.cs:436），超出部分直接跳过 —— 这就是自适应画质 `gfxQuality` 能"降低尘埃数量"的实现方式：不是少生成，而是少更新/少绘制。若抛异常，`ignoreErrors` 下重建整个尘埃池（Terraria/Main.cs:18236-18244）。
- **时间** `UpdateWorld_Time`（Terraria/Main.cs:18257）→ `Main.UpdateTime()`（Terraria/Main.cs:65767）：核心是 `UpdateTimeRate()` 计算 `dayRate`（快进 60、睡觉 ×5、冻结 0、菜单 1，Terraria/Main.cs:6340-6365），然后 `time += dayRate`（Terraria/Main.cs:65908），再推进日月食/雨/沙尘/灯笼夜/派对/双月塔防等事件计时（Terraria/Main.cs:65906-65915）；昼夜切换走 `UpdateTime_StartDay/StartNight`（Terraria/Main.cs:66160/66315）并在 `time > 54000` 时重置（Terraria/Main.cs:66097-66104）。
- **地形** `UpdateWorld_WorldGenAndInvasion`（Terraria/Main.cs:18273）：`WorldGen.UpdateWorld()` + `UpdateInvasion()`，整段 try/catch 且 `ignoreErrors` 决定是否重抛。

### 8. 暂停与逐帧调试

- `WorldUpdateStepper.ShouldUpdateWorld()`（Terraria.Testing/WorldUpdateStepper.cs:20）：
  - 未暂停 → 恒 true；
  - 暂停时：按住 End/小键盘+ 满 12 帧后**每 2 帧放行一次**；或者按键刚松开的瞬间放行一次。
  - 这意味着暂停时 `DoUpdate` 的前半段（UI/输入/动画）照常跑，只有 `DoUpdateInWorld` 被冻结 —— 调试器可以在暂停态检查世界而不让它继续演化。
- 世界生成的 `WorldGen.generatingWorld` 与 `isGeneratingOrLoadingWorld` 会在多处短路：`ShouldUpdateEntities` 直接返回 false（Terraria/Main.cs:17891），自动保存被跳过，液体参数不被覆盖等。

### 9. 服务器主循环的差异

`Main.DedServ()`（Terraria/Main.cs:5319）先 `NeverSleep()` 阻止系统休眠，设 `dedServ=true / showSplash=false`，手动 `Initialize()`，然后在控制台循环里选世界，之后 `main.Run()` 用 `Terraria.Server` 的 Game 实现驱动 Update。服务端在 `DoUpdate` 里走 `dedServ` 分支：不设置 `IsFixedTimeStep`（那是客户端的自适应逻辑），而是用 `dedServFPS` 开关按秒统计 update 次数打印（Terraria/Main.cs:17089-17117）。
> 注意：`Program.RunGame` 里 `if (Main.dedServ)` 的判断先于 `DedServ()` 执行，而 `dedServ` 的置真发生在 `DedServ()` 内部（Terraria/Main.cs:5337），因此这条分支依赖服务器构建在此之前用其他方式置位；本反编译树中没有第二个置位点，**未验证**。

## 设计要点与取舍

1. **"一逻辑帧 = 固定的 1/60 秒"被写死在代码里，而不是用时间增量参数传递。** 从玩家、NPC 到弹幕，所有 `Update` 都不接收 dt（Terraria/Player.cs:24542、Terraria/NPC.cs:91257、Terraria/Projectile.cs:16765 的签名里都只有槽位索引）。代价是理论上的帧率无关性只能靠"钳住步长 + 丢时间"来保证；收益是全部数值调参（重力 0.1、移速累加 0.08 等）都可以写成"每帧常数"，代码极其朴素、可预测，也天然利于网络同步（服务端与客户端跑同样的逻辑步）。改倍速（`dayRate`）是唯一显式的时间倍率。
2. **时间累加器 + clamp 到 3 帧 = 防死亡螺旋。** 卡顿超过 50ms 后不会无限补帧（Terraria/Main.cs:17189），代价是"慢动作"：一旦超载，游戏时间会走得比真实时间慢。这是实时游戏的标准取舍——宁可掉速不卡死。
3. **三种 FrameSkipMode 共存于两套控制点。** `Off/Subtle` 用 `Main` 自己的累加器 + `EndDraw` 里基于 Present 间隔的自旋来实现"更新与绘制同频、垂直同步满帧"；`On` 则退回 FNA 的固定步长 + 可变时间步。代码里 `num3 = 0`（Terraria/Main.cs:17190）使老式跳帧分支恒不执行，说明作者已把"跳帧不绘制"整体废弃但保留了字段与分支，属于**渐进式改造留下的死代码**。
4. **两级自适应：帧率→画质，而非帧率→逻辑。** `gfxQuality` 每秒钟根据 `frameRate` 调整，驱动尘埃上限、血迹寿命、液体迭代次数、光照渲染阶段（Terraria/Main.cs:17235-17282）。这是"保逻辑速度、牺牲视觉质量"的选择。
5. **每子系统独立 RNG。** `SwapRandom` 让"随机"变成可切片的资源，任何子系统增删随机调用都不会串扰其他子系统。这在多人同步（服务端与客户端各自跑同样的随机）和回放/录制中至关重要，也是能让"回放一份输入，在本地重演相同世界"的基础。
6. **全局静态 + 单例 `instance` + 一个巨型 `Main` 类。** 好处：零查找开销、任何地方都能拿 `Main.player[Main.myPlayer]`；坏处：`DoUpdate` 与 `DoUpdateInWorld_Inner` 成了顺序不可拆解的"上帝函数"，子系统之间只能靠调用顺序、静态字段与"先清空再统计"的约定（如 `nearbyActiveNPCs`）耦合。跨系统修改时**务必读全上下文**，尤其注意"某方法开头重置了哪些静态字段"，它们往往由前面的阶段写入。
7. **异常容错的粒度很粗。** 多数循环用 `try/catch` + `ignoreErrors`（调试/测试模式为真时吞异常）；NPC/弹幕/物品在出错时"重建实例"而不是"跳过"，因为残留的半损坏实体会让后续每一帧继续抛。
8. **加载与初始化被拆成"资源 → 规则数据"两段。** 资源走了可中断的迭代器 + 后台线程池；规则数据（配方、商店、掉落表）是纯 CPU 的同步计算，被放在 splash 结束那一刻执行，从而可以在等待贴图的同时**不阻塞窗口响应**，同时又能保证进入菜单时所有静态表就绪。
9. **主线程任务队列是唯一的跨线程入口。** 所有需要碰游戏状态的异步回调都通过 `QueueMainThreadAction` 入队，在 `Update` 末尾统一消费（Terraria/Main.cs:16934、16959）。这避免了在 Update 中途被插入修改状态。
