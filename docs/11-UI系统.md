# UI 系统

> 适用范围：Terraria v1.4.5.8 反编译源码。路径均相对 `decompiled/Terraria/`。
> 阅读提示：反编译出的 `num/flag2/_isStateDirty` 等命名，本文统一转写为工程含义；`foreach` 展开的 `Enumerator + while(MoveNext())` 可脑内折叠回 `foreach`；`delegate{...}` 即 lambda。

## 一句话结论

Terraria 的 UI 是**一棵手工计算布局的 UIElement 树**：每个元素用 `StyleDimension`（绝对值 + 父容器尺寸的百分比）声明左/上/宽/高，再叠加 `Margin/Padding/HAlign/VAlign`，由 `Recalculate()` 自上而下一次性算出 `_outer/_dimensions/_inner` 三层矩形（没有 CSS 的"测量-排列"两遍，也没有布局缓存失效传播，父元素一变就整棵子树重算）。**UIState 只是一个铺满全屏的 UIElement 根节点**，真正的"状态栈"在 `UserInterface` 里：它维护一个最多 32 条的历史列表，`SetState/GoBack` 只负责切换"当前画哪棵树"，不保留离屏状态。全局只有两个 `UserInterface` 实例：主菜单用 `Main.MenuUI`，游戏内浮层（成就、按键设置、图鉴、表情、虚拟键盘等）用 `Main.InGameUI`，由布尔量 `Main.inFancyUI` 控制其生命周期。**物品槽交互没有走 UIElement 事件**——`ItemSlot` 是一个拥有 44 个 context 常量的巨型静态工具类，每个槽的宿主在自己的 `DrawSelf` 里顺手调用它完成悬停、点击、提示，直接读写 `Main.mouseItem`。

## 关键数据结构

### 尺寸与矩形
- `StyleDimension`（`Terraria.UI/StyleDimension.cs:3-37`）：`Pixels + Precent * 容器尺寸`（`StyleDimension.cs:19-22`）。注意字段名拼写就是 `Precent`（原文如此，非本文笔误）。预置 `Fill`（100%）、`Empty`（0）两个静态值（`StyleDimension.cs:5-7`）。
- `CalculatedStyle`（`Terraria.UI/CalculatedStyle.cs:5-28`）：浮点矩形，提供 `ToRectangle/Position/Center`。布局结果全部落在它上面，**只有命中测试时才转成整数 `Rectangle`**。
- `Alignment`（`Terraria.UI/Alignment.cs:5-35`）：九宫格对齐常量，本质是 `(0/0.5/1, 0/0.5/1)` 两个乘数，与 `UIElement.HAlign/VAlign` 同义。
- `StyleDimension` 的 `Width.Set(-10f, 0.5f)` 这种写法非常常见（如 `Terraria.GameContent.UI.States/UIManageControls.cs:262`），含义是"父宽的一半再减 10 像素"，用来给按钮留缝。

### 元素树
- `UIElement`（`Terraria.UI/UIElement.cs:11-617`）：
  - 子节点 `protected readonly List<UIElement> Elements`（`UIElement.cs:23`），只读暴露为 `Children`（`UIElement.cs:93`）。
  - 布局字段 `Top/Left/Width/Height` + `Min/MaxWidth/Height` + `Margin*/Padding*` + `HAlign/VAlign`（`UIElement.cs:25-69`）。
  - 三层矩形 `_outerDimensions / _dimensions / _innerDimensions`（`UIElement.cs:71-75`）：外层含边距、中层是元素本体（命中测试用它）、内层是去掉内边距后的"内容区"。**子元素是相对父元素的内层矩形定位的**。
  - 交互开关 `IgnoresMouseInteraction`（完全不参与命中）、`PassThroughMouseInteraction`（命中后可继续向下层找），`OverflowHidden`（裁剪子节点）。
  - `UniqueId` 由静态计数器自增（`UIElement.cs:87,125`），供游戏手柄导航等外部系统做稳定 key。
  - 事件是 C# `event` 委托（`UIElement.cs:97-121`）：左右键的 Down/Up/Click/DoubleClick、MouseOver/Out、ScrollWheel，以及 `OnUpdate/OnDraw`。
- `UIState`（`Terraria.UI/UIState.cs:3-13`）：**整份文件只有 13 行**。构造时把 `Width/Height` 设为 100%，外加一个 `NoGamepadSupport` 标志。这就是"状态"的全部定义——一棵铺满屏幕的 UIElement 子树。
- `UIEvent / UIMouseEvent / UIScrollWheelEvent`（`Terraria.UI/UIEvent.cs:3-11`、`UIMouseEvent.cs:5-14`、`UIScrollWheelEvent.cs:5-14`）：`Target`（真正被点中的元素）、`MousePosition`、`ScrollWheelValue`。

### UserInterface 的输入缓存
`UserInterface`（`Terraria.UI/UserInterface.cs:11-357`）内部有私有类 `InputPointerCache`（`UserInterface.cs:15-39`），左右键各一份（`UserInterface.cs:53-91`）：
- `WasDown`（上一帧是否按下）、`LastDown`（按下时的目标元素）、`LastClicked`（用来判双击）、`LastTimeDown`（上次按下时间戳）。
- 四个委托 `MouseDownEvent/MouseUpEvent/ClickEvent/DoubleClickEvent` 把"左键/右键"的差异抽象掉，`HandleClick` 只写一份逻辑。

常量：`DOUBLE_CLICK_TIME = 500` ms（`UserInterface.cs:41`）、`STATE_CHANGE_CLICK_DISABLE_TIME = 200` ms（`UserInterface.cs:43`）、历史上限 32 / 裁剪 4（`UserInterface.cs:45-47`）。

### ItemSlot 的 context 体系
`ItemSlot.Context`（`Terraria.UI/ItemSlot.cs:35-126`）用常量整数编码"这个槽在什么语义场景里"，从 `InventoryItem = 0`（`ItemSlot.cs:37`）一直到 `NewCraftingUIMaterial = 43`（`ItemSlot.cs:125`）。所有行为差异都靠这张表分支，例如背包 0 / 钱币 1 / 弹药 2 / 宝箱 3 / 银行 4 / 垃圾桶 6 / 商店 15 / 合成材料 22 / 鼠标携带 21。`Count = 44`（`ItemSlot.cs:125`）用于给一组 `bool[44]` 策略表定长度（静态构造函数 `ItemSlot.cs:316-410`）：`canFavoriteAt / canLoadoutShareAt / canShareAt / canQuickDropAt / canItemSwapAt / retainFavoriteOnMoveAt / hideNewAndShinyHighlightAt`。这些表在静态构造里逐项置 true（`canFavoriteAt` 只对 0/1/2/32 四个 context 生效，`ItemSlot.cs:358-361`；`canLoadoutShareAt` 只对 8/9/10/11/12 五个 context 生效，`ItemSlot.cs:367-371`；`canShareAt` 则几乎覆盖全部 context，`ItemSlot.cs:372-407`）；尤其注意 `retainFavoriteOnMoveAt` 只覆盖 0/1/2/5/32 五个 context（`ItemSlot.cs:362-366`），并非全表，等于一份"按 context 查询的能力矩阵"。注意 `Count = 44` 指的是 context **个数**，而部分 context 编号没有在 `LeftClick`/`RightClick` 的主 switch 中出现（例如 21、22、31、40），这些槽只参与悬停提示或作为只读展示槽。

### 常量式"装备栏"结构
`ItemSlot` 还持有：
- `inventoryGlowHue/Time` 与 `...Chest` 共四个长度 58 的数组（`ItemSlot.cs:330-333`），对应背包 58 槽的"新物品高亮"计时（"新物品"发光效果）。
- `playerSlotPulseEffects`（`ItemSlot.cs:334`），按 `PlayerItemSlotID` 索引的槽位脉冲效果，用于 `IndicateBlockedSlot` 这类"这个槽放不进去"的抖动提示（`ItemSlot.cs:527-532`）。

## 执行流程

### 1. 布局：Recalculate 一次算完整棵子树
`UIElement.Recalculate()`（`UIElement.cs:291-310`）：
1. 取父容器的**内层**尺寸；没有父节点就取 `UserInterface.ActiveInstance.GetDimensions()`，即把整屏尺寸除以 `Main.UIScale`（`UserInterface.cs:332-336`）。这是"UI 坐标系"的根。
2. 若父元素是 `UIList`，把父高度强制置为 `float.MaxValue`（`UIElement.cs:294-297`）——列表里的条目允许无限高。
3. `GetDimensionsBasedOnParentDimensions`（`UIElement.cs:312-328`）：`X/Y = 父X/Y + Left/Top.GetValue(父尺寸)`；宽高先用 `Min/Max` 夹一次；**然后再加上 Margin 的两倍**（`UIElement.cs:323-324`），接着 `HAlign/VAlign = (父尺寸 - 自身含边距尺寸) * 对齐系数`（`UIElement.cs:325-326`）。因此 `HAlign = 0.5f` 才是真居中。
4. 结果存进 `_outerDimensions`；依次减掉边距得到 `_dimensions`（`UIElement.cs:299-303`），再减内边距得到 `_innerDimensions`（`UIElement.cs:304-308`）。
5. `RecalculateChildren()` 递归（`UIElement.cs:378-384`）。

**取舍**：这是 O(节点数) 的整树重算，没有脏标记。调用点很节制——只有 `Append`（`UIElement.cs:177`）、`CopyStyle`（`UIElement.cs:417`）、`SetState`（`UserInterface.cs:300`）、窗口尺寸变化（`Terraria/Main.cs:67377`）等少数场合触发。但 `UIList.DrawSelf` 在**绘制阶段**每帧调一次 `Recalculate()`（`Terraria.GameContent.UI.Elements/UIList.cs:179-186`），也就是"按滚动条偏移重排列表"的策略，代价是列表类界面每帧整树重排。

### 2. 绘制：UIElement.Draw 的 spriteBatch 切换
`Draw`（`UIElement.cs:203-242`）：
1. 先发 `OnDraw` 事件。
2. 若 `UseImmediateMode` 或指定了 `OverrideSamplerState`，End/Begin 一遍只画 `DrawSelf`，再 Begin 回默认状态（`UIElement.cs:214-221`）——这是为了在单帧内换采样器（例如像素画风贴图需要 PointClamp）。
3. 若 `OverflowHidden`，用 `GetClippingRectangle` 算出裁剪矩形设置到 GraphicsDevice，并换 `OverflowHiddenRasterizerState`（`UIElement.cs:226-241`）；画完子节点后恢复。
4. `DrawChildren` 按 `Elements` 顺序**后加者画在上面**（`UIElement.cs:164-170`）。

坐标系全程使用 `Main.UIScaleMatrix`，即一个 `Matrix.CreateScale(UIScale)`（`Terraria/Main.cs:2641-2649`）。`UIScale` 会被 `UIScaleMax` 限制，后者按"真实分辨率 / 800×600"取比例并保证 ≥1（`Terraria/Main.cs:2660-2667`）。这就是"UI 不会比 800×600 更小"的来历。

`GetClippingRectangle`（`UIElement.cs:256-275`）把内层矩形乘上 UIScaleMatrix，再与当前 Scissor 矩形二次求交——**嵌套的 OverflowHidden 因此天然支持**，不需要父裁剪矩形显式传递。

### 3. 输入：UserInterface.Update 的命中 → 悬停 → 点击
`UserInterface.Update`（`UserInterface.cs:190-228`）每帧：
1. 取鼠标位置；若 `PlayerInput.UsingGamepad`，位置改为"当前手柄选中锚点"的位置（`UserInterface.cs:181-188`），于是同一套命中代码即可服务手柄。
2. 若 `Main.gameMenu == false && PlayerInput.IgnoreMouseInterface`（聊天输入等场景），本帧不做命中（`UserInterface.cs:196-202`）。
3. `GetElementAt(MousePosition)`：**从后往前遍历子节点**（后加的在上层），命中就停止；`PassThroughMouseInteraction` 让其继续往下层找（`UIElement.cs:330-358`）。找到候选后递归进入它的 `GetElementAt`，实现"最深的那个元素接管悬停"。若子节点都没命中，才检查自己（`UIElement.cs:349-357`）。
4. 悬停元素变化时，对旧元素发 `MouseOut`、新元素发 `MouseOver`（`UserInterface.cs:205-213`）。**事件是沿父链向上冒泡的**：`MouseOver` 设置 `IsMouseHovering = true` 后调父节点的同名方法（`UIElement.cs:516-527`），所以父容器也能知道"指针在我那个范围里"。
5. `HandleClick`（`UserInterface.cs:230-255`）：上升沿发 Down，若 500ms 内连点同一元素则追加 DoubleClick；下降沿时**只有鼠标仍在该元素内含点时**才发 Click，然后发 Up（`UserInterface.cs:243-253`）。这杜绝了"按下 A 拖到 B 松手"被误判为点击。
6. 滚轮按 `PlayerInput.ScrollWheelDeltaForUI` 发送给当前悬停元素，然后清零（`UserInterface.cs:219-223`）。
7. 最后递归 `_currentState.Update(time)`（`UIElement.cs:244-254`），先发 `OnUpdate` 再遍历子节点。

`STATE_CHANGE_CLICK_DISABLE_TIME` 的作用：切换状态后的 200ms 内点击被禁用（`UserInterface.cs:203-204,214-218`），防止"点了一个按钮，新界面在同一位置又冒出一个按钮，被同一次点击误触"。

### 4. UIState 栈：SetState / GoBack / 历史裁剪
`SetState(UIState)`（`UserInterface.cs:276-303`）：
1. 同一个状态直接返回。
2. 非 null 时压入历史（`AddToHistory`，`UserInterface.cs:315-322`），历史超过 32 条就丢弃最老的 4 条（**不是 1 条**：`RemoveRange(0, 4)`）。
3. 旧的当前状态：先对悬停元素发 `MouseOut`，再 `Deactivate()`（递归 `OnDeactivate`，`UIElement.cs:590-597`）。
4. 换指针，`ResetState()`（`UserInterface.cs:165-179`）清空指针缓存、并至少再禁点 200ms。
5. 新状态 `Activate()`（`UIElement.cs:554-565`）：若 `_isInitialized` 为假，先对**根节点**调一次 `Initialize()`（`UIElement.cs:603-607`，`OnInitialize` 里通常一次性建好整棵子树），再调 `OnActivate`；然后递归**每个子节点**的 `Activate()`——子节点同样只经历一次 `OnInitialize`，但会因当前状态被再次激活而**再次触发 `OnActivate`**。
6. `Recalculate()`，并置 `_isStateDirty = true`（`UserInterface.cs:296-301`），在下一次 `Draw` 中再重算一次（`UserInterface.cs:262-266`）。

`GoBack`（`UserInterface.cs:305-313`）：历史里至少 2 条时，取倒数第二条作为目标，并把最后两条一起删掉，再 `SetState`。**注意 `SetState` 会把目标重新压回历史**，所以"返回"之后历史长度是 `n-1`，可以连续返回。这就是所谓"状态栈"——它其实是一个"只追加、返回时成对弹出"的列表，**不保留离屏 UIState 的实例状态**：状态对象里保存的 UI 子树和字段都还在（因为对象被历史列表引用着），但 `_isInitialized` 已置位、`OnActivate` 会再跑一遍。多数写法在 `OnActivate` 里重排界面（如 `UIManageControls.OnActivate` 按 `Main.gameMenu` 调整容器位置，`Terraria.GameContent.UI.States/UIManageControls.cs:705-714`）。

`ActiveInstance`（`UserInterface.cs:49`）：静态字段，构造时和 `Use()` 时被赋值（`UserInterface.cs:143,146-157`），`UIElement.Recalculate` 与 `UIScrollbar` 都通过它来拿"根尺寸"和"鼠标位置"。这是典型的全局单例耦合：**同一时刻只能有一个 UserInterface 是"活动"的**。

### 5. 两类宿主：主菜单 MenuUI 与游戏内 InGameUI
- 两个实例：`Main.MenuUI`（`Terraria/Main.cs:391`）、`Main.InGameUI`（`Terraria/Main.cs:393`）。
- 更新：`UpdateUIStates` 依次调 `MenuUI.Update`、`InGameUI.Update`（`Terraria/Main.cs:17663-17670`），随后是创意菜单、新版合成 UI 各自的非 UIElement 更新。
- 可见性每帧重算：`MenuUI.IsVisible = gameMenu && menuMode == 888`；`InGameUI.IsVisible = !gameMenu && InGameUI.CurrentState != null`（`Terraria/Main.cs:62642-62643`）。`menuMode == 888` 是"正在显示某个 UIState 全屏菜单"的约定值（如 `Main.GoToWorldSelect` 先置 888 再 `SetState`，`Terraria/Main.cs:48977-48981`）。
- 主菜单绘制：在菜单绘制流程里只有 `menuMode == 888` 且 `!_blockFancyUIWhileLoading` 时才 `MenuUI.Draw`，`menuMode != 888` 时主动 `SetState(null)` 清空；加载中（`_blockFancyUIWhileLoading`）即使 888 也不绘制（`Terraria/Main.cs:51846-51855`）。这说明菜单不是"每帧都画同一棵树"，而是靠 menuMode 驱动状态更换。
- 游戏内绘制：`InGameUI.Draw` 被挂在 InterfaceLayers 的 `Vanilla: Fancy UI` 层（`Terraria/Main.cs:45532`），在 `DrawInterface_12_IngameFancyUI` 中先自行 End/Begin 换成 `UIScaleMatrix`，再调用（`Terraria/Main.cs:46917-46927`）。若 `inFancyUI` 且 `IngameFancyUI.Draw` 返回 false，则这一层返回 false，**后续 InterfaceLayers 全部不再绘制**（`Terraria/Main.cs:45684-45689` 的 `while(... && layer.Draw())`）——全屏浮层就是靠返回值做"遮罩"的。
- 专用快路径：`onlyDrawFancyUI` 为真时跳过整个世界绘制，只画 `InGameUI`（`Terraria/Main.cs:63051-63060`）。

### 6. IngameFancyUI：游戏内浮层的开关与收尾
`Terraria.UI/IngameFancyUI.cs` 是游戏内 UIState 的"门面"：
- `OpenUIState(state, closeIngameWindows)`（`IngameFancyUI.cs:69-79`）：置 `CoverNextFrame` 标志、清聊天输入、关掉所有旧式背包窗口（`IngameUIWindows.CloseAll`），置 `Main.inFancyUI = true`，再 `InGameUI.SetState`。入口如表情菜单（`Terraria/Main.cs:43126`）、图鉴（`Terraria/Main.cs:43181`）。
- `CanCover()`（`IngameFancyUI.cs:21-33`）：允许"只遮挡一帧"的一次性放行，用于切换动画的第一帧。
- `Draw`（`IngameFancyUI.cs:190-226`）：先处理虚拟键盘的"小屏 + 手柄"例外；若 `InGameUI.IsElementUnderMouse()` 为真则把 `LocalPlayer.mouseInterface` 置位，**世界层面的鼠标交互因此被屏蔽**；若 `inFancyUI` 已为假（被外部关掉），这里兜底 `SetState(null)`。
- `Close`（`IngameFancyUI.cs:162-188`）：置 `inFancyUI=false`，视情况自动打开背包（`playerInventory = true`），再 `SetState(null)`。

这里体现的是 Terraria 的遗留设计：**没有"模态对话框"抽象**。全屏 UI 的其余画面（背包、宝箱）仍然走 `Main` 里那一大堆 `DrawInterface_*` 过程式绘制，新版 UIState 只是"盖在游戏世界上的一个矩形"。

### 7. InterfaceLayers：老式 UI 的"层序表"
`GameInterfaceLayer`（`Terraria.UI/GameInterfaceLayer.cs:8-56`）：一个带 `Name` 和 `ScaleType` 的绘制项。`Draw()` 按类型切换缩放：`Game` → 世界缩放矩阵；`UI` → `UIScaleMatrix`；其余 → 恒等（`GameInterfaceLayer.cs:20-37`）。每次调用都自带 Begin/End，并用 try/catch 把绘制异常送进 `TimeLogger.DrawException`（`GameInterfaceLayer.cs:39-49`）。返回值是"是否继续画后面的层"。

`SetupDrawInterfaceLayers` 用硬编码数组建 43 个层（`Terraria/Main.cs:45466-45473`），`DrawInterface` 用 `while (enumerator.MoveNext() && enumerator.Current.Draw())` 顺序执行（`Terraria/Main.cs:45684-45689`）。`LegacyGameInterfaceLayer` 把无参委托包成一个层（`Terraria.UI/LegacyGameInterfaceLayer.cs:5-20`），绝大多数层都是这种适配器。

### 8. ItemSlot：不注册事件的物品槽
`ItemSlot.Handle(inv, context, slot, allowInteract)`（`ItemSlot.cs:561-569`）是唯一的"入口"，顺序固定为：
1. `OverrideHover`（`ItemSlot.cs:571-598`）：当鼠标悬停时，根据当前按键把 `Main.cursorOverride` 设为"收藏星/可分享/垃圾桶"等光标（`ItemSlot.cs:586-598`）。空槽直接返回。
2. `LeftClick`（`ItemSlot.cs:886-1222`）与 `RightClick`（`ItemSlot.cs:1614-1694`）。
3. `MouseHover`（`ItemSlot.cs:3169-...`）：把物品拷进 `Main.HoverItem`、记录 `tooltipContext/tooltipSlot`，并视 context 设置 `buy/social/wornArmor` 等提示标志（`ItemSlot.cs:3179-3204`）。

左键的核心是 `PickItemMovementAction`（`ItemSlot.cs:1459-1612`）：先判"这次操作是什么语义"，再在 `LeftClick` 里按返回码分支：
- 返回 `0`：整堆交换（含"鼠标携带物与槽位"互换）。以 `MouseItemSwap` + 栈上限合并实现，支付、声音、网络同步（`context == 3` 时发包 `NetMessage.SendData(32,...)`）都在这里（`ItemSlot.cs:904-991`）。
- 返回 `1`：单件移动。鼠标携带 1 件且槽位已有别的物品时走 `MouseItemSwap`；槽位为空时直接克隆一件并把鼠标物品减 1（`ItemSlot.cs:991-1092` 的 case 1 分支）。这正是"右键逐件拿取"的底层。
- 返回 `2`：拆分，鼠标已空且右键按下时，每次把"半堆"拿到鼠标上（`ItemSlot.cs:1093` 附近的 case 2）。
- 返回 `3`：仅悬停高亮、不响应点击（`ItemSlot.cs:1191` 起的 case 3 直接返回）。

右键（`ItemSlot.cs:1614-1694`）同样是"按 context 分派"：
- `context == 15`（商店）直接走 `HandleShopSlot`（`ItemSlot.cs:1626-1628`）。
- 可开启的礼袋（`ItemID.Sets.OpenableBag`）、可变换的物品（`ItemID.Sets.HasItemSwap`）走对应的回调，且都以 `Main.mouseRightRelease` 为前提，避免长按连发（`ItemSlot.cs:1637-1653`）。
- 虚荣槽 9/11（`SwapVanityEquip`）、背包/银行/虚空袋里单价可装备物品（`SwapEquip`）会自动装备（`ItemSlot.cs:1656-1675`）。
- 其余情况走"逐件拿到鼠标"：`Main.superFastStack + 1` 件/帧，并刷新 `stackSplit` 冷却（`ItemSlot.cs:1678-1692`）。这就是"按住右键快速把整堆搬到鼠标上"。

`HandleShopSlot`（`ItemSlot.cs:2013-2074`）：先检查堆叠合并可行性，再按 `GetItemExpectedPrice` 算购买价、`BuyItem` 扣钱，用 `shopSellbackHelper` 记录可退货条目，最后 `AnnounceTransfer` 发全局转移事件。

批量购买件数 `superFastStack + 1`，若 `CanBulkBuy` 还会再乘上 `GetBulkBuyAmount`（`ItemSlot.cs:2025-2031`）——这是"批量买/批量合成"的统一入口。

### 9. 物品槽三种宿主写法
同一个 `ItemSlot` 有三条挂载方式：
1. **DrawSelf 顺手处理**：`UIItemSlot`（`Terraria.GameContent.UI.Elements/UIItemSlot.cs:7-40`）在 `DrawSelf` 里先 `HandleItemSlotLogic`（仅当 `IsMouseHovering` 为真），再 `ItemSlot.Draw`。**"更新"与"绘制"被强行合并到同一时刻**，因为 `ItemSlot` 需要"这一帧鼠标确实悬停在这个槽上"这个信息。
2. **裸坐标循环**：`ChestUI.DrawSlots`（`Terraria.UI/ChestUI.cs:324-388`）自己算 10×4 网格的像素坐标，对每个槽手工判 `Utils.FloatIntersect` 后才调 `ItemSlot.Handle`，随后无条件 `ItemSlot.Draw`（`ChestUI.cs:369-380`）。宝箱/银行/虚空袋共用的同一套代码，靠 `player.chest` 的值映射 context 3/4/32（`ChestUI.cs:348-366`）。
3. **Main 的主背包**：整体由 `Main.DrawInterface_...` 进程式绘制，靠 `Main.inventoryScale`（`Terraria/Main.cs:1788`）与 `invBottom`（`Terraria/Main.cs:1170`）定位，不走 UIElement 树。

`UIItemSlot` 的尺寸固定 48×48（`UIItemSlot.cs:20-21`），绘制位置还要按 `Main.inventoryScale` 再缩放、以中心对齐（`UIItemSlot.cs:37-38`）——说明"槽外观尺寸是 52 像素"是硬编码的美术约定。

### 10. 全屏界面的组织
`Terraria.GameContent.UI.States/` 下每个大文件一个 `UIState`，结构高度雷同（对照 `UIAchievementsMenu.InitializePage`，`Terraria.GameContent.UI.States/UIAchievementsMenu.cs:28-73` 与 `UIManageControls.OnInitialize`，`Terraria.GameContent.UI.States/UIManageControls.cs:130-222`）：

1. **外层容器**：一个宽度 `0.8f`、`MaxWidth` 600~900、`Top=220`、`Height = 父高 - 220` 的 `UIElement`，`HAlign = 0.5f`。注释不写但语义是"居中、留出上方标题栏"。
2. **主面板**：`UIPanel` 铺满外层，`BackgroundColor = (33,43,79)*0.8`，`Height = 父高 - 110`（减掉底部按钮条）。`UIPanel` 默认自带 12 像素内部边距（`Terraria.GameContent.UI.Elements/UIPanel.cs:32`）。
3. **列表**：`UIList` + `UIScrollbar`，列表宽 `-25` 给滚动条让位，并 `SetScrollbar` 绑定（`UIAchievementsMenu.cs:51-56`）。
4. **标题条**：`UITextPanel<LocalizedText>`，`Top = -33~-45`（负的绝对偏移 = 向上溢出父容器）。
5. **底部按钮**：`UITextPanel`，`VAlign = 1f` + `Top = -45` + `Height = 50`，绑定 `OnMouseOver/OnMouseOut` 做淡入淡出、`OnLeftClick` 做动作（`FadedMouseOver/FadedMouseOut` 就是改 `BackgroundColor/BorderColor`，见 `UIManageControls.cs:940-947`）。
6. **返回**：主菜单场景下 `GoBackClick` 通常是 `Main.menuMode = 某值`（如 `UIManageControls.cs:949-953` 置 1127，`UIWorldSelect.cs:110-116` 的 `NewWorldClick` 置 `menuMode = 888` 后 `SetState(new UIWorldCreation())`，而返回按钮 `UIWorldSelect.cs:76` 绑定的 `GoBackClick`（`UIWorldSelect.cs:118-122`）只把 `menuMode` 设为 1 或 12）；游戏内场景则是 `IngameFancyUI.Close()`。

`UIList`（`Terraria.GameContent.UI.Elements/UIList.cs:10-197`）另有值得注意的细节：
- 内部包裹一层 `UIInnerList`，其 `ContainsPoint` 恒返回 true（`UIList.cs:16-19`），等于"列表区域内的任何一点都算点到了列表"，这样滚动条/空白区域也能吞掉鼠标，不至于点到背后的东西。
- 只绘制与可见区相交的条目（`UIList.cs:21-34`），这是列表的视口裁剪。
- 条目排序靠 `UIElement.CompareTo`（`UIList.cs:160-163`，基类返回 0，由子类覆盖）；也支持 `ManualSortMethod` 手动排序（`UIList.cs:147-158`）。
- 滚动实现是"反向移动整个内层列表的 `Top`"（`UIList.cs:179-186`），配合 `UIScrollbar.ViewPosition` 的取值钳位（`Terraria.GameContent.UI.Elements/UIScrollbar.cs:37-47`）：setter 为 `Clamp(value, 0, _maxViewSize - _viewSize)`，而 `SetView`（`UIScrollbar.cs:72-78`）**先钳位旧的 `_viewPosition`、再更新 `_viewSize/_maxViewSize`**，无内容时两者同为 0，区间退化为 `[0,0]`。

### 11. 控件层面的通用模式
- `UIImageButton`（`Terraria.GameContent.UI.Elements/UIImageButton.cs:9-74`）：构造时按贴图尺寸自动设宽高（`UIImageButton.cs:31-32`）；`DrawSelf` 用 `IsMouseHovering ? 1f : 0.4f` 的透明度做"禁用/可用"外观（`UIImageButton.cs:48-56`）；`MouseOver` 里播提示音（`UIImageButton.cs:58-62`）。**很多按钮没有单独的 Click 声音**，声音统一挂在 MouseOver。
- `UIColoredSlider`（`Terraria.GameContent.UI.Elements/UIColoredSlider.cs:46-105`）：用两个静态字段 `CurrentAimedSlider / CurrentLockedSlider`（`UISliderBase.cs:13-15`）做"拖动锁定"。**判定逻辑在 DrawSelf 里**：鼠标松开时清锁、鼠标在条上或已锁定时记录、松手前保持拖动（`UIColoredSlider.cs:57-65,78-82`）。与 ItemSlot 的写法一致——**"每帧在绘制时读输入"是这套 UI 的通用范式**，而不是传统事件驱动的控件。
- `UIScrollbar`：`AutoHide` 让无内容可滚时自行隐藏（`UIScrollbar.cs:103-125`）；拖动中直接用 `ActiveInstance.MousePosition` 换算比例（`UIScrollbar.cs:109-113`）。**滚动条绕过事件系统直接读全局鼠标位置**，是又一个隐式依赖单例的地方。

## 设计要点与取舍

1. **"布局 = 一次递归计算"而非失效传播**。牺牲了"只改一个元素就局部重排"的优化，换取代码量极小：整个布局引擎不到 40 行（`UIElement.cs:291-328`）。代价是 `UIList` 这类"每帧滚动"的容器必须在绘制时整树重算（`UIList.cs:179-186`）。
2. **"状态栈"名不副实**。`UIState` 只是根节点容器（13 行），历史列表 `_history` 只是一个 `List<UIState>`（`UserInterface.cs:51`），没有"暂停/恢复"语义，也没有事务化。`GoBack` 的成对弹出（`UserInterface.cs:307-312`）与 32/4 的裁剪策略（`UserInterface.cs:315-322`）是纯粹的"手感优先"的近似实现——连续返回几十次后更早的历史会被整段丢失。
3. **事件沿父链冒泡，`Target` 保持最初命中的元素**。这允许父容器用 `evt.Target` 区分"是哪个子按钮被点了"（如 `UIManageControls` 的 `FadedMouseOver` 直接把 `evt.Target` 强转 `UIPanel`，`UIManageControls.cs:936-941`）。
4. **`PassThroughMouseInteraction` + `OverflowHidden` 覆盖了绝大多数"层叠"需求**，所以不需要真正的 z-index：后 `Append` 的在上、命中反序遍历、裁剪靠 ScissorRect 取交集，三者合起来能得到一致的结果（`UIElement.cs:226-241,330-358`）。
5. **`ItemSlot` 是典型的"上帝类"**：4674 行、44 个 context、十几张策略表、Draw 与逻辑混在一点。好处是**物品槽行为集中，UI 层零成本接入**；坏处是任何新界面都必须同时理解"context 语义"和"谁负责调用 Handle"。`UIItemSlot` 只用了 3 行代码就完成接入（`UIItemSlot.cs:24-31`），正是这个设计真正兑现的收益。
6. **`ActiveInstance`、`Main.*`、`ItemSlot` 静态状态构成了隐式全局耦合**。`UIElement` 不知道自己在哪棵树上，只能通过 `UserInterface.ActiveInstance.GetDimensions()` 反推根尺寸（`UIElement.cs:293`）；`MenuUI.Draw` 第一步就是 `Use()`（`UserInterface.cs:259`），把 `ActiveInstance` 切到自己。这意味着**嵌套渲染两个根 UI 需要显式 `Use()` 切换**，否则布局会按错误的根尺寸算。
7. **触摸/手柄统一到"鼠标位置"**。`GetMousePosition` 在手柄模式下返回"当前导航锚点"的位置（`UserInterface.cs:181-188`），于是所有命中逻辑不需要第二套实现。手柄导航本身由 `UILinkPointNavigator` 负责，各状态在 `Draw` 末尾手工"连线"（如 `UIManageControls` 的 `SetupGamepadPoints`，`UIManageControls.cs:961-1015`）。`UIState.NoGamepadSupport` 就是留给"这页不需要手柄"的开关。
8. **同时存在三代 UI 技术**：过程式（背包/宝箱/主 HUD，`Main.DrawInterface_*`）、UIElement 树（全屏菜单）、中间态（`ItemSlot` 静态工具类被两代共享）。文章开头"UI 系统"其实是这三者的并集，读源码时必须先判断一段代码属于哪一代。
