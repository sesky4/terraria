# 音频系统

> 源码范围：`decompiled/Terraria/`，重点为 `Terraria.Audio/` 命名空间、`Terraria/Main.cs` 音频驱动部分。
> 文中所有 `路径:行号` 均相对 `decompiled/Terraria/`。

## 一句话结论

Terraria 的音频分成两条互不相干的通道：**短音效**走 XNA/FNA 的 `SoundEffect`/`SoundEffectInstance`（旧的 `LegacySoundPlayer` 大 switch + 新的 `SoundPlayer` + `SlotId` 句柄追踪），**音乐**走 XACT（`AudioEngine`/`SoundBank`/`WaveBank`/`Cue`），并用资源包里的 OGG/WAV/MP3 解码轨替换内置 cue；两者统一经 `SoundEngine` 这层静态门面暴露给 `Main` 与游戏逻辑，并用 `Main.soundVolume / ambientVolume / musicVolume` 三个全局音量做最终衰减。

## 关键数据结构

### `SoundEngine`（静态门面）— `Terraria.Audio/SoundEngine.cs:11`

| 成员 | 作用 |
|---|---|
| `LegacySoundPlayer` / `SoundPlayer` | 两个播放器实例，只有在 `IsAudioSupported` 为真时才创建（SoundEngine.cs:37-44） |
| `AreSoundsPaused` | 记录上一帧是否处于"聚焦丢失即暂停"状态，用于检测边沿（SoundEngine.cs:19） |
| `IsAudioSupported` | 由启动自检决定，被几乎所有 API 当早退条件（SoundEngine.cs:21） |

### `LegacySoundPlayer` — `Terraria.Audio/LegacySoundPlayer.cs:12`

- 每类音效一对数组：`Asset<SoundEffect>[]`（资源句柄，异步加载）+ `SoundEffectInstance[]`（预创建、可复用的实例槽）。例如 `SoundDig/SoundInstanceDig`（:26-28）、`SoundCoin`（:42-44）、`SoundZombie`（:131 附近）、`SoundSplash`（:141 附近）。
- `SoundAttenuationDistance = 2500f`（:160）：**像素单位**的线性衰减半径，是新旧两条播放路径共用的常量。
- `TrackableSounds` / `TrackableSoundInstances`（:152-154）、`_trackedInstances`（:159）：前者是资源包自定义音效列表，后者保存所有由 `CreateInstance` 生成的实例，`Reload` 时统一 `Dispose`（:264-270）。

### `ActiveSound` 与 `SlotId` — `Terraria.Audio/ActiveSound.cs:9`

一个 `ActiveSound` = "一个正在开着的 `SoundEffectInstance` + 它的风格（`SoundStyle`）+ 位置/音量/音高 + 可选循环条件"。

- `IsGlobal`（:13）：全局音（如 UI 提示）不做 3D 衰减与声像。
- `Condition`（:21）：`LoopedPlayCondition` 委托，每帧 `Update` 时求值，为 false 立即停止（:139-144）。
- `Position`、`Volume`、`Pitch` 是**公开可变字段**，游戏逻辑每帧自行写入（例：`Projectile.cs:38942-38946`）。

`SlotId` 是 `ReLogic.Utilities` 提供的句柄类型（`SlotVector` 的索引+版本号），**本仓库中未包含其定义**，能在源码里看到的只有它的用法：`SlotId.Invalid`（SoundEngine.cs:167）、`SlotId.FromFloat(...)` / `.ToFloat()`（Projectile.cs:38936、38940）；后者用于把句柄塞进 `localAI[]` 这类浮点数组里持久化。句柄具体编码属于外部库（ReLogic），本文不臆测。

### `SoundStyle` 家族 — `Terraria.Audio/SoundStyle.cs:6`

- 基类持有 `Volume`、`PitchVariance`、`Type`（Sound/Ambient/Music，见 `SoundType.cs`），并提供 `GetRandomPitch()`：在 `±PitchVariance/2` 均匀抖动（SoundStyle.cs:40-43）。
- `LegacySoundStyle`（LegacySoundStyle.cs:8）是"数字 ID + 变体"：`SoundId` + `_style` + `Variations`。`Style` 属性在变体数 >1 时随机返回 `_style.._style+Variations-1`（:22-32）。
- **关键设计**：`IsTrackable => SoundId == 42`（:32）。数字 42 是"可追踪自定义音效"的魔法槽位，`SoundID.CreateTrackable` 一律用 `new LegacySoundStyle(42, count, ...)` 构造（Terraria.ID/SoundID.cs:1229），所以只有这些音效才能进 `SoundPlayer` 的新式追踪体系。注意这里的 `count`（:1216）是**注册时列表当前的元素总数**，即该音效在全局可追踪音效序列里的起始下标；`Style` 在变体数 >1 时为 `count..count+Variations-1`，**不是从 0 起的局部下标**。`CustomSoundStyle` 则总是 `IsTrackable => true`（CustomSoundStyle.cs:14）。
- `WithVolume/WithPitchVariance/AsMusic/AsAmbient` 都是"返回新对象"的不可变改造器（LegacySoundStyle.cs:65-95；其后 `Includes` 在 :97-104）。`WithVolumePerceived` 做了一次 `volume^1.6609` 的幂补偿（:70-75），把"人耳感知音量"映射到线性振幅。

## 执行流程

### 1. 启动与能力自检

1. `Main` 构造流程中调用 `audioSystem = SoundEngine.Initialize()`（Terraria/Main.cs:10927）。
2. `Initialize` 先跑 `TestAudioSupport()`：构造一段 166 字节的 8kHz 单声道静音 WAV 放进 `MemoryStream`，用 `SoundEffect.FromStream` 试探硬件（SoundEngine.cs:200-223）。捕获 `NoAudioHardwareException` 或任何异常都判为不支持。
3. 支持则返回 `new LegacyAudioSystem()`，否则 `new DisabledAudioSystem()`（SoundEngine.cs:23-35）。`DisabledAudioSystem` 所有方法为空实现，`IsTrackPlaying` 恒 false、`GetAvailableAudioRenderers` 返回空表（DisabledAudioSystem.cs:52-80）——这是"无声模式下所有音乐逻辑照常运转但无副作用"的优雅降级。
4. 随后 `audioSystem.SetPlayCallback(102, RainbowBoulderMusicPlayCallback)`（Main.cs:10928）。回调在 `LegacyAudioSystem.UpdateCommonTrack` 每次真正 `Play` 时触发，并自增循环计数（LegacyAudioSystem.cs:306-316）；`Main.RainbowBoulderMusicPlayCallback` 借此在彩虹巨岩音乐播完第一遍后切到 103（Main.cs:62546-62556）。

### 2. 音效资源加载

1. `AssetInitializer.LoadSounds` 调用 `SoundEngine.Load(Services)`（Terraria.Initializers/AssetInitializer.cs:97-100）。
2. `SoundEngine.Load` 仅当 `IsAudioSupported` 时 `new LegacySoundPlayer(services)` 与 `new SoundPlayer()`（SoundEngine.cs:39-46）。
3. `LegacySoundPlayer` 构造 ⇒ `LoadAll()`（LegacySoundPlayer.cs:163-167）。`LoadAll` 逐条把 `"Sounds/Item_N"`、`"Sounds/NPC_Hit_N"`、`"Sounds/Zombie_N"` 等交给 `Load`（:181-258）；`Load` 只是 `IAssetRepository.Request<SoundEffect>(name, AssetRequestMode.AsyncLoad)`（:358-361）。**资源以异步方式请求，真正的实例化放在下一步**。
4. 资源包自定义音效：`TrackableSounds[i] = Load("Sounds/Custom" + 分隔符 + SoundID.GetTrackableLegacySoundPath(i))`（:254-259）。`SoundID.CreateTrackable` 在注册时会向 `_trackableLegacySoundPathList` 追加文件名——单变体直接 `Add(name)`，多变体循环 `Add(name + "_" + i)`，不做任何大小写转换（SoundID.cs:1210-1229），所以索引与路径一一对应。
5. `Reload()` ⇒ `CreateAllSoundInstances()`（:169-171）：先 `Dispose` 全部旧实例并清空 `_trackedInstances`（:264-270），再**预创建每一种音效的 `SoundEffectInstance`**（:271-340）。
   - 这里是**单实例槽**模型的来源：数组长度就是"同时最多几个该音效变体"。
   - 反编译里能看到若干"借用"：`SoundInstancePixie = CreateInstance(SoundGrab)`（:273）、`SoundInstanceSplash[0] = CreateInstance(SoundRoar[0])`（:297）、`SoundInstanceDoubleJump = CreateInstance(SoundRoar[0])`（:299）、`SoundInstanceMoonlordCry = CreateInstance(SoundNpcKilled[10])`（:302）。即"同一份波形被多个逻辑槽复用"是原作者的刻意做法（音效美术上通用）。
6. `SoundEngine.Reload`（SoundEngine.cs:60-71）会同时让两个播放器重载；调用点有两处：`AssetSourceController` 在资源包列表变化后（Terraria.GameContent/AssetSourceController.cs:60-61），以及 `LegacyAudioSystem.ChangeAudioDevice`（LegacyAudioSystem.cs:390）。

### 3. 旧通道：`LegacySoundPlayer.PlaySound`

入口：`SoundEngine.PlaySound(int type, ...)` ⇒ `LegacySoundPlayer.PlaySound(type, x, y, Style, volumeScale, pitchOffset)`（SoundEngine.cs:102-110）。

1. **网络钳制**：`Main.dedServ` 直接返回 null（LegacySoundPlayer.cs:369-372）。注意 `SoundEngine` 层已拦一次（SoundEngine.cs:105）。
2. **总音量短路**：`Main.soundVolume == 0` 且 type 不在 30..35 时返回 null（:373-376）。
3. **3D 定位**（:377-402）：
   - `x == -1 || y == -1` ⇒ `flag = true`，视为**全局音**（不衰减、不声像）。
   - 否则在加载世界/联机服（`Main.netMode == 2`）时直接返回（:391-393）。
   - `vector = (x,y) - Main.Camera.Center`，`dist = vector.Length()`；若 `dist < 2500`：
     - `pan = clamp(vector.X / (Main.MaxWorldViewSize.X * 0.5), -1, 1)`（:396）——**只按水平偏移做声像**，垂直偏移只影响音量。
     - `volume = 1 - dist / 2500`（:397），即**线性衰减**，不是平方反比。
4. **每音效特化 switch(type)**：每个 case 做三件事——挑变体下标、若旧实例正在播则 `Stop`、用 `asset.Value.CreateInstance()` 新造实例并设置 `Volume/Pan/Pitch`。典型模板见下（`type == 0` 挖掘音，:443-457）：

   ```csharp
   case 0:
   {
       int num13 = Main.rand.Next(3);                 // 随机挑选变体
       if (SoundInstanceDig[num13] != null) SoundInstanceDig[num13].Stop();
       SoundInstanceDig[num13] = SoundDig[num13].Value.CreateInstance();
       SoundInstanceDig[num13].Volume = num2;          // 衰减后音量
       SoundInstanceDig[num13].Pan = num3;             // 水平声像
       SoundInstanceDig[num13].Pitch = (float)Main.rand.Next(-10, 11) * 0.01f;  // ±0.1 随机音高
       soundEffectInstance = SoundInstanceDig[num13];
       break;
   }
   ```
   （来源：LegacySoundPlayer.cs:443-457，为可读性略去多余缩进）
5. **常用分支的工程含义**：
   - `type == 2`（Item 音效，:520 起）：`num = Style` 当作 `SoundItem` 下标；先做一批按 item id 的专属音量修正（:521-553）；再根据 `num` 决定"是否允许打断自己"——`159` 播放中则**直接返回 null**（:555-563、585-591），其余默认 `Stop` 后重建（:586-597），而 9/10/24/26/34/43/103/156/162/205 则**不 Stop**（:598-611，仅让字段被覆盖，旧实例自然播完）。
   - `34/35`（液体/熔岩）：不是一次性音，而是**"若已在播则只更新音量/声像，否则新建"**（:1252-1295）——这是旧通道里唯一"持续音"的写法。
   - `34` 还乘了 `1 - Main.shimmerAlpha`（:1261），微光液体会压低水声。
   - `41`（月球领主咆哮）：音量用 `1 / (1 + 与本地玩家距离)` 而非统一衰减（:1377-1378）。
   - `42`：唯一走 `TrackableSounds` 的分支，直接 `CreateInstance` 并写进 `TrackableSoundInstances[num]`（:1383-1388）。`num` 即 `Style`（:365），而 `Style` 是 `LegacySoundStyle._style`（`LegacySoundStyle.cs:20-30`）——由 `new LegacySoundStyle(42, count, ...)` 传入的 `count`（SoundID.cs:1229）。所以这里的下标是**全局可追踪音效的起始序号**，不是从 0 起的局部下标；变体 >1 时 `Style` 取 `count..count+Variations-1`。
   - `65`（僵尸 115/116/117 组）：**三个都没在播才播**，否则返回 null（:1389-1414）。
6. **收尾**（:1417-1430）：统一 `Pitch = clamp(Pitch + pitchOffset, -1, 1)`、`Volume *= volumeScale`、`Play()`、`SoundInstanceGarbageCollector.Track(instance)`，再返回实例。
7. **整个函数被 `try/catch { }` 包住**（:365 处 try、:1417-1431 处 catch）。音频异常一律静默吞掉——玩家宁可少一个音也不该崩游戏。

### 4. 新通道：`SoundPlayer` + `SlotId` 追踪

入口：`SoundEngine.PlayTrackedSound / PlayTrackedLoopedSound`（SoundEngine.cs:131-154）。

1. `PlayTrackedSound` 先做**实例数上限**检查：`style.MaxTrackedInstances > 0 && GetActiveSoundCount(style) >= MaxTrackedInstances` 就放弃（SoundEngine.cs:136-139）。`GetActiveSoundCount` 遍历插槽、只计 `Style == style && IsPlaying` 的项（SoundPlayer.cs:110-124）。
2. `SoundPlayer.Play`（SoundPlayer.cs:10-24）：
   - `IsTrackable == false` 的 style 被拒（只有 SoundId 42 与 `CustomSoundStyle` 通过）。
   - **屏幕外剔除**：目标点与屏幕中心距离平方 > `1e8`（即 10000 像素，SoundPlayer.cs:14-18）直接不播。
   - 通过则在 `_trackedSounds`（`SlotVector<ActiveSound>`，初始容量 4096，SoundPlayer.cs:6）里新建 `ActiveSound` 并返回其 `SlotId`。
3. `ActiveSound` 构造 ⇒ `Play()`（ActiveSound.cs:78-89）：`Style.GetRandomSound().CreateInstance()`、加上 `Style.GetRandomPitch()`、写入 `DetermineIntendedVolume()`、`Play()`、交给 `SoundInstanceGarbageCollector.Track`，最后立刻 `Update()` 一次让首帧音量正确。
4. **每帧更新**：`SoundEngine.Update` ⇒ `SoundPlayer.Update()`（SoundEngine.cs:45-66，`SoundPlayer.Update()` 在 :64）。注意存在**两条并行**的每帧更新：一条是 `Main.UpdateAudio` 开头的 `SoundEngine.Update()`（Main.cs:11172），驱动新式追踪音与暂停边沿；另一条是同函数后段的 `audioSystem.Update()/UpdateMisc()`（Main.cs:11634-11635），推进音乐侧 `IAudioSystem`。二者不是同一条调用链，也不互相包含。它对每个 `ItemPair` 调 `ActiveSound.Update()`，不再播放就 `Remove(item.Id)`，并 `catch` 任何异常后同样移除（SoundPlayer.cs:97-109）。`ActiveSound.Update` 会先检查循环条件，再重算音量（ActiveSound.cs:135-149）。**注意：反编译里的 `foreach (SlotVector.ItemPair ... in (IEnumerable<...>)` 是编译器为 `SlotVector` 自定义枚举器生成的展开（显式接口转换就是语法糖残迹），脑内折叠成普通 foreach 即可。**

   写锁场景（调用方视角）：游戏逻辑不每帧"重新播放"，而是**持有 SlotId、每帧改 `ActiveSound.Position/Volume/Pitch`**：

   ```csharp
   ActiveSound activeSound = SoundEngine.GetActiveSound(SlotId.FromFloat(localAI[2]));
   if (activeSound == null && num12 != 0f) {
       localAI[2] = SoundEngine.PlayTrackedLoopedSound(SoundID.RCCar, base.Center,
           new ProjectileAudioTracker(this).IsActiveAndInGame).ToFloat();
       activeSound = SoundEngine.GetActiveSound(SlotId.FromFloat(localAI[2]));
   }
   if (activeSound != null) {
       activeSound.Volume = num12;
       activeSound.Position = base.Center;
   }
   ```
   （来源：Terraria/Projectile.cs:38935-38947，此即遥控车 `SoundID.RCCar` 的循环音驱动模式）
5. **3D 与混音在 `DetermineIntendedVolume` 里**（ActiveSound.cs:154-172）：
   - 非全局音：`pan = clamp((Position - Main.Camera.Center).X / (MaxWorldViewSize.X*0.5), -1, 1)`；`atten = clamp(1 - dist/2500, 0, 1)`——与旧通道同一公式、同一个常量。
   - 再乘 `Style.Volume * Volume`，然后按 `Style.Type` 乘对应的全局音量（Sound/Ambient/Music → `Main.soundVolume/ambientVolume/musicVolume`，:162-170）。
6. **循环音的终止条件**：`ActiveSound.LoopedPlayCondition`，由调用方构造小对象提供，例如 `ProjectileAudioTracker.IsActiveAndInGame`（ProjectileAudioTracker.cs:16-27，检查 `Main.gameMenu` 与目标投射物是否仍存活且类型一致）与 `VampireSizzleTracker.IsActiveAndInGame`（VampireSizzleTracker.cs:12-20）。**这是"句柄失配"防护**：投射物数组槽被新投射物复用时，旧声音会因类型不一致而被停掉。
7. `SoundPlayOverrides`（SoundPlayOverrides.cs）目前只有一个 `float? Volume` 字段，`ActiveSound.UseOverrides` 在构造时把它合并进实例音量（ActiveSound.cs:42-48）。用法见 Player.cs:28807-28815。

### 5. FNA 场景下的实例回收

`SoundInstanceGarbageCollector`（SoundInstanceGarbageCollector.cs:6-35）只维护一个 `List<SoundEffectInstance>`，且 `Track` 只在 `Program.IsFna` 时登记（:11-17）。每帧 `SoundEngine.Update` 调 `Update()`，把空引用或 `State == Stopped` 的实例 `Dispose` 掉并从表里删除（:20-33）。原因：FNA 的 `SoundEffectInstance` 持有非托管缓冲区，不显式 Dispose 会泄漏；XNA 路径下则由 GC 兜底，故不需要登记。

### 6. 音乐：cue 加载

1. `Main.LoadMusic_InSteps()`（Main.cs:11030-11042）是一个协程：先 `PrepareWaveBank()` 反复 `Engine.Update()` 直到 `WaveBank.IsPrepared`（LegacyAudioSystem.cs:154-161），然后 `for i in 1..maxMusic` `LoadCue(i, "Music_" + i)`（`maxMusic = 105`，Main.cs:461），最后 `LoadFromSources()`。
2. `LegacyAudioSystem.Init`：`AudioEngine("Content\\TerrariaMusic.xgs", 250ms 更新周期, renderer)`，加载 `Content\\Sound Bank.xsb` 与 `Content\\Wave Bank.xwb`（分 512 个 512 字节流块的 WaveBank），并分配 `AudioTracks[maxMusic]`、`TrackLoopCounts`、`PlayCallbacks`（LegacyAudioSystem.cs:139-152）。
3. `LoadCue` 为每个曲目建一个 `CueAudioTrack`，同时记入 `TrackNamesByIndex`、`DefaultTrackByIndex` 和 `AudioTracks[i]`（:163-169）。
4. `LoadFromSources`（:34-61）：对每个有名字的曲目，从**资源包内容源**里找 `Music/<名字>` 的替换轨；有替换且不等于当前轨时先 `Stop(Immediate)`，若当前轨不是默认轨再 `Dispose`，然后替换。`FindReplacementTrack` 按扩展名分派 `.ogg/.wav/.mp3` 到三种音轨实现（:84-124），单条失败只通过 `Main.IssueReporter` 报错，不打断其余曲目。
5. 资源包变化：`AssetSourceController` 重设内容源时调用 `Main.audioSystem.UseSources(list2)` 并 `SoundEngine.Reload()`（Terraria.GameContent/AssetSourceController.cs:58-61），于是音效与音乐同时重建。

### 7. 音乐：每帧驱动（`Main.UpdateAudio`）

`UpdateAudio()`（Main.cs:11164 起）先调 `SoundEngine.Update()`（:11172，内部再驱 `SoundPlayer.Update()`），随后：

1. **音乐系统自身的每帧步进**：`audioSystem.Update()` 与 `audioSystem.UpdateMisc()`（:11634-11635）——这两行在 `curMusic` 赋值**之前**，推进的是 `IAudioSystem` 内部状态，不是 `SoundPlayer`。
2. `curMusic = newMusic`（:11636）——本帧选中的曲目号由前面一大段场景判定（`newMusic`）得出。
3. **月球领主倒计时压制**：`num`（音乐乘数，初始 1，:11637）来自 `MoonLordCountdown / MaxMoonLordCountdown` 的平方；倒计时低于 20% 时把 `curMusic` 强制为 0（:11638-11655）。
4. **静音令牌计数**：`_musicSilencerCounter` 在 `flag2` 为真时 +1 否则 -1，夹在 `[0,240]`；比例为 `(counter/240)^2`，从乘数里扣掉，到达 1 时 `curMusic = 0`（:11656-11668）。
4. **逐轨更新**：`isMainTrackAudible = musicFade[curMusic] > 0.25f`（:11669），然后 `for i in 1..maxMusic`：
   - 目标音量 `num4 = musicFade[i] * musicVolume * num`（:11672），62..88 号乘 0.9，52 号乘 1.15 并封顶 1（:11673-11683）。
   - **28 号（雨）与 45 号（风）是环境音**：雨用 `atmo^4`、云量、微光 alpha 算强度（:11697-11711）；风用 `|windSpeedCurrent|*0.7+0.3` 再乘 `atmo^4`（:11714-11739）。满足条件时 `UpdateAmbientCueState`，否则 `UpdateAmbientCueTowardStopping`。
   - 其余曲目：`i == curMusic` ⇒ `UpdateCommonTrack(allowMusic, i, num4, ref musicFade[i])`；否则 `UpdateCommonTrackTowardStopping(...)`（:11741-11751）。
5. 最后 `audioSystem.UpdateAudioEngine()`（:11754），并维护 `musicError`：连续 100 次异常就显示"Music Disabled"并把 `musicVolume = 0`（:11755-11777）。

### 8. 音乐：淡入淡出语义

`musicFade[]` 是**每条轨独立的 0..1 淡入淡出系数**，由 `LegacyAudioSystem` 的四个方法推进，步长固定 `0.005/帧`（约 3.3 秒从 0 到 1，按 60FPS 计）：

| 方法 | 行为 | 位置 |
|---|---|---|
| `UpdateCommonTrack(active, i, totalVolume, ref tempFade)` | `tempFade += 0.005`；未在播且 `active` 则 `Reuse()` → 设 `Volume` → `Play()` → 触发 PlayCallback、`TrackLoopCounts[i]++`；否则只 `SetVariable("Volume", totalVolume)` | LegacyAudioSystem.cs:295-321 |
| `UpdateCommonTrackTowardStopping(...)` | 在主轨可听（`isMainTrackAudible`）时 `tempFade -= 0.005`；`Main.curMusic == 0` 时直接归零；归零即 `Volume=0` + `Stop(Immediate)` + 重置循环计数 | :323-355 |
| `UpdateAmbientCueState(i, gameIsActive, ref trackVolume, systemVolume)` | 系统音量为 0 主动 Stop；未在播则 `Reuse()+Play()`；暂停中且窗口活动则 `Resume()`；否则 `trackVolume += 0.005` 并写 `Volume` | :219-251 |
| `UpdateAmbientCueTowardStopping(i, stoppingSpeed, ref trackVolume, systemVolume)` | 按传入速度下降，到 0 `Stop(Immediate)` | :253-280 |

要点：**"切歌"并不是显式指令，而是"改 `curMusic` 后两套方法的此消彼长"**——旧轨因不再等于 `curMusic` 走 TowardStopping 淡出，新轨走 CommonTrack 淡入，天然获得交叉淡化。无交叉淡化的特例由 `Main.musicNoCrossFade` 标记：命中时直接把 `musicFade[newMusic]` 置 1（Main.cs:12679-12684），例如 51 号在主菜单前曲 50 播过时被置为 true（:12368-12371）。

`CueAudioTrack.Reuse` 的实现是"先 Stop 旧 cue 再 `SoundBank.GetCue` 取新 cue"（CueAudioTrack.cs:47-54）——XACT 的 cue 是一次性对象，不能重播，只能重取。

### 9. 资源包音乐：OGG 流式解码

`OGGAudioTrack`（OGGAudioTrack.cs:8-27）基于 NVorbis 的 `VorbisReader` 解码，写入 `DynamicSoundEffectInstance`。循环点由 `FindLoops()` 从 Vorbis 注释里找出（:14-18），`PrepareBufferToSubmit` 在越过循环终点或读不满一整块时把读取位置重置到 `_loopStart` 再补齐剩余样本（:33-45），把 float 样本转 16 位小端字节（:47-55）。基类 `ASoundEffectBasedAudioTrack.Update` 在`待提交缓冲区少于 8 块`时每帧补 2 块（ASoundEffectBasedAudioTrack.cs:45-53、60-66）——**这是"生产者-消费者式"的流式音乐管线**，与传统 cue 的"交给 XACT 自行循环"完全不同。

### 10. 暂停 / 失焦

1. `SoundEngine.Update` 读 `FocusHelper.PauseSounds`，状态翻转时 `SoundPlayer.PauseAll()/ResumeAll()`（SoundEngine.cs:54-63）。
2. `FocusHelper.PauseSounds` 仅在"游戏未激活且单机"时返回 true（Terraria/FocusHelper.cs:98-107）；`AllowMusic` 在窗口失焦时取决于 `AllowAudioUnfocused` 设置（:86-96），`QuietAmbientSounds` 即"非当前选中窗口"（:110）。
3. `allowMusic == false` 时 `Main.UpdateAudio` 会 `audioSystem.PauseAll()` 与 `SoundEngine.StopAmbientSounds()`（Main.cs:11184-11189）。后者只停 `SoundInstanceLiquid[0..1]`（LegacySoundPlayer.cs:1436-1445）——旧通道的"环境音"实际上就是液体声。
4. `LegacyAudioSystem.PauseAll/ResumeAll` 只处理 `musicFade[i] > 0` 的轨，且用 `try/catch` 忽略单轨失败（LegacyAudioSystem.cs:175-217）。

## 设计要点与取舍

1. **两代音效 API 并存，边界由 `SoundId == 42` 划定**。旧 API 用 `int type` + 巨型 switch，调用方零分配、天然缓存实例；新 API 用 `SoundStyle` + `SlotId`，能每帧调参、能设条件终止、能限流。不能追踪的音效被迫继续走旧路径——所以 `SoundID` 里"普通音效"是 `new LegacySoundStyle(3, 1)`（SoundID.cs:162），"可追踪"的才用 `CreateTrackable`（SoundID.cs:1062 的 `RCCar`）。这是典型的**渐进式重构**，代价是两套 3D/音量公式要各自维护。
2. **固定大小的实例槽 vs 每次 `CreateInstance`**。`CreateAllSoundInstances` 预建是为了**首次播放零延迟**，但 `PlaySound` 分支里仍大量出现 `xxx.Value.CreateInstance()`（例：:443-446）——预建实例被当"占位"随后被覆盖，旧实例仅 `Stop` 不 `Dispose`。这意味着同一音效频率极高时会持续分配新 `SoundEffectInstance`，靠 FNA 的 GC 列表回收（SoundInstanceGarbageCollector.cs:11-17）。
3. **3D 只用水平声像 + 线性距离衰减**。两个通道都是 `pan = Δx / 半个视野宽`、`gain = 1 - dist/2500`（LegacySoundPlayer.cs:396-399、ActiveSound.cs:156-157）。不做多声道输出分配，靠立体声 pan 近似定位；线性衰减比物理正确的反平方衰减"更远仍可闻"，适合像素游戏"远处也要能听到"的需求。
4. **"距离 > 10000 直接不播"（SoundPlayer.cs:14-18）与 "距离 ≥ 2500 音量置 0 但可能在播"（LegacySoundPlayer.cs:393）并存**：新通道省实例，旧通道省计算；旧通道在 2500 之外仍会 `CreateInstance` 但 `num2 <= 0` 时会返回 null（:436-439），所以实际也不播。该短路条件是 `num2 <= 0f && (type < 30 || type > 35) && type != 39`，即 30-35（液体/熔岩等）与 39 不在其列，静音时仍照常走 switch。
5. **循环音由调用方持有句柄，引擎不主动回收**。`ActiveSound.Update` 只在 `Condition` 失败时 `Stop(immediate:true)`（ActiveSound.cs:138-143），随后 `SoundPlayer.Update` 因 `IsPlaying == false` 移除槽位（SoundPlayer.cs:102-105）。调用方只需要"拿到句柄 → 每帧改字段"。若调用方没给条件（`PlayLooped` 传 `null`），`Condition != null` 判断不成立，该声音会**一直循环在播**，直到被 `StopAll`/`Reload` 或实例被外部停掉才释放并移除槽位——这不是靠 `IsPlaying` 判死（循环音不会自行结束），而是无终止条件；即便如此也不会泄漏，只是长期占槽，这正是 `MaxTrackedInstances` 限流存在的原因。
6. **音量三轨分离**：`SoundStyle.Type` 决定最终乘哪一个全局音量（ActiveSound.cs:162-171）；旧通道则用 `DoesSoundScaleWithAmbientVolume` 的白名单（LegacySoundPlayer.cs:1447-1470，包含 30-35、39、43-46、67-69）来区分"这是环境音"应乘 `ambientVolume` 还是 `soundVolume`。两份白名单机制不同步是历史包袱。
7. **异常全吞**。`PlaySound` 的 `try/catch { }`（LegacySoundPlayer.cs:366 处 try、1424-1428 处 catch）、`SoundPlayer.Update` 的 `catch`（SoundPlayer.cs:106-109）、`LegacyAudioSystem.PauseAll` 的 `catch`（LegacyAudioSystem.cs:190-193）、`SceneState` 的 `_disabledBlizzardSound` 自锁（Terraria/SceneState.cs:211-214、275-278）——音频属于"失败可接受"的子系统，宁可静音也不崩。
8. **降级链完整**：无硬件 → `DisabledAudioSystem`（静默空实现）；音乐连续异常 → `musicVolume = 0`（Main.cs:11758-11768、11772-11778）；加载音乐异常 → 音效音量也归零（Main.cs:10988-10993）；暴风雪音效异常 → 永久关闭该音（SceneState.cs:275-278）。
9. **资源包覆盖音乐的方式是"替换 IAudioTrack 对象"，而不是替换 XACT 包**。内置包只提供 cue，替换音轨完全在托管侧解码（LegacyAudioSystem.cs:84-124），所以资源包能做无缝循环的 OGG，而内置曲目依赖 XACT 的 loop 定义。

### 未验证 / 需注意

- **`MusicCueHolder` 在 1.4.5.8 源码树中未被引用**（`grep MusicCueHolder` 仅命中定义文件本身）。它看起来是旧版 `LegacyAudioSystem` 中"用 `SoundBank.GetCue` 直接管理音乐"的那一版实现被 `CueAudioTrack` 取代后的残留；但"是残留"这一判断只基于当前树无引用，**未验证其是否被其他程序集（如 ReLogic）反射使用**。
- **`SlotId` 与 `SlotVector` 的定义不在本仓库**（属于 ReLogic 库），本文仅根据用法描述其"失效句柄返回 null"的外部行为（`SoundPlayer.GetActiveSound` 对 `!Has(id)` 返回 null，SoundPlayer.cs:54-60）；其内部编码、是否线程安全均未验证。
- **`Main.UpdateAudio` 全貌未逐行读完**（该函数逾 600 行，含大量场景判定）。本文只覆盖了与音频系统直接相关的部分（:11634-11779、:12358-12371、:12660-12690、:12990-13012），曲目"该播哪首"的场景选择逻辑请另见光照/场景文档。
- **`UpdateAudio` 开头`bool allowMusic = FocusHelper.AllowMusic;`（Main.cs:11184）到 `_musicLoaded` 守卫（:11168）之间**还有数据包/服务器守卫，本文未逐条列出。
