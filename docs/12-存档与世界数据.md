# 存档与世界数据：指针分段的世界文件、加密的角色文件与块压缩地图

> 适用范围：Terraria v1.4.5.8 反编译源码。路径均相对 `decompiled/Terraria/`。
> 阅读提示：反编译出的 `b/b2/b3/b4` 是世界文件瓦片段的四级头字节，`_temp*` 是"存档时刻的世界状态快照"，`num/num2` 多为计数或偏移；`using`、内联 `delegate`、switch 表达式均可脑内折叠回 try/finally、回调、经典 switch。

## 一句话结论

世界存档是一个**指针表 + 11 个定长顺序段**的单一二进制：写时顺序写出各段并记录每段结束偏移，最后回退到文件头回填；读时逐段读取并**要求流位置恰好落在下一段指针上**，否则整档判损坏。角色 `.plr` 是同一版本号体系下的一次性顺序序列化，外面套了一层固定密钥的 Rijndael 加密；地图 `.map` 是第三个独立文件，裸 Deflate + 自研游程编码。三者共用 `FileMetadata` 20 字节魔数头与同一个"当前版本 326"的门闸。

## 关键数据结构

### 文件元数据（三类存档共用）
- 20 字节：8 字节魔数（低 56 位即 ASCII "Relogic"，高 8 位是文件类型）、4 字节 `Revision`、8 字节位标志（bit0 为"收藏"）（Terraria.IO/FileMetadata.cs:9-18）。
- 写时 `Revision++` 再写，读时低 56 位不符直接抛 `FormatException`，类型不符也抛（Terraria.IO/FileMetadata.cs:27-31、Terraria.IO/FileMetadata.cs:41-67）。
- 世界进入格式头（Terraria.IO/WorldFile.cs:1183），角色（Terraria/Player.cs:55398）与地图（Terraria.Map/MapHelper.cs:3070）都紧跟版本号。

### 世界文件：11 段指针表
- 段数写死 11：格式头、世界头、瓦片、箱子、告示牌、NPC、瓦片实体、压力板、城镇管理、图鉴、创造能力（Terraria.IO/WorldFile.cs:1160-1175）。
- 格式头先占位 11 个 0，末了由 `SaveHeaderPointers` 倒回文件头改写（Terraria.IO/WorldFile.cs:1184-1188、Terraria.IO/WorldFile.cs:1216-1227）。
- 帧重要位图：按 `Main.tileFrameImportant[type]` 每 8 个类型压成 1 字节（Terraria.IO/WorldFile.cs:1189-1199），读回时同一份位图决定每格是否携带帧坐标（Terraria.IO/WorldFile.cs:1938-1955）。
- 世界标志段是整份文件最长的元数据块，从 GameMode 写到各种秘密种子、Boss 击杀记录、天气、背景样式，末尾嵌 `WorldGen.Manifest.Serialize()`（Terraria.IO/WorldFile.cs:1246-1439）。

### 快照字段
`_tempTime/_tempDayTime/_tempRaining/_tempSandstorm*/_tempParty*/…`（Terraria.IO/WorldFile.cs:98-146）。`SetTempToOngoing`（Terraria.IO/WorldFile.cs:1047）是"运行时 → 快照"，`SetOngoingToTemps`（Terraria.IO/WorldFile.cs:152）是反向，`ResetTempsToDayTime`（Terraria.IO/WorldFile.cs:1013）把快照拨到白天 13500。

### 角色与地图的模型
- `PlayerFileData : FileData`：持有 `Player` 与一个 `Stopwatch` 统计游玩时长（Terraria.IO/PlayerFileData.cs:11-13）。
- `WorldFileData`：世界的元数据视图，`MapFileName` 在新世界用 `UniqueId`，老世界退回 `WorldId`（Terraria.IO/WorldFileData.cs:106-117）。

## 执行流程

### 1. 世界列表的元数据快读
`GetAllMetadata`（Terraria.IO/WorldFile.cs:186）先读版本号：>326 立刻返回 LaterVersion；≥135 才校验并读元数据；≥88 直接按指针 Seek 到世界头，跳过瓦片；≥179 读种子与生成器版本，==179 的种子是 int 需转字符串；≥181 读 UUID（Terraria.IO/WorldFile.cs:198-240）。因此打开世界列表从不解析瓦片。

### 2. 进入世界：LoadWorld
`WorldFile.LoadWorld()`（Terraria.IO/WorldFile.cs:648）：
1. 云存档不可用时置 `WorldGen.loadFailed` 返回（Terraria.IO/WorldFile.cs:654-666）。
2. 文件不存在且 `Main.autoGen` 时，先建元数据、按种子生成、立刻 `SaveNewWorld`（Terraria.IO/WorldFile.cs:667-702）。
3. 整档 `ReadAllBytes` 进 `MemoryStream` 再解析（Terraria.IO/WorldFile.cs:706-708）。
4. 版本分派：≤0 未知错误；>326 版本过新；>87 走 v2；否则走 Release 88 之前的老格式（Terraria.IO/WorldFile.cs:719）。
5. 成功后再做三件事：补算矿层、迁移旧瓦片实体、清掉残留的临时方块（Terraria.IO/WorldFile.cs:737-739）。
6. 用 `Liquid.QuickWater(2)` 与最多 10 万次 `Liquid.UpdateLiquid()` 把液体重新静置，进度条走 50%~100%；随后重置云、刷新萤火虫概率、扫描空岛、按 WorldId 选世界特有怪物（Terraria.IO/WorldFile.cs:740-778）。
7. 全程异常写入 `LastThrownLoadException` 并置 `loadFailed`（Terraria.IO/WorldFile.cs:780-788）。

### 3. 分段读取 LoadWorld_Version2
`LoadWorld_Version2`（Terraria.IO/WorldFile.cs:1769）：
1. `LoadFileFormatHeader` 取版本号、元数据、指针数组、位图（Terraria.IO/WorldFile.cs:1911-1959）。
2. 依 `LoadHeader → LoadWorldTiles → LoadChests → LoadSigns → LoadNPCs` 顺序读，每段结束都断言位置等于 `positions[i]`，不等即 `BadSectionPointer`（Terraria.IO/WorldFile.cs:1776-1808）。这是整份格式的自校验核心：任何字段读多读少都会在下一个边界暴露。
3. 第 6 段分版本：116~121 是旧"假人"数据只读丢弃（Terraria.IO/WorldFile.cs:2889-2897），≥122 才是瓦片实体（Terraria.IO/WorldFile.cs:1824）。
4. 第 7~10 段自 170/189/210/220 引入；<210 用 `FillBasedOnVersionBefore210` 从击杀记录反推图鉴（Terraria.IO/WorldFile.cs:1824-1858、Terraria.IO/WorldFile.cs:3424）。
5. 收尾 `LoadWorld_LastMinuteFixes()` 再 `LoadFooter()`（Terraria.IO/WorldFile.cs:1860-1861）。
6. `LoadFooter` 只验三项：布尔为真、世界名一致、WorldId 一致（Terraria.IO/WorldFile.cs:3005-3020）。

### 4. 世界头与标志位
- `LoadHeader`：名字 → 种子 → 生成器版本 → UUID（<181 新生成）→ 世界 ID → 边界 → 尺寸 → `WorldGen.clearWorld()` → `LoadWorldFlags`（Terraria.IO/WorldFile.cs:1961-1989）。写侧尺寸是**先 Y 后 X**（Terraria.IO/WorldFile.cs:1236-1237）。
- `LoadWorldFlags` 最典型的迁移：209 起 GameMode 是 int；112~208 是 bool；**只有 208 版**额外读一位才能识别大师模式（Terraria.IO/WorldFile.cs:1992-2050）。
- 派生值：<267 没有 Zenith 标志，用 `remixWorld && drunkWorld` 推算；267 起显式存储（Terraria.IO/WorldFile.cs:2020-2034 区段）。

### 5. 瓦片段：四级头 + 自研游程
`SaveWorldTiles`（Terraria.IO/WorldFile.cs:1440）：
- 逐列写（x 外层、y 内层），进度条按列推进（Terraria.IO/WorldFile.cs:1443-1446）。
- 每格复用 16 字节小缓冲，从尾部向前塞扩展头，只有非 0 才写；最终把"首个非 0 头字节 → 负载末尾"的连续区间一次写出（Terraria.IO/WorldFile.cs:1564-1582、Terraria.IO/WorldFile.cs:1612）。
- 头字节语义：主掩码管"有无方块/墙/液体种类/取色字节/压缩长度"；第二掩码管线、斜坡、促动器、漆色、墙高字节、微光；第三掩码管隐形与全亮（Terraria.IO/WorldFile.cs:1455-1610）。半砖/斜坡占据第二掩码高 3 位，0 为无、16 为半砖、其余为斜坡号加 1 后左移 4（Terraria.IO/WorldFile.cs:1528）。
- **内联游程**：同列向下且 `isTheSameAs`、类型在 `TileID.Sets.AllowsSaveCompressionBatching` 白名单内才累加（Terraria.IO/WorldFile.cs:1583-1592），≤255 用 1 字节否则 2 字节（Terraria.IO/WorldFile.cs:1593-1601）。

`LoadWorldTiles`（Terraria.IO/WorldFile.cs:2528）是严格逆运算：
- 主掩码最低位为 1 才读第二掩码，第二掩码最低位为 1 才读第三掩码，第三掩码同位置位再引出第四掩码（Terraria.IO/WorldFile.cs:2540-2557）。这就是"扩展头逐级存在"。
- 类型：主掩码 0x20 表示读 2 字节小端（type ≥256）（Terraria.IO/WorldFile.cs:2562-2572）；只有位图标记为重要才读帧坐标（Terraria.IO/WorldFile.cs:2573-2581），否则置 -1 由运行时按邻居重算。
- 液体：主掩码高 2 位非 0 即有液体并读液位；第三掩码 0x80 优先判微光，否则 2=岩浆、3=蜂蜜（Terraria.IO/WorldFile.cs:2592-2621）。顺序不能反，否则微光会被读成蜂蜜。
- 斜坡/半砖只在 `SaveSlopes` 允许的方块上生效（Terraria.IO/WorldFile.cs:2626-2650 区段）。
- 压缩计数按主掩码高 2 位三态：0 格 / 1 字节 / 2 字节（Terraria.IO/WorldFile.cs:2694-2699），然后循环把同一块逐格 `CopyFrom` 复制下去（Terraria.IO/WorldFile.cs:2722-2728）。
- 顺带统计 `WorldGen.tileCounts[type]`，地表以上权重 ×5，供世界统计与矿层推断（Terraria.IO/WorldFile.cs:2700-2719）。

### 6. 箱子 / 告示牌 / NPC
- `SaveChests` 写前**先清洗**：坐标越界或脚下不是容器方块就 `Chest.RemoveChest`（Terraria.IO/WorldFile.cs:1619-1650）。
- `LoadChests`：294 起每箱自带 `maxItems`（适配不同尺寸），旧版读一个全局槽数；超出结构容量的槽位只读后丢弃（Terraria.IO/WorldFile.cs:2737-2790）。读完按坐标去重，8000 以外的残留箱子清空（Terraria.IO/WorldFile.cs:2791-2819）。
- `SaveNPCs` 两段：城镇 NPC（名字、坐标、家、是否无家）和可持久化世界 NPC，各以 `false` 收尾（Terraria.IO/WorldFile.cs:1712-1760）。`LoadNPCs` 先读微光化城镇 NPC 的 type 列表，再按尾哨循环填回 `Main.npc`（Terraria.IO/WorldFile.cs:2899-2930）。
- <251 没有"已解锁商店"位，加载后用 `NPC.AnyNPCs(type)` 反推（Terraria.IO/WorldFile.cs:2935-2944 区段）。

### 7. 加载后修补
- `LoadWorld_LastMinuteFixes`：<258 把"发光涂料"（色调 31）迁成独立全亮标志（Terraria.IO/WorldFile.cs:1864-1871、Terraria.IO/WorldFile.cs:2822-2841）。
- `FixAgainstExploits`：修箱子与瓦片实体的非法数据，并**复核每个城镇 NPC 的房间**，失效时先尝试换房、再不行就置为无家可归（Terraria.IO/WorldFile.cs:1873-1909）。既是反外挂，也是坏档自愈。

### 8. 保存：快照 → 内存成档 → 写盘 → 回读校验 → 备份/回滚
`SaveWorld`（Terraria.IO/WorldFile.cs:864）→ `_SaveWorld`（Terraria.IO/WorldFile.cs:877）：
1. 等世界转换结束，状态栏提示（Terraria.IO/WorldFile.cs:886-890）。
2. `Monitor.TryEnter(IOLock)` 成功即存；拿不到锁且 `canBeSkipped` 为假就阻塞等待，为真则直接放弃（Terraria.IO/WorldFile.cs:891-911）。于是自动存档可被手动存档压掉，手动存档必等。
3. `InternalSaveWorld`（Terraria.IO/WorldFile.cs:915）：非 `useTemps` 先拍快照，`resetTime` 再把时间拨到白天（Terraria.IO/WorldFile.cs:1013-1046）。
4. 7MB 预分配 `MemoryStream` 拼出完整文件（Terraria.IO/WorldFile.cs:933）；写前先留存旧字节，写完**立刻读回**调用 `ValidateWorld`（Terraria.IO/WorldFile.cs:944-953）。
5. 校验通过：旧字节写入 `.bak` 并滚动备份；失败：旧字节原样写回（等价回滚）（Terraria.IO/WorldFile.cs:953-970）。
6. `DoRollingBackups`：`WorldRollbacksToKeep` 默认 2、上限 9，按 `.bak → .bak2 → …` 挪号（Terraria/Main.cs:1184、Terraria.IO/WorldFile.cs:973-1011）。

`ValidateWorld`（Terraria.IO/WorldFile.cs:3022）不把世界装进 `Main`，而是**用同一份指针表做只读偏移扫描**：瓦片逐格跳过、箱子/告示牌/NPC 按计数跳过，每段比对 `positions[i]`（Terraria.IO/WorldFile.cs:3164-3183）；最后读 Footer 要求布尔为真且名字或世界 ID 至少一个匹配（Terraria.IO/WorldFile.cs:3226-3234）。异常写 `client-crashlog.txt` 后返回 false（Terraria.IO/WorldFile.cs:3236-3245）。

### 9. 世界数据版本迁移
- **入口分派**：>87 走 v2，否则走 v1 老格式（Terraria.IO/WorldFile.cs:719）。v1 很多字段可选，例如 <63 没有月相就直接 `RandomizeMoonState` 随机（Terraria.IO/WorldFile.cs:3440-3475）。
- **只增不改**：迁移全部写成 `if (version >= N)` 才多读一段，旧字段语义不变；例如 Δ135 才有元数据，否则 `FromCurrentSettings` 伪造一份（Terraria.IO/WorldFile.cs:1915-1931）。
- **补丁式换算**：<115 的衣柜按箱子存储，加载后 `FixDresserChests` 搬位置；<105 需 `WorldGen.FixHearts`；<294 箱容全局统一（Terraria.IO/WorldFile.cs:2737、Terraria.IO/WorldFile.cs:2819）。
- **写永远 326**：`SaveFileFormatHeader` 直接写死 326（Terraria.IO/WorldFile.cs:1182），所以**打开旧世界再保存一次就是不可逆升级**。

### 10. 角色：AES 加密的顺序序列化
- 保存：`Player.SavePlayer`（Terraria/Player.cs:55332）→ `InternalSavePlayer`：先存成就、存地图；`Main.ServerSideCharacter` 为真时**跳过角色文件**（服务器托管）（Terraria/Player.cs:55355-55374）。
- 写前把旧文件复制成 `.bak`，再用 `RijndaelManaged` 加同一份硬编码 8 字节充当 Key/IV 的 `CryptoStream` 包住 `BinaryWriter`（Terraria/Player.cs:779、Terraria/Player.cs:55389-55398）。版本号 326 是**加密后**写在最前面的，必须解密才能读到。
- 读取：`LoadPlayer` 设 `PaddingMode.None` 整文件解密（Terraria/Player.cs:55718-55738）。写端 `FlushFinalBlock` 会补 PKCS7 填充，读端关掉填充才不会污染尾部，这是必须脑补的写读不对称。版本 >326 只读出名字并标记 `LaterVersion`（Terraria/Player.cs:55748-55754）。
- 写端 `Serialize`（Terraria/Player.cs:55409）没有任何行内版本判断，恒定按当前布局顺序输出；版本兼容全靠读端 `Deserialize` 逐字段 `if (release >= N)` 分支（如 Terraria/Player.cs:56347），所以"按 release 逐字段分支"只对读端成立。读端还**对越界值钳制**：生命上限 >500 钳到 500、魔力上限 >200、当前魔力 >400（Terraria/Player.cs:55882-55892），发型 ≥228 归 0，皮肤 7 在 <161 迁到 9。任何异常都吞掉，返回一个只保留名字的空角色。
- 存档写入 `DateTime.UtcNow.ToBinary()` 作为"最后保存时刻"（Terraria/Player.cs:55568），Δ202 起才存在（Terraria/Player.cs:56346-56350），老档用文件 mtime 兜底（Terraria/Player.cs:55756-55759）；重进世界时用它**扣除离线期间的死亡等待**（最多折算 1000 秒）（Terraria/Player.cs:56426-56432）。
- `LoadPlayer_LastMinuteFixes` 按当前装备**重算派生属性**（熔岩上限、翅膀、免摔、爬山虎等）再 `FixLoadedData()`（Terraria/Player.cs:56490-56522）：大量战斗属性不入档，只存真正持久的字段。
- 坏档兜底：`GetFileData` 若状态不是 Ok/LaterVersion，就用 `.bak` 覆盖原文件再读一次（Terraria/Player.cs:56524-56548）。

### 11. 地图存档
- 路径：玩家文件同目录（去掉 `.plr`）下 `<MapFileName>.map`，新世界用 UUID、老世界退回 WorldId，读取时还兼容旧命名（Terraria.Map/MapHelper.cs:3048-3055、Terraria.Map/WorldMap.cs:234-249）。
- 保存：`WorldMap.Save`（Terraria.Map/WorldMap.cs:251）→ `MapHelper.SaveMap`（Terraria.Map/MapHelper.cs:3020）；`TryEnter` 失败直接放弃（地图重要性低，丢一帧无妨）（Terraria.Map/MapHelper.cs:3022-3025）。
- 写侧（Terraria.Map/MapHelper.cs:3043-3340）：326 + 元数据 → 世界名/ID/尺寸 → 方块与墙的"配色选项计数表" → 整图行优先游程 → `DeflateStream` 边写边压缩，4KB 冲刷一次（Terraria.Map/MapHelper.cs:3064、Terraria.Map/MapHelper.cs:3327-3339）。`(CompressionMode)0` 是反编译失真，等价 `Compress`；输出是**裸 deflate**，没有 zlib 头。
- 单格：类型按 tile/wall/liquid/sky/dirt/rock/hell 分段成基址+偏移；位掩码决定是否带颜色、是否带亮度、游程长度几字节；亮度 ≤18 视为未探索，只写游程（Terraria.Map/MapHelper.cs:3145-3350 区段、Terraria.Map/MapHelper.cs:3166-3178）。
- 读取：首 4 字节最高位 0x8000 是"块压缩格式"标记，剥掉才得真实版本。随后先看该标记分派：**块压缩（flag 为真）一律走 `LoadMapVersionCompressed`，与版本号无关**；只有非块压缩的旧格式才按版本号分，>91 走 `LoadMapVersion2`、≤91 走 `LoadMapVersion1`（Terraria.Map/WorldMap.cs:194-212）。
- 块压缩读回（Terraria.Map/MapHelper.cs:3371 起）：重建类型映射后按 64×64 分块循环，每块先读 4 字节压缩长度，0 表示整块空（写默认 `MapTile` 即未探索）；非 0 则读入并在 `fixed` 指针下直接当 `MapTile` 数组用（Terraria.Map/MapHelper.cs:3548-3608、Terraria.Map/MapHelper.cs:3569-3595）。
- 世界 ID 或宽高不匹配直接抛异常，被 `WorldMap.Load` 捕获后拷成 `.bad` 并清空内存地图（Terraria.Map/MapHelper.cs:3386-3389、Terraria.Map/WorldMap.cs:218-231）。加载成功后 `ClearEdges` 清掉四周 40 格黑边，与 `UnlockMapSection` 的 40 格夹取同源（Terraria.Map/WorldMap.cs:211、Terraria.Map/WorldMap.cs:15）。

### 12. 保存的触发点
- 退出：`WorldGen.SaveAndQuit` 在主线程先拍快照，再把"存玩家 → 存世界"交给线程池（Terraria/WorldGen.cs:6644-6662、Terraria/WorldGen.cs:6607-6630）。
- 改名：`RenameWorldCallBack` 先 `LoadWorld()`、改 `Main.worldName` 再 `SaveWorld(useTemps: true)`——**用"读-改-写"实现改名**，会触发一次完整世界重写（Terraria/WorldGen.cs:6670-6695）。
- 补充：`WorldGen.cs` 中没有"世界转换（腐化/猩红替换）时反复 Load/Save"的回调；腐化/猩红转换走 `Convert` 的循环，不在 WorldGen 的改名/退出回调里。WorldGen 内只有三处保存：6618 退出保存、6689 改名保存、6797 `saveAndPlay`。

## 设计要点与取舍

1. **用"写顺序 + 回填指针"取代长度前缀**：每段长度隐式等于相邻指针之差。代价是必须先整档在内存里拼完（7MB 预分配），收益是读端能用位置比对做交叉校验，把字段错位与半截写入统一归为 `BadSectionPointer`。
2. **写-读-校验-回滚闭环**：保存后立刻回读校验，失败就写回旧字节；配合 `.bak` 与最多 9 份滚动备份，坏档损失被限制在一次会话内。
3. **位打包到极致**：一格最坏十余字节、最好 1 字节，对大世界的两千万格是数量级差异；压缩长度还按 1/2 字节自适应，但只对 `AllowsSaveCompressionBatching` 白名单方块开放，写端白名单与读端帧重要位图必须同源生成，否则读写不对称。
4. **全局静态量即存档模型**：世界标志段直接读写 `Main`/`NPC`/`WorldGen` 的静态字段，序列化代码极短，代价是无法同时持有多个世界、读档依赖"当前活动世界"这一全局前提。
5. **快照只服务后台保存**：主线程定格易变状态后，`IOLock` 保证同一时刻只有一次写盘，但不提供真正并发安全；`canBeSkipped` 让自动存档可丢而手动存档必等。
6. **加密是混淆不是安全**：密钥硬编码、Key 与 IV 相同，只为让 `.plr` 不能当文本直接改；因此体积大、纯展示的地图不加密，只做 Deflate。
7. **大量属性不入档**：角色只存原始字段，派生属性读后由 `LoadPlayer_LastMinuteFixes` 重算，让平衡性调整能直接作用到老存档，也避免版本间派生值不一致。
8. **校验分两道**：`ValidateWorld` 只验字节结构（我写的档是否可信），`FixAgainstExploits` 验业务不变量（外来档是否可信）。前者发现不了改档，后者才是安全边界。

### 反编译阅读提示
- 瓦片段请按"主掩码 = 有无方块/墙/液体，第二掩码 = 线/斜坡/漆色/微光，第三/第四掩码 = 隐形/全亮"来读，同名变量在不同函数中含义会变，以被掩码运算的那个为准。
- `LoadWorld` 里的嵌套 `using` 是 try/finally + Dispose 展开；`FileUtilities.ProtectedInvoke`（Terraria.IO/WorldFile.cs:897）只是普通回调。整条链路没有 async/await，并发全靠 `ThreadPool` + `Monitor`，不需要折叠状态机。
