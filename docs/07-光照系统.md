# 光照系统

> 适用范围：Terraria v1.4.5.8 反编译源码。路径均相对 `decompiled/Terraria/`。
> 阅读提示：反编译出的 `num/num2/flag/val` 等机械命名，本文统一转写为工程含义；`FastParallel.For` 的匿名委托可脑内折叠回「对某区间并行执行体函数」。

## 一句话结论

Terraria 1.4.5.8 的光照是**两阶段、逐格烘焙**的：`TileLightScanner` 只负责算出"每个格子自身发出多少彩光"（自发光方块、环境天空光、液体光），写入 `LightMap`；真正的**传播与衰减**由 `LightMap.Blur()` 用横竖各两个相反方向的"扫描线"（sweep）完成，衰减系数按格子掩码（空气/固体/水/蜂蜜/裂纹砖）查表；新版引擎还把扫描与模糊拆到不同帧。旧的 `LegacyLighting` 复用同一个 `TileLightScanner` 播种，但把传播改成"每帧只处理全部网格的一部分"，并额外提供 White/Retro/Trippy 三种模式。

## 关键数据结构

### 引擎抽象与门面
- `ILightingEngine`（`Terraria.Graphics.Light/ILightingEngine.cs:5-15`）：`Rebuild / AddLight / ProcessArea / GetColor / Clear`。`AddLight` 输入是**单格 RGB 颜色**（0~1），不是"半径+强度"，衰减完全交给传播阶段。
- `Terraria.Lighting`（`Terraria/Lighting.cs:10`）：全局门面，持有 `NewEngine`（`Lighting.cs:21`）、`LegacyEngine`（`Lighting.cs:23`），由 `_activeEngine`（`Lighting.cs:25`）指向当前实现。游戏代码只调 `Lighting.*`。
- `LightMode`（`Terraria.Graphics.Light/LightMode.cs:3`）：`White, Retro, Trippy, Color`；默认 `_mode = LightMode.Color`（`Lighting.cs:19`）。
- `LightMaskMode`（`Terraria.Graphics.Light/LightMaskMode.cs`）：`None / Solid / Water / Honey / CrackedBricks`，即每格的"光受阻材质"。

### 光照网格 LightMap
`Terraria.Graphics.Light/LightMap.cs`：
- 两条并行数组 `_colors: Vector3[]` 与 `_mask: LightMaskMode[]`，默认 203×203（`Terraria.Graphics.Light/LightMap.cs:47-57`）。
- 索引 `IndexOf(x,y) = x * Height + y`（`Terraria.Graphics.Light/LightMap.cs:252-255`），**列主序**：按 x 扫整列在内存上连续。
- 5 个衰减属性：`LightDecayThroughAir/Solid/CrackedBrick/Water(Vector3)/Honey(Vector3)`，即每走一格相乘的系数。
- `NonVisiblePadding`（`Terraria.Graphics.Light/LightMap.cs:19`）：外圈若干行列不作传播起点，只被写入。
- `SetSize` 仅在容量不足时重建数组，之后复用。

### 新引擎 LightingEngine
- 双缓冲：`_activeLightMap + _activeProcessedArea` 与 `_workingLightMap + _workingProcessedArea`（`Terraria.Graphics.Light/LightingEngine.cs:41-51`）。
- `AREA_PADDING = 28`（`Terraria.Graphics.Light/LightingEngine.cs:29`）扫描外扩；`NON_VISIBLE_PADDING = 18`（`Terraria.Graphics.Light/LightingEngine.cs:31`）Blur 外圈宽度。
- `_perFrameLights / _oldPerFrameLights`（`Terraria.Graphics.Light/LightingEngine.cs:35-37`）与 `_perFrameLightSwapUpdateCount`（`Terraria.Graphics.Light/LightingEngine.cs:33`）：本帧/上帧临时光源与其交换帧号。
- `EngineState`（`Terraria.Graphics.Light/LightingEngine.cs:13-20`）：`MinimapUpdate → ExportMetrics → Scan → Blur`，`Main.renderCount` 直接取状态序号 0~3。

### 旧引擎 LegacyLighting
- `LightingState`（`Terraria.Graphics.Light/LegacyLighting.cs:63-89`）：每格 `R/G/B`（已处理）+ `R2/G2/B2`（本阶段输入）+ 四个材质标记 `CrackedLight/StopLight/WetLight/HoneyLight`（`Terraria.Graphics.Light/LegacyLighting.cs:77-83`）。
- `_states`（x 为主）与 `_axisFlipStates`（y 为主）两套交错数组**引用同一批 LightingState 对象**（`Terraria.Graphics.Light/LegacyLighting.cs:240-255`），令"按行扫"和"按列扫"都能拿到连续数组，无需转置。
- `_tempLights`：`Dictionary<Point16, ColorTriplet>`（`Terraria.Graphics.Light/LegacyLighting.cs:152`），同格**逐分量取最大值**（`Terraria.Graphics.Light/LegacyLighting.cs:268-293`）。
- `_negLight/_negLight2/_negLight3` 与 `_wetLightR/G/B`、`_honeyLightR/G/B`（`Terraria.Graphics.Light/LegacyLighting.cs:162-178`）：传播期使用的衰减参数。

## 执行流程

### 1. 每帧入口 LightTiles 与可视区

`Main.DoDraw` 绘世界前调用 `Lighting.LightTiles(GetAreaToLight())`（`Terraria/Main.cs:63064`）。`LightTiles`（`Lighting.cs:100-107`）置 `Main.render = true`、刷新 `GlobalBrightness`、调用 `_activeEngine.ProcessArea(area)`。旧引擎这一帧的处理是**条件分片**的（`Terraria.Graphics.Light/LegacyLighting.cs:327-364`）：先 `Main.renderCount++`；`< 3` 才调 `DoColors` 推进颜色；`== 2` 时 `CopyFullyProcessedDataOver` 整体拷贝，`_lastCameraPosition` 有值时（含 `> 2`）`ShiftUnProcessedDataOver` 平移旧数据（不再扫光）；`renderCount > RenderPhases` 时只做 `PreRenderPhase()` 把计数归零，本帧不扫光。`Present()` 只在 `Terraria.Graphics.Light/LightingEngine.cs:135-140` 的新引擎里被调用，`DoColors` 也不依赖渲染相，不会在渲染相前被额外调用。

`Main.GetAreaToLight`（`Terraria/Main.cs:64859-64873`）：新光照用 `Camera.ScaledPosition/Size`，旧光照用 `UnscaledPosition/Size`（`Terraria/Main.cs:64863-64867`），再按 16 像素一格换算并各向外多取 1~2 格。

`GlobalBrightness`（`Lighting.cs:109-116`）默认 1.2，玩家 `blind` 时 1.0——它只是**读取侧的亮度乘子**，不属于光照数据。

**为什么要连调两次**：新引擎一帧只推进一个相位，需要"立刻出结果"的场合（闪电增减亮、`renderNow`）会连调两次 `LightTiles`（`Terraria/Main.cs:59668-59675`、`Terraria/Main.cs:62763-62764`），凑满"扫描+模糊"一轮；世界截图则 `Initialize()` 后连调 4 次（`Terraria/Main.cs:57584-57589`）。

### 2. 新引擎：四相位状态机

`ProcessArea` 按 `_state` 分派，每次只做一相（`LightingEngine.cs` `ProcessArea` 的 switch）：

1. **MinimapUpdate**：`Main.mapDelay` 递减或 `ExportToMiniMap()`（把 `_activeLightMap` 每格取 RGB 最大值写进地图，裁掉 28 格 padding 后写入，`Terraria.Graphics.Light/LightingEngine.cs:246-268`），然后 `renderCount = 3`。
2. **ExportMetrics**：`Main.UpdateSceneMetrics()`，`renderCount = 0`。`UpdateSceneMetrics`（`Terraria/Main.cs:63441-63470`）以 `GetAreaToLight()` **外扩 28 格**为扫描区（`Terraria/Main.cs:63461-63462`，与 `AREA_PADDING` 一致），计算群系、`Main.waterStyle`、`SceneState` 衰减等；截图时直接 return（`Terraria/Main.cs:63443-63446`）。
3. **Scan**：`ProcessScan`（`Terraria.Graphics.Light/LightingEngine.cs:115-126`）：`area.Inflate(28, 28)` → `_workingLightMap.SetSize` 且 `NonVisiblePadding = 18` → `_tileScanner.Update()` → `_tileScanner.ExportTo(area, map, options)`，其中 `DrawInvisibleWalls = Main.ShouldShowInvisibleBlocksAndWalls()`。
4. **Blur**：`ProcessBlur` → `UpdateLightDecay` → `ApplyPerFrameLights` → `_workingLightMap.Blur()`，然后 `Present()` 交换双缓冲。

### 3. 逐格扫描 TileLightScanner

`ExportTo`（`Terraria.Graphics.Light/TileLightScanner.cs:17-41`）对扩展区 `FastParallel.For` 按列并行，每格：

1. `IsTileNullOrTouchingNull`（`Terraria.Graphics.Light/TileLightScanner.cs:43-54`）：世界外或上/下/左/右任一邻格为 null → 掩码 None、光值清零，规避世界边界采样。
2. `GetTileMask`（`Terraria.Graphics.Light/TileLightScanner.cs:66-85`）：`LightIsBlocked` 且非 131（木平台）、非 `inActive`、坡度 0 → `CrackedBricks` 或 `Solid`；否则若非岩浆且 `liquid > 128` → 蜂蜜 `Honey`，否则 `Water`；其余 `None`。**液体量 ≤128 不参与彩色吸光**，即浅水不染色。`LightIsBlocked`（`Terraria.Graphics.Light/TileLightScanner.cs:152-163`）= 方块存在且 `Main.tileBlockLight[type]`，隐形方块是否挡光取决于 `_drawInvisibleWalls`。
3. `GetTileLight`（`Terraria.Graphics.Light/TileLightScanner.cs:87-106`）用四个 `ApplyXxx` 逐分量取较大值叠加（非相加）。

> 语法糖提示：`TileLightScanner` 类体内多数方法在反编译文本中**多缩进了一层**（例如 `ApplySurfaceLight` 定义于 `Terraria.Graphics.Light/TileLightScanner.cs:3150`），这是反编译器对嵌套结构的展开痕迹，逻辑上它们仍是该类的私有方法，阅读时把这一层缩进折叠掉即可。

区域选择（`Terraria.Graphics.Light/TileLightScanner.cs:90-99`）：`y <= Main.worldSurface` → `ApplySurfaceLight`（天空光）；`y > Main.UnderworldLayer` → `ApplyHellLight`（地狱光）；两者之间的地下**无环境光**——这是"洞穴必须点灯"的机制来源。

### 4. 天空光、昼夜注入与地狱光

**`ApplySurfaceLight`**（`Terraria.Graphics.Light/TileLightScanner.cs:3150-3257`）：
- 基色为 `Main.tileColor`（`Terraria/Main.cs:1242` 声明），取 R/G/B 三个 0~1 分量与其均值 `num7`（`Terraria.Graphics.Light/TileLightScanner.cs:3155-3158`）。
- 只有"对天空开放"（无太阳挡光方块，或斜坡/半砖/隐形方块且四邻无液体，`Terraria.Graphics.Light/TileLightScanner.cs:3168`）且"有透光背景墙"的格子才获得天空色。
- 液体 `< 200` 时按规则削弱甚至取消（半砖下方有水则不给）；`liquid >= 200` 且 `Main.liquidAlpha[13] > 0`（微光水体）时只给一点蓝色并乘随机抖动（`Terraria.Graphics.Light/TileLightScanner.cs:3170-3186`）。**微光环境偏暗偏蓝，来自于天空光被水体吸收而非单独的光照模式。**
- 彩虹类背景墙 88~93/241 把天空光乘上过滤色，墙 93（`case 5`）再叠 `Main.DiscoR/G/B`（`Terraria.Graphics.Light/TileLightScanner.cs:3188-3239`）。
- 末尾统一乘 `1 - Main.shimmerDarken`（`Terraria.Graphics.Light/TileLightScanner.cs:3241-3244`）。

**昼夜的注入点**：`Main.ApplyColorOfTheSkiesToTiles`（`Terraria/Main.cs:64105-64113`）把 `ColorOfTheSkies` 按"3/10 均混 + 7/10 本色"合成后写入 `Main.tileColor`，再经 `SkyManager.Instance.ProcessTileColor` 修正；`ColorOfTheSkies` 由 `SetBackColor`（`Terraria/Main.cs:64384`）根据昼夜与群系算出。昼夜切换在 `UpdateTime`：`time > 54000` 入夜（`Terraria/Main.cs:20163-20167`）、`time > 32400` 入昼（`Terraria/Main.cs:20145-20161`）；此外 `UpdateTime` 末尾让 `tileBlockLight[718]` 随 `dayTime` 翻转（`Terraria/Main.cs:66105-66112`），说明存在昼夜开关的挡光方块。

由此可知：**昼夜不是光照引擎的独立参数，而是经由 `Main.tileColor` 这一个颜色入口注入**；光照每帧重建并重新采样该颜色，所以天色任何一帧的平滑变化都会即时反映到地表光上。

**`ApplyHellLight`**（`Terraria.Graphics.Light/TileLightScanner.cs:3259-3336`）：基亮度 `num4 = 0.55 + sin(GlobalTimeWrappedHourly * 2) * 0.08`（`Terraria.Graphics.Light/TileLightScanner.cs:3264`），输出 `(num4, num4*0.6, num4*0.2)` 的暖橙呼吸光；开放度、透光墙、液体条件与天空光同构，彩虹墙过滤逻辑也复刻一份（`Terraria.Graphics.Light/TileLightScanner.cs:3271-3322`）。

### 5. 材质自发光：墙 / 方块 / 液体

- **墙光** `ApplyWallLight`（`Terraria.Graphics.Light/TileLightScanner.cs:165-340`）：按 `tile.wall` 分派（357 微光墙、182/33 彩色墙纸、137 岩浆墙、44/346 彩虹墙、154~176 石墙等），部分墙在 `LightIsBlocked` 时不发光。若该墙可被漆染色（局部 `flag`），亮度取 `WorldGen.paintColor(wallColor)` 的分量除以 765（`Terraria.Graphics.Light/TileLightScanner.cs:305-312`）——**除以 765 而非 255，等于亮度只有漆色的约 1/3**。
- **方块光** `ApplyTileLight`（`Terraria.Graphics.Light/TileLightScanner.cs:342-3148`）：只处理 `Main.tileLighted[type]` 的方块，常用 `tile.frameX/frameY` 区分变体（例如 129 宝石灯按 `frameX/18 % 3` 换色，`Terraria.Graphics.Light/TileLightScanner.cs:3071-3090`）；125 粉色火把直接写 `lightColor.Y/Z`（`Terraria.Graphics.Light/TileLightScanner.cs:3063-3070`）。方块漆色覆盖的分母是 255（`Terraria.Graphics.Light/TileLightScanner.cs:3129-3135`）。
- **液体光** `ApplyLiquidLight`（`Terraria.Graphics.Light/TileLightScanner.cs:108-150`）：`liquid <= 0` 直接返回；岩浆给暖橙、微光给青蓝，并随 `270 - Main.mouseTextColor` 呼吸。**注意不按液位衰减**：液位类型由 `Tile.lava()` 读取 `bTileHeader` 的类型位（`Terraria/Tile.cs:347-350`，`shimmer()` 见 `:381-384`），与液位无关，所以"少量岩浆也很亮"。

**闪烁/呼吸的统一手法**：大量 `localRandom.Next(min,max)` 与 `(270 - Main.mouseTextColor) / 常数` 项（火把 `Terraria.Graphics.Light/TileLightScanner.cs:1032-1033`、彩虹墙 `Terraria.Graphics.Light/TileLightScanner.cs:230-231`）。`localRandom` 来自 `_random.WithModifier(x, y)`（`Terraria.Graphics.Light/TileLightScanner.cs:90`），该函数用固定整数哈希由坐标生成子种子（`Terraria.Utilities/FastRandom.cs:32-35`）；`_random.NextSeed()` 每帧在 `Update()` 中推进（`Terraria.Graphics.Light/TileLightScanner.cs:56-59`）。于是每格相位固定、整体每帧刷新——火光呈"原地抖动"而非整片漂移。

### 6. 传播与衰减：LightMap.Blur

`Blur`（`Terraria.Graphics.Light/LightMap.cs:86-91`）连续两次 `BlurPass` 后 `_random.NextSeed()`。每次 `BlurPass`（`Terraria.Graphics.Light/LightMap.cs:93-112`）做四条扫掠：每个 x 列正/反两向、每个 y 行正/反两向，全部并行。

`BlurLine`（`Terraria.Graphics.Light/LightMap.cs:114-250`）沿一条线维护"携带光" `zero`（RGB 独立）：
- 格子比 `zero` 亮 → 取该值并解除对应分量的熄灭标记（`flag/flag2/flag3`）；
- 格子更暗且未熄灭 → 把 `zero` 写回该格（光沿直线"拉"过去）；
- `zero` 分量低于 **0.0185** 视为熄灭（`Terraria.Graphics.Light/LightMap.cs:128/144/160`），此后停止写入与衰减——避免无限长灰尾；
- 推进前按本格掩码乘衰减：None→空气、Solid→实心、CrackedBricks→裂纹砖、Water→水色 × 随机 0.98~0.99（`Terraria.Graphics.Light/LightMap.cs:219` 用 `_random.WithModifier((ulong)i)`，`i` 为数组绝对下标，保证同格每帧随机值稳定）、Honey→蜂蜜色。

这是经典**四方向逐行传播 + 双向扫描**：单次 pass 只处理"直线可达"的光，两遍叠加后拐角被第二次 pass 补齐，近似各向同性。`NonVisiblePadding` 让最外 18 格只作写入目标，防止边缘假光反灌可视区（`Terraria.Graphics.Light/LightMap.cs:99-108`）。

**衰减系数的运行时来源** `UpdateLightDecay`（`Terraria.Graphics.Light/LightingEngine.cs:141-206`）：
- 空气 0.91、实心 0.56（`:144-145`），蜂蜜 `(0.75,0.7,0.6)*0.91`（`:146`）；
- 水按 `Main.waterStyle` 0~13 查表（`:148-181`），如普通水偏蓝 `(0.88,0.96,1.015)`——**不同水体透光颜色不同的来源**；
- 玩家状态：`nightVision` ×1.03，`blind` ×0.95，`blackout`/`headcovered` ×0.85（`:183-203`）；
- 再乘 `Main.SceneState.airLightDecay/solidLightDecay`（`:204-205`）。这两个值由 `SceneState.UpdateLightDecay` 每帧向目标 1.0 平滑逼近（`SceneState.cs:301-302`，步长 0.005）。常态下 `airLightDecay` 只乘 `1 - shimmerAlpha * 0`（恒为 1，实为占位），`solidLightDecay` 乘 `1 - shimmerAlpha * 0.3`；只有 `Main.getGoodWorld` 才按与邪教徒/神庙/地牢的距离把两者降到 0.6~0.94（`SceneState.cs:283-300`），并以步长 0.005 平滑逼近。

### 7. 帧内临时光源 ApplyPerFrameLights

`Lighting.AddLight(int,int,float,float,float)`（`Lighting.cs:161-167`）在 `Main.gamePaused` 或专用服务器（`netMode == 2`）时直接丢弃，所以**暂停时粒子新光不会补进网格**；其余情况转交 `_activeEngine.AddLight`，新引擎只是追加进 `_perFrameLights`。

`ApplyPerFrameLights`（`Terraria.Graphics.Light/LightingEngine.cs:209-236`）：
- 若 `Main.GameUpdateCount == _perFrameLightSwapUpdateCount`（`:211`）说明本帧已交换，改读**上一帧列表**；
- 对落在 `_workingProcessedArea` 内的点，用 `Vector3.Max` 顶入网格（`:222`），与扫描的"取最大"一致，不会叠加爆亮；
- 非截图状态下，帧号变化时交换新旧列表、清空当前列表并记录帧号（`:225-234`）。

这样即便 `AddLight` 发生在扫描之后，光也会在 Blur 前写进 working map。`Clear` 会同时重置两块网格、两个列表与帧号。

### 8. 读取侧：GetColor 系列与四角插值

- `GetColor(int,int)`（`Lighting.cs:222-250`）：`GetColor` × `GlobalBrightness` ×255 取整、钳 255，手工拼 `PackedValue`（0xFFRRGGBB）；菜单态返回白色（`:224-227`）。
- `GetColor(x,y,oldColor)`（`Lighting.cs:202-209`）：光照 × 原色，用于贴图染色。
- `GetSubLight`（`Lighting.cs:124-137`）：按亚格位置对四格双线性插值。
- `GetColor9Slice / GetColor4Slice`：九宫格/四象限取样，供带边框或斜面的贴图。
- `GetCornerColors`（`Lighting.cs:297-382`）：每个顶点 = 中心格 + 相邻两格 + 对角格共 4 格之和，乘 `GlobalBrightness * scale * 63.75`（`:309`，即 255/4）——**四格平均再归一**，方块内部因此呈现平滑渐变，代价是相邻方块光照互相渗透。渲染侧调用见 `Terraria.GameContent.Drawing/TileDrawing.cs:4056`。

引擎在区域外返回 `Vector3.Zero`（`LightingEngine.cs:63-71`、`Terraria.Graphics.Light/LegacyLighting.cs:211-219`）。注意新引擎 `ProcessBlur` 的 Blur 相就调用 `Present()` 把 working 换成 active（`Terraria.Graphics.Light/LightingEngine.cs:101`、`:128-140`），因此 active 区永远是上一轮 Scan 得到的、比本帧 `GetAreaToLight` 大 28 格的扩张区——28 格外扩真正保证的是 Blur、指标与读取所用区域都落在上一次已呈现的活动区内，`GetColor` 的越界返回零在正常帧里只是兜底。

## 设计要点与取舍

1. **发光与传播彻底解耦。** 扫描器只回答"本格多亮、什么材质"，以 `(color, mask)` 交给网格；传播只按 mask 乘系数。旧引擎因此能原样复用同一个扫描器（`Terraria.Graphics.Light/LegacyLighting.cs:192`、`:723-727`）。新增光源只需改扫描器 switch，不触碰传播。

2. **乘法衰减 + 逐分量取最大。** 每格乘 0.5~0.9 的系数而非减固定值，亮度高时衰减慢、远处仍留微光，并靠 0.0185 阈值强制收尾；多光源一律取 max 不相加，避免过曝。

3. **新引擎用"全帧重建 + 双缓冲"换正确性。** 无历史依赖，传送、天气切换、切换显示隐形方块都能立刻正确；代价是每帧 O(W·H) 扫描 + 两遍四方向 Blur。把扫描/模糊拆帧并插入地图导出与指标统计（`EngineState`），是为了摊平单帧峰值。

4. **旧引擎用"滚动缓冲 + 分相位扫掠"换性能。** 按相机位移平移旧数据（`ShiftUnProcessedDataOver`，`Terraria.Graphics.Light/LegacyLighting.cs:473-537`；位移超过 5 格则放弃），`Main.renderCount == 2` 时整体拷贝（`CopyFullyProcessedDataOver`，`:538-621`）；`DoColors` 按 4 个相位分段（`:996-1085`），4 个相位按行/列/行/列交替使用 `_states` 与 `_axisFlipStates`（相位 0、2 用 `_states`，相位 1、3 用 `_axisFlipStates`，`:1034-1048`），后两相在更小区域收敛。代价是"光慢慢爬过来"的观感。

5. **四种模式的差异主要在"衰减口径"，不在扫描。** `doColors_Mode0_Swipe`（`:1088-1191`，Color 用，White 亦复用 Mode0）为**乘法**；`doColors_Mode2_Swipe`（`:1274-1330`，Retro）为**减法**（`num4 - _negLight`，`:1316`），故 Retro 是硬边"光圈"；`doColors_Mode1/3_Swipe`（White/Trippy）同样是减法，Trippy 三个通道的公式略有差异（`:1384/1404/1422`）。`_rgb = (Mode == 0 || Mode == 3)`（`:662`），所以 Color 与 Trippy 保留三通道、White 与 Retro 不保留；压平均值发生在 Retro/White 的播种分支（`:749`）以及 Trippy 下的水/蜂蜜分支里。**注意 `_negLight` 系列在乘法与减法两种口径下复用同一组字段，改值时必须同时考虑两种用法。**

6. **水体是"彩色 + 随机"的透光介质。** 新引擎按水体样式查 RGB 系数（`Terraria.Graphics.Light/LightingEngine.cs:148-181`）并叠 0.98~0.99 抖动；旧引擎另有 `_blueWave` 在 0.97~1.0 往返（`Terraria.Graphics.Light/LegacyLighting.cs:854-866`），使水光周期性轻呼吸——新引擎已改为固定系数。

7. **昼夜与地下环境光是"边界条带"。** 扫描器以 `worldSurface` 与 `UnderworldLayer` 两条硬边界切换（`Terraria.Graphics.Light/TileLightScanner.cs:90-99`），地表/地狱各自再做平滑（地狱光带正弦呼吸），地下内部默认漆黑。背景墙（能否透光）因此成为地下视野的关键变量。

8. **全局亮度乘子在渲染期而非数据期。** `GlobalBrightness`、255 取整与钳制都在读取时执行，网格数据保持 0~1 浮点，使调亮度不污染已算数据，也让九宫格/四角插值共用同一份数据。

9. **强耦合提醒。** `LightingEngine` 直接读写 `Main.renderCount`（与地图更新、整帧渲染进度共享同一计数器）、`Main.mapDelay`、`Main.SceneMetrics/SceneState`、`Main.waterStyle`、`Main.tileColor`、`Main.GameUpdateCount`、`Main.ShouldShowInvisibleBlocksAndWalls()`。因此单独测试光照几乎不可行，任何改动都必须在完整 `Main` 循环中验证；若要独立复现，需要一个提供这些静态字段的同构环境。
