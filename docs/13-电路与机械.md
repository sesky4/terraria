# 电路（Wiring）与机械

> 覆盖代码：`Terraria/Wiring.cs`（3436 行，全部静态成员）+ 少数外部协作者（`Terraria.GameContent/PressurePlateHelper.cs`、`Terraria.GameContent.Tile_Entities/TELogicSensor.cs`、`Terraria/MessageBuffer.cs`、`Terraria/Tile.cs`、`Terraria.DataStructures/DoubleStack.cs`）。
> 下文 `Terraria/Wiring.cs:N` 均指 `decompiled/Terraria/Terraria/Wiring.cs` 的第 N 行。

## 一句话结论

Terraria 的电路不是"事件驱动"的，而是一个**按线缆颜色分趟执行的广度优先洪水填充**：一次触发从触发器所在格出发，沿同色线缆把整个连通域收集成待处理队列，逐个格调用 `HitWireSingle` 产生元件效果；机械元件（大炮、间歇泉、雕像、计时器……）的触发节流统一挂在同一个 `_mechTime` 冷却表上，由世界更新每 tick 递减。

## 关键数据结构

全部是 `Wiring` 的私有静态字段，在 `Initialize()` 中一次性分配（`Terraria/Wiring.cs:90-113`），跨世界复用。

| 字段 | 类型 | 工程含义 |
|---|---|---|
| `_wireList` | `DoubleStack<Point16>` | 待遍历线缆格的 BFS 队列（双端容器，但这里只当 FIFO 用） |
| `_wireDirectionList` | `DoubleStack<byte>` | 与 `_wireList` 一一对应的"从哪个方向进入"标记 |
| `_wireSkip` | `Dictionary<Point16,bool>` | 本次遍历中"已处理、别再重复触发"的格子 |
| `_toProcess` | `Dictionary<Point16,byte>` | 邻居去重计数：一个格子从多个方向到达时只入队一次 |
| `_GatesCurrent/_GatesNext` | `Queue<Point16>` | 逻辑门"这一轮 / 下一轮"待传播的格 |
| `_GatesDone` | `Dictionary<Point16,bool>` | 本轮回合内已处理过的逻辑门，防重入 |
| `_LampsToCheck` | `Queue<Point16>` | 本次被点亮的逻辑门灯，等待连锁评估 |
| `_PixelBoxTriggers` | `Dictionary<Point16,byte>` | 像素盒本次收到的方向位（1=横向 / 2=纵向） |
| `_teleport` | `Vector2[2]` | 一次 `TripWire` 内收集到的两台传送机坐标，未找到时为 (-1,-1) |
| `_inPump/_outPump` | `int[20]` ×4 + 计数 | 本次收集到的入/出水泵格，`TripWire` 结束后统一结算 |
| `_mechX/_mechY/_mechTime` | `int[1000]` | 全局机械冷却表 |
| `_currentWireColor` | `int` | 当前正在处理第几色线（1/2/3/4） |
| `CurrentUser` | `int` | 触发源玩家下标；255 表示无主/服务端（`Terraria/Wiring.cs:77-88`） |
| `running` | `bool` | 电路执行期间为 true，供世界生成侧联动（`Terraria/Wiring.cs:19`） |

机械命名到工程含义的对照：

| 变量 | 含义 |
|---|---|
| `b`（`HitWire` 内） | 新格子的入队次数预算：普通元件 3，分线器/像素盒 0 |
| `_toProcess` 的值 | 该格"还能再被几个方向入队"，减到 0 即出表 |
| `_wireDirectionList` 的值 | 进入方向：0=从下往上走 1=从上往下 2=从左往右 3=从右往左（`Terraria/Wiring.cs:860-881`） |
| `_mechTime[k]` | 该机械元件剩余冷却 tick，`<=0` 时从表中移除 |
| `forcedStateWhereTrueIsOn` | 三态开关：null=按当前状态取反，true/false=强制目标状态（当前所有调用点都传 null） |
| `doSkipWires` | 元件内部是否顺手 `SkipWire` 自己（当前恒为 true） |
| `time`（`CheckMech` 参数） | 该元件触发后锁住多少 tick |
| `flag4 / flag5 / flag6 / flag7`（`CheckLogicGate`） | 依次是：门的求值结果 / 门处于特殊态 / 装饰灯读到特殊态 / 最终是否输出 |

## 执行流程

### 1. 数据表示：一个瓦片可以叠 4 色线 + 1 个致动器

线缆不是实体，而是 `Tile` 上的四个独立位（`wire()/wire2()/wire3()/wire4()`），另有 `actuator()` 与 `inActive()`（`Terraria/Tile.cs:608-659`、`Terraria/Tile.cs:693`）。放置/拆除由 `WorldGen.PlaceWire / KillWire` 等函数完成（`WorldGen.cs:58416`、`WorldGen.cs:58427`），多色线在同一格互不排斥。因此"同色才连通"是遍历器的规则，不是数据结构的规则。

### 2. 触发器入口：所有人最后都汇入 `HitSwitch`

触发器种类繁杂（压力板、手动开关、逻辑传感器、矿车轨道、地雷、间歇泉……），但都调用 `Wiring.HitSwitch(int i, int j)`（`Terraria/Wiring.cs:259`）。它按瓦片类型分派：

- 135/314/423/428/442/476（压力板、轨道开关、逻辑传感器等）：直接 `TripWire(i, j, 1, 1)`（`Terraria/Wiring.cs:261-269`）。
- 440（大开关）：`TripWire(i, j, 3, 3)`（`Terraria/Wiring.cs:270-274`）。
- 136（手动开关）：先翻转 `frameY` 再触发（`Terraria/Wiring.cs:275-287`）。
- 210（地雷）→ `ExplodeMine`；443（间歇泉）→ `GeyserTrap`（`Terraria/Wiring.cs:288-295`）。
- 144（计时器）：翻转 `frameY` 作为开启标记，开启时 `CheckMech(i, j, 18000)` 登记进冷却表（`Terraria/Wiring.cs:296-311`）。
- 441/468/467（机关箱）：由 `frameX/frameY` 折算回左上角，再 `TripWire(左上角, 2, 2)`（`Terraria/Wiring.cs:311-339`）。
- 132/411（拉杆/引爆器）：翻转 2x2 的 `frameX`，引爆器额外 `CheckMech(..., 60)`，再 `TripWire(左上角, 2, 2)`（`Terraria/Wiring.cs:340-377`）。

注意 `TripWire` 的第三、四个参数是**扫描线缆的矩形宽高**，不是元件自身尺寸：代码只用它决定从多大范围收集线缆起始点（大开关 3x3、拉杆/机关箱 2x2、其余 1x1，`Terraria/Wiring.cs:542-553`），并不以此约束元件的大小。2x2 元件的 4 格都可能各自触发一次 `HitSwitch`，代码也没有"每次触发最多 4 次 BFS"这样的硬性约束。

"点击了多元件的一个格子"都遵循同一公式：用 `frameX/frameY` 除以 18 得到局部偏移，减去即得左上角。这是维护该文件时最容易出错的地方。

**外部调用点**（说明触发源不止玩家）：

- `Terraria/Collision.cs:3359`：实体碰撞到压力板类瓦片；
- `PressurePlateHelper.cs:161`：压力板"所有人离开"边沿，见第 9 节；
- `TELogicSensor.cs:88`（`UpdateEndInternal` 处理 `tripPoints`）、`TELogicSensor.cs:367`（传感器被 `Kill` 时）：逻辑传感器的触发；
- `Minecart.cs:1292`：矿车碰到轨道开关；
- `WorldGen.cs:46760`：大开关等多元件；
- `Terraria/Player.cs:32414`、`Terraria/Player.cs:32464`、`Terraria/Player.cs:32578`、`Terraria/Player.cs:35090`：玩家按键/使用逻辑门灯；
- `MessageBuffer.cs:1890`（撬箱子）、`MessageBuffer.cs:2689`（网络消息 59）。

### 3. `TripWire`：一次触发 = 四次独立遍历

`TripWire(left, top, width, height)`（`Terraria/Wiring.cs:525`）是系统真正入口，结构高度重复、可脑内折叠。`left/top` 是扫描起点，`width/height` 是该起点的扫描矩形宽高（`Terraria/Wiring.cs:542-553`）：

1. 客户端直接返回（`Terraria/Wiring.cs:527-530`）——电路只在服务端/单机模拟。
2. 清空两个队列、置 `running = true`、复位 `_teleport`。
3. 把矩形范围内的**红线**格压入 `_wireList`（`Terraria/Wiring.cs:534-556`）。
4. 队列非空时：清零泵计数 → `HitWire(_wireList, 1)` → 若同时收集到入泵和出泵则 `XferWater()`（`Terraria/Wiring.cs:558-567`）。
5. 把 `_teleport` 存入 8 槽结果数组，对 2/3/4 色线重复 3–4 步（`Terraria/Wiring.cs:569-665`）。
6. `running = false`，逐组取出传送机坐标，两台都有效时调用 `Teleport()`（`Terraria/Wiring.cs:647-665`）；最后 `PixelBoxPass()`、`LogicGatePass()`（`Terraria/Wiring.cs:668`、`Terraria/Wiring.cs:682`）。

所以**一次"开关被按下"最多产生 4 次 BFS（红/绿/蓝/黄各一趟）+ 4 次传送结算**；每种颜色完全隔离，颜色之间不会互相激活同一根线。这是 `TripWire` 里写死的四趟循环，而不是对触发频率的额外限制。

### 4. `HitWire`：带方向与去重的 BFS

`HitWire(next, wireType)`（`Terraria/Wiring.cs:837`）：

1. 种子格先全部 `SkipWire`、`_toProcess = 4`，再压回队尾、方向记 0（`Terraria/Wiring.cs:839-849`）。这样触发器自身不会被邻居"再拉进来"一次。
2. 主循环：每次 `PopFront` 出一个格与方向，先执行 `HitWireSingle(x, y)`，再四向扩展（`Terraria/Wiring.cs:851-859`）。
3. 扩展规则：
   - 离世界边界 2 格内跳过（`Terraria/Wiring.cs:886-889`）；目标格必须有当前颜色的线（`wireType switch {...}`，`Terraria/Wiring.cs:944-953`）。
   - 入队预算 `b` 默认 3，**分线器 424 与像素盒 445 为 0**（`Terraria/Wiring.cs:899-904`）。
   - 方向敏感：邻格是 424 时按其 `frameX/18` 只允许直通或特定转向（`Terraria/Wiring.cs:905-928`）；当前格是 445 时只允许同向，并把方向位写进 `_PixelBoxTriggers`（`Terraria/Wiring.cs:929-943`）。
   - 已在 `_toProcess` 中的格：计数减一，减到 0 即移除且**不再入队**——这就是多方向到达只处理一次的实现（`Terraria/Wiring.cs:956-968`）。
   - 否则入队并记录方向（`Terraria/Wiring.cs:969-972`）。
4. 结束后清空 `_wireSkip` 与 `_toProcess`（`Terraria/Wiring.cs:977-978`）。

> 编译器糖提示：`switch (wireType) { 1 => tile.wire() ? 1 : 0, ... }`（`Terraria/Wiring.cs:944-953`）是 switch 表达式；`DoubleStack` 虽是双端容器，但这里只用 `PushBack/PopFront/Count`，按 FIFO 队列读即可。

### 5. `HitWireSingle`：元件效果的分派表

`HitWireSingle(i, j)`（`Terraria/Wiring.cs:996`）是所有机械元件"被电到后做什么"的唯一集中处，占 `Wiring.cs` 一半以上。开头的通用规则：

- 若该格有**致动器**，先 `ActuateForced(i, j)`（`Terraria/Wiring.cs:1003-1006`）；
- 若该格没有活动瓦片直接返回（`Terraria/Wiring.cs:1008-1010`）——这意味着"被致动虚化的方块"，其上的元件不再响应。

之后是若干前置特判（144 计时器自触发、421/422 篝火切换、255–268 各类灯的分类切换、419 逻辑门灯、406/452 大型多格灯具……），再进入主体巨型 `switch (type)`。典型分支的工程含义：

| 分支 | 含义 | 位置 |
|---|---|---|
| 419 逻辑门灯 | 翻转 `frameX`、`SkipWire` 自身、入队 `_LampsToCheck` | `Terraria/Wiring.cs:1053-1069` |
| 356 / 663 | 天盘 / 月盘：加速到白天 / 黄昏 | `Terraria/Wiring.cs:1137-1176` |
| 425 | 广播盒：读关联告示牌文本，按 `AnnouncementBoxRange` 发给玩家 | `Terraria/Wiring.cs:1177-1236` |
| 209 | 大炮 / 兔子炮：按帧推算朝向与冷却，`CheckMech` + `WorldGen.ShootFromCannon` | `Terraria/Wiring.cs:1237-1461` |
| 212 | 雪球炮：固定 15 帧冷却后发射 | `Terraria/Wiring.cs:1357-1440` |
| 235 | 传送机：记入 `_teleport[0/1]` | `Terraria/Wiring.cs:1553-1576` |
| 429 | 四色灯：按 `_currentWireColor` 只翻转对应颜色的位 | `Terraria/Wiring.cs:1586-1621` |
| 42/93/95/100/126/173/564 等 | 各类灯具 / 家具的开关（`Toggle*` 系列） | `Terraria/Wiring.cs:1684-1744` |
| 137 | 各类陷阱（飞镖/长矛/尖球……），按帧号决定弹种与方向 | `Terraria/Wiring.cs:1764-1985` |
| 443 / 467 | 间歇泉 → `GeyserTrap`；机关箱 → `Hopper` | `Terraria/Wiring.cs:1987-1988`、`Terraria/Wiring.cs:1991-1993` |
| 142/143 | 水泵：把 2x2 四格登记进 `_inPump`/`_outPump`，每侧最多 19 格 | `Terraria/Wiring.cs:2046-2120` |
| 105 | 雕像：按帧号选生物，受 `NPC.MechSpawn` 数量限制 | `Terraria/Wiring.cs:2129-2483` |
| 410/480/509/657 等 | 月相碑类：`WorldGen.SwitchMonolith` | `Terraria/Wiring.cs:2025-2034` |
| 455 | 生日派对手动开关 | `Terraria/Wiring.cs:2036-2037` |

共同规律：**冷却一律走 `CheckMech`，"防重复触发"一律走 `SkipWire`，状态存在 `frameX/frameY` 上，改完立刻 `NetMessage.SendTileSquare`。**

### 6. 机械冷却表：`CheckMech` + `UpdateMech`

`CheckMech(i, j, time)`（`Terraria/Wiring.cs:455`）语义是"**若该坐标当前不在冷却中，登记 time tick 冷却并返回 true（允许触发）**；已在表中返回 false"。表实际上限 998 条（`_numMechs < 999`，`Terraria/Wiring.cs:464`），满了也返回 false——一个静默的全局上限。

`UpdateMech()`（`Terraria/Wiring.cs:145`）由 `WorldGen.UpdateWorld()` 每 tick 调用（`WorldGen.cs:71871`）：

- 递减三种大炮的全局冷却（`Terraria/Wiring.cs:147-158`）；
- 倒序遍历冷却表，每项每 tick 减 1（`Terraria/Wiring.cs:162`）；
- **计时器（144）走特殊路径**：按 `frameX/18` 选分频值 60/180/300/30/15，用 `Math.IEEERemainder(_mechTime, 分频) == 0` 判定是否到点；到点就 `TripWire(自身, 1, 1)` 并把 `_mechTime` 重置为 18000（`Terraria/Wiring.cs:178-209`）。开着的时候每到一个分频边界就开火一次，直到玩家再按一次关闭；
- 冷却归零时：144 复位外观并同步；411 翻转帧图；然后用后续元素依次前移覆盖当前项（`for (k = num; k < _numMechs; k++) { _mechX[k] = _mechX[k+1]; ... }`），最后 `_numMechs--`（`Terraria/Wiring.cs:245-253`）。
- 删除是 O(n) 的顺序前移，而且发生在上述倒序遍历（`Terraria/Wiring.cs:162`）的中途：被前移上来的记录会在下一轮循环里被再次访问，因此同一个冷却项可能被递减不止一次；`CheckMech` 本身也只是 O(n) 线性查找。

### 7. 逻辑门：`LogicGatePass` + `CheckLogicGate`

逻辑门体系由两种瓦片组成：419（逻辑门灯，叠在门上方的装饰列）、420（逻辑门本体，`frameY/18` 决定门类型）。

1. 灯被电到时只做两件事——翻转 `frameX`、入队 `_LampsToCheck`（`Terraria/Wiring.cs:1053-1069`）。
2. `LogicGatePass()`（`Terraria/Wiring.cs:682`）用**双层队列**做"轮次传播"：外层 while 在 `_LampsToCheck` 非空时循环；内层先清空所有待检查灯，再交换 `_GatesNext` 与 `_GatesCurrent`，逐门 `TripWire`（`Terraria/Wiring.cs:691-710`）。开头的 `if (_GatesCurrent.Count != 0) return;`（`Terraria/Wiring.cs:684-687`）是重入保护——门输出触发的递归 `TripWire` 会把 `_GatesCurrent` 填上，此时直接返回，等外层循环继续。
3. `CheckLogicGate(lampX, lampY)`（`Terraria/Wiring.cs:720`）从灯所在列向下扫描，遇到 420 就统计其上连续的 419：`num2` 是灯总数，`num3` 是亮的数量（`frameX == 18` 记为亮，`Terraria/Wiring.cs:746-760`）。若是 `frameX == 36` 的装饰灯则标记 `flag3` 并停止扫描。
4. 按门类型（`frameY/18`，`Terraria/Wiring.cs:761-787`）求值：

| `frameY/18` | 门 | 判据 |
|---|---|---|
| 0 | AND | `num2 == num3` 全亮 |
| 1 | OR | `num3 > 0` 至少一盏 |
| 2 | NAND | `num2 != num3` 不是全亮 |
| 3 | NOR | `num3 == 0` 全灭 |
| 4 | XOR | `num3 == 1` 恰好一盏 |
| 5 | XNOR | `num3 != 1` 不是恰好一盏 |

5. 仅当结果与当前状态不同（`flag` 为门自身的 `frameX == 18`），且不处于"特殊态/装饰态"时（`Terraria/Wiring.cs:788-794`），才更新门帧、`SkipWire` 自身、同步瓦片（`Terraria/Wiring.cs:795-801`）。
6. 输出判定 `flag7`：装饰灯存在时按 `Main.rand.Next(num2) < num3` 随机决定亮灭（`Terraria/Wiring.cs:804-811`）——这是"骰子/随机门"的视觉表现。
7. 若需输出：门还不在 `_GatesDone` 中则入队 `_GatesNext`，等待下一轮 `TripWire`；若已在 `_GatesDone` 中则只打一个烟雾特效并广播（`Terraria/Wiring.cs:812-828`）——说明该门在本轮回合里已经输出过，不再重复参与。

> 注意：这种"轮次传播"并非同帧求到不动点；一个门的输出造成的下一级灯变化要等外层 while 下一次迭代处理，而迭代次数取决于拓扑是否收敛。`_GatesDone` 只在本轮回合内有效（`Terraria/Wiring.cs:689` 清空）。

### 8. 致动器（Actuator）

- `Actuate(i, j)`（`Terraria/Wiring.cs:389`）要求格上有致动器，然后按 `inActive()` 调 `ReActive` 或 `DeActive`；`ActuateForced`（`Terraria/Wiring.cs:407`）不检查有无致动器，供 `HitWireSingle` 使用。
- `DeActive`（`Terraria/Wiring.cs:3209`）有多层保护：无瓦片不处理；丛林神庙墙后的砖要打过世纪之花才允许（`Terraria/Wiring.cs:3211`）；只有"实心且非 NotReallySolid"的瓦片能虚化，并显式排除 314/379/386-389/476 等特殊类型（`Terraria/Wiring.cs:3215-3233`）；上一格有 `PreventsActuationUnder` 或 `CanKillTile` 为假则不改。真正虚化只是 `inActive(true)` + 重新排版 + 同步。
- `ReActive`（`Terraria/Wiring.cs:3239`）无条件恢复。
- 致动与元件逻辑在同一格上依次发生：先 `ActuateForced`，然后如果方块已被虚化，元件不再响应（`Terraria/Wiring.cs:1003-1010`）。

### 9. 压力板与计时器

**压力板**（135/428 等）不是"踩一下就触发"，而是由 `PressurePlateHelper`（`Terraria.GameContent/PressurePlateHelper.cs`）做进出边沿检测：

- 玩家移动时 `UpdatePlayerPosition`（`Terraria/Player.cs:28485`）比较本帧/上帧的 Hitbox 与板子的判定框，发现进入就记录"这个玩家站在板上"；
- `MoveAwayFrom`（`PressurePlateHelper.cs:130`）在所有玩家都离开之后才真正触发；
- 统一入口 `PokeLocation` 会先置 `Wiring.blockPlayerTeleportationForOneIteration`，再 `HitSwitch`（`PressurePlateHelper.cs:157-161`）；
- 该标志在 `LogicGatePass` 末尾被消费（`Terraria/Wiring.cs:714-717`），语义是"本 tick 的传送机不许把玩家传走"；逻辑传感器也在 `UpdateEndInternal` 里对它逐条赋值（`TELogicSensor.cs:87`）。

**计时器**（144）是"自触发的周期信号源"：`HitSwitch` 首次打开时 `CheckMech(i, j, 18000)`（`Terraria/Wiring.cs:303`），之后全靠 `UpdateMech` 里的 `Math.IEEERemainder` 分频判定定时把同一格再送进 `TripWire`（`Terraria/Wiring.cs:205-209`）——它不是独立对象，只是冷却表里一个"永远不会到 0 就重启"的条目。

### 10. 逻辑传感器（TELogicSensor）

瓦片 423 是**瓦片实体**而非纯 Tile，类型由 `frameY/18` 决定（昼/夜/玩家在上方/水/岩浆/蜂蜜/任意液体）。

- `Update()`（`TELogicSensor.cs:106`）比较当前状态（`TELogicSensor.cs:106-133`），只在状态变化时调用 `ChangeState(..., TripWire: true)`；
- `ChangeState`（`TELogicSensor.cs:135`）改 `frameX` 并同步瓦片，然后把 `(坐标, logicCheck == PlayerAbove)` 压入 `tripPoints`（`TELogicSensor.cs:145-148`，入队在第 147 行）；
- `UpdateEndInternal`（`TELogicSensor.cs:82`）在所有瓦片实体更新完后遍历 `tripPoints`，逐条设置 `blockPlayerTeleportationForOneIteration` 并 `HitSwitch`（`TELogicSensor.cs:85-88`），服务端再广播消息 59（`TELogicSensor.cs:89-92`）。

延迟两步是为了让同帧内多个传感器的触发顺序稳定，并保证读到的是本帧最终瓦片数据。另有两条绕过列表的路径：`Kill` 在传感器被移除时直接 `HitSwitch` 并广播 59（`TELogicSensor.cs:343`、`TELogicSensor.cs:367-368`）。

### 11. 水泵与液体结算

水泵没有"逐格转移"，而是**批量登记 + 一次性结算**：`HitWireSingle` 对 142/143 只往 `_inPump/_outPump` 塞最多 19 个坐标（`Terraria/Wiring.cs:2046-2120`），`TripWire` 在每个颜色跑完后调 `XferWater()`（`Terraria/Wiring.cs:475`）：外层遍历入泵、内层遍历出泵，液体量上限 255、颜色类型必须一致才转移，每次转移后 `SquareTileFrame` 刷新。**只有同一次 `TripWire` 收集到的入/出泵才配对**，不同颜色的泵不会互通。

### 12. 传送机

- 类型 235 被电到时只是把自身左上角记进 `_teleport[0]` 或 `_teleport[1]`（`Terraria/Wiring.cs:1553-1576`）。
- `TripWire` 每跑完一种颜色就把这两个坐标存进 8 槽结果数组（`Terraria/Wiring.cs:568-569`、`Terraria/Wiring.cs:624-625` 等），全部颜色结束后逐对取回并 `Teleport()`（`Terraria/Wiring.cs:655-665`）。
- `Teleport()`（`Terraria/Wiring.cs:3134`）先排除两台在竖直方向相邻的情况（`Terraria/Wiring.cs:3136-3139`），用 48x48、向上偏移的判定框与玩家/NPC Hitbox 求交：
  - 玩家传送受 `blockPlayerTeleportationForOneIteration` 门控（`Terraria/Wiring.cs:3156`），服务端还要 `RemoteClient.CheckSection` 并发消息 65；
  - NPC 传送要求 `lifeMax > 5`、非 Boss、非 `noTileCollide`、不在 `NPCID.Sets.TeleportationImmune` 中（`Terraria/Wiring.cs:3188-3199`）。
- `TeleporterHitboxIntersects`（`Terraria/Wiring.cs:3199`）用 `Rectangle.Union`（`Terraria/Wiring.cs:3201`）求两矩形的并集，再判定并集宽高不超过两矩形宽高之和（`Terraria/Wiring.cs:3202-3205`）；实现上反而多做了一次矩形构造，并非"避免额外分配"。

### 13. 网络同步

电路模拟只在服务端/单机进行：`TripWire` 第一行就在客户端返回（`Terraria/Wiring.cs:527-530`）。触发通过消息 **59** 扩散——服务端处理完 `HitSwitch` 后广播，客户端收到后本地重演（`MessageBuffer.cs:2684-2695`）。线缆本身的编辑用消息 **17**（`MessageBuffer.cs:1121-1122`、`MessageBuffer.cs:1241-1250`），批量布线用消息 **109**（`MessageBuffer.cs:3797-3811`）；传送、烟雾、开关门等动作另有 19/65/106 等消息。

## 设计要点与取舍

1. **颜色隔离 = 免费的多回路**。四种线在同一个 BFS 模板里跑四遍，而不是在一个大图里按颜色求连通分量；换来的是代码重复四份（`Terraria/Wiring.cs:534-665`），但也天然保证"不串线"。
2. **`SkipWire` 是系统的"隔离阀"**。多元件在改帧前先 `SkipWire` 全部占格，防止相邻线把同一元件连触多次；同时 `WorldGen` 里多处用 `Wiring.running` 判断后 `SkipWire`（例如 `WorldGen.cs:32042`、`WorldGen.cs:37933`、`WorldGen.cs:51263`），把"因电路而发生的方块变化"从遍历中摘掉。这是全局静态状态在工程上的妥协——假定了电路执行期间不会有并发的世界修改，而这正好符合 Terraria 单线程主循环的前提。
3. **冷却表是全局单例，不是元件的私有字段**。优点是不用给每种瓦片加字段、与其他系统解耦；代价是容量硬上限、`CheckMech` 为线性扫描、且"冷却键 = 左上角坐标"，所以 2x2/3x3 元件必须先折算到左上角。
4. **无递归、靠队列轮次传播**。逻辑门与传送都采用"本次只收集，下一次再结算"，避免 `TripWire` 里嵌套 `TripWire` 造成栈溢出与状态半更新。
5. **静默失败**。`CheckMech` 表满、`NPC.MechSpawn` 超出上限、漏斗找不到空箱子……都只是"什么都不做"（例如 `Terraria/Wiring.cs:464-472`），不报错也不提示，调试时只能观察现象。
6. **帧号被当作数据**。大量元件把 `frameX/frameY` 当作状态位/朝向/颜色位（429 的四色灯 `Terraria/Wiring.cs:1586-1621`、雕像编号），改帧就等于改逻辑状态，所以每次改帧后必须紧跟 `SendTileSquare`。
7. **坐标系是瓦片左上角，不是中心**。`HitSwitch` 收到的可能是多元件的任意一格，所有分支开头都要做一次"折算到左上角"。
8. **显式类型硬编码**。`HitWireSingle` 是 1500 多行的巨型 switch，每类元件的帧动画、特效、网络包都写死在这里，扩展新家具最方便，但维护极难，也是 Mod 引擎（tModLoader）必须打补丁的重灾区。
