# 世界生成系统（WorldGen）

> 分析对象：Terraria v1.4.5.8 反编译源码。下文所有 `路径:行号` 均相对 `decompiled/Terraria/`，行号为 1-based。
> `Terraria/WorldGen.cs` 有 87346 行，绝大多数 pass 主体仍是 C# 2 时代的机械命名（`num3`、`flag2`、`val`）。阅读时把 `num*` 当局部临时变量、`flag*` 当布尔状态位，按上下文翻译。

## 一句话结论

世界生成是一条**按名字注册、按权重计进度、逐 pass 串行执行**的直线流水线：`WorldGen.GenerateWorld` 先 `clearWorld` / `Reset` 铺好全局变量与前哨参数，`AddPasses` 用约 110 个 `PassLegacy`（名字 + 委托）顺序追加进 `WorldGenerator`，后者在 `while(true)` 里按"已完成 pass 数"逐个执行、每个 pass 之后记录哈希并支持快照/暂停/回退；每个 pass 内部要么是老式 `TileRunner` / `ChasmRunner` 蛇形描刷，要么是 `WorldBuilding` 那套"形状扫过一片区域、动作链决定每个格点做什么"的小 DSL，生物群系、地牢、宝箱再在这个基础上叠加 `StructureMap` 占位保护。

## 执行流程

### 第 0 步：入口与全局重置

1. `WorldGen.GenerateWorld`（Terraria/WorldGen.cs:11020）是世界生成入口。它置位 `generatingWorld` 等一组全局标志，加载内嵌配置 `WorldGenConfiguration.FromEmbeddedPath(...)`（WorldGen.cs:11036，实现见 Terraria.WorldBuilding/WorldGenConfiguration.cs:69），再构造 `new WorldGenerator(Main.ActiveWorldFileData.Seed, ...)`（WorldGen.cs:11038）。
2. 固定顺序：`clearWorld()` → `Reset()` → `AddPasses()` → `DisablePassesForSpecialSeeds()` → `_generator.GenerateWorld()` → `Finish()`（WorldGen.cs:11039-11045）；`finally` 中把所有特殊种子开关复位（WorldGen.cs:11047-11062）。
3. `Reset()`（WorldGen.cs:11065）做两件事。其一，从 `WorldGenerationOptions.Get<WorldSeedOption_*>()` 读出特殊种子开关，写入 `Main.*` 与 `WorldGen.*` 静态字段（WorldGen.cs:11071-11080）。其二，初始化 `GenVars` 全部跨 pass 共享量：铜/铁/银/金的瓦片 ID（7/6/9/8，WorldGen.cs:11117-11120）、`beachBordersWidth = 275`（WorldGen.cs:11147）、`oceanWaterStartRandomMin = 220`（WorldGen.cs:11152）、`skyLakes` 随宽度递增（WorldGen.cs:11138-11145）、`crimsonLeft` 随机（WorldGen.cs:11173-11179）。这些常量是后续 pass 的"世界级前哨参数"，例如 `evilBiomeBeachAvoidance` 由 `beachSandRandomCenter + 60` 算出（WorldGen.cs:11157）。
4. 地牢朝向与丛林位置也在 `Reset` 中定下：`dungeonSide` 由 `genRand.Next(2)` 选左右（WorldGen.cs:11301），随后据此把 `jungleOriginX` 放在世界另一端（WorldGen.cs:11304-11329）；醉汉世界会把朝向再翻转一次（WorldGen.cs:11335-11338）。

### 第 1 步：注册 pass（AddPasses）

5. `AddPasses()`（Terraria/WorldGen.cs:11466 起）是一串 112 次 `AddGenerationPass(...)` 调用，从 `new TerrainPass()`（WorldGen.cs:11468）到 `GenPassNameID.FinalCleanup`（WorldGen.cs:22249）。三个重载最终都落到 `_generator.Append(...)`（WorldGen.cs:10053-10066），**注册顺序即执行顺序**。
6. pass 名字是 `GenPassNameID` 里的常量字符串（Terraria.ID/GenPassNameID.cs:5 起），**同一个名字同时充当进度权重键、JSON 配置键和 manifest 键**；改名字等价于换了一个 pass。
7. 部分 pass 是条件注册：`Skyblock` 只在 `skyblockWorldGen` 时注册（WorldGen.cs:11474-11480），`DualDungeonsDitherSnake` 只在双地牢种子下注册（WorldGen.cs:14750-14753）；而 `DisablePassesForSpecialSeeds`（WorldGen.cs:22605）在双地牢种子下直接 `Disable()` 掉冰原、沙漠、丛林、神庙、腐化、微光等 pass（WorldGen.cs:22612-22620）。被禁用的 pass 仍留在列表里，执行时记为 `Skipped`（WorldGenerator.cs:498-506）。

### 第 2 步：生成器主循环

8. `WorldGenerator.GenerateWorld`（Terraria.WorldBuilding/WorldGenerator.cs:421）先挂上 `_controller` 并计算总权重 = 所有启用 pass 的 `Weight` 之和（WorldGenerator.cs:424-426）。主循环位于 WorldGenerator.cs:433 的 `while(true)`：请求中止则跳出（435-439）；被暂停则每 10ms 空转（`OnPaused`，114-119）；否则在 `_controlLock` 内取 `_passes[PassResults.Count]` 执行（451-458）——**用已完成数当下标**，既不重跑也不跳号。
9. `RunPass`（WorldGenerator.cs:496）每次都会 `Main.rand = new UnifiedRandom(_seed)`（507-508）。被重设的是 `Main.rand`，而 DSL 用的是 `genRand`（GenBase.cs:9），两者是不同随机源；本 pass 结束时再取一次 `WorldGen.genRand.Next()` 记入结果（WorldGenerator.cs:522），用于判定随机序列是否一致。随后 `_progress.Start(Weight)` → `pass.Apply(progress, 配置)` → `_progress.End()`，异常只记录不中断（509-520），最后断言**两个 pass 之间不得残留活动液体**（WorldGenerator.cs:521）。这正是 `SettleLiquids` 被拆成几段、夹在流水线中间的原因。
10. pass 结束后 `OnPassCompleted`（WorldGenerator.cs:122）：只在调试 UI 打开或已是最后一个 pass 时计算 `HashWorld()`（128-131），再按 `SnapshotFrequency` 决定是否存快照（141-161），最后 `CheckLatestPassResultAgainstManifest`（173）把本次结果与旧 manifest 比较——名字、`RandNext` 采样、世界哈希任一不同即判定输出变化（`Matches`，GenPassResult.cs:22-33），开发模式下会暂停并载入旧快照供比对。哈希本体是"逐列滚动哈希再折叠"的两级结构（WorldGenerator.cs:527 起）。

### 第 3 步：地形塑造（TerrainPass）

11. `TerrainPass`（Terraria.GameContent.Biomes/TerrainPass.cs:10）是所有地形的底子。它按列扫描整幅世界宽度，维护两类量：`num3` = 当前列地表高度（下称 surface）、`num4` = 当前列土石分界高度（下称 rockStart），以及四个历史极值 `num5/num6/num7/num8`（最终写回 `GenVars`，TerrainPass.cs:225-236）。
12. 初值：地表约为 `0.3H × (0.9~1.1)`（TerrainPass.cs:61-63），土石分界 = 地表 + `0.2H × (0.9~1.1)`（64-66）。每列按"地貌段"推进：段型从 Plateau/Hill/Dale/Mountain/Valley 随机（93-100），段长 5~40 列，Plateau 会被大幅拉长。每列高度增量由 `GenerateWorldSurfaceOffset`（TerrainPass.cs:293）给出——用"几何分布的 while 循环"（例如 Mountain 为 `while(rand.Next(0,2)==0) num-=1`）制造指数长尾，所以山是"多数列缓变、少数列陡升"。醉汉/For the Worthy/Remix 走另一套系数（TerrainPass.cs:295 起）。
13. 两条硬约束保证出生区好走：世界水平 45%~55% 禁用山/谷段（TerrainPass.cs:102-105），48%~52% 强制 Plateau（106-109）；地表夹在 `0.17H`~`0.26H` 之间，小世界下界抬到 0.19H（116-148）。接近海滩时改用 `0.23H` 作上界，并在 `rightBeachStart` 处调用 `RetargetSurfaceHistory`（181-188、409）这是${Q}把海岸线压平${Q}的实现：以 500 列为窗口，把最近记录的地表高度逐列下调 1 格直到不超过海滩高度，再交给 `RetargetColumn`（TerrainPass.cs:264）重填整列（`RetargetColumn` 只保证地表以下是土/石，不会把山推得更高）。
14. 正式落笔只有 `FillColumn`（TerrainPass.cs:242）：地表以上清空，地表到土石分界填土（type 0），其下填石（type 1）。**整张图的土石分布在这一步定型**，后续 pass 只做挖、换、盖。
15. 收尾把土石分界波动约束在 `surface + 0.06H`~`surface + 0.35H`（174-193），再写 `Main.worldSurface / Main.rockLayer` 与 `GenVars.waterLine/lavaLine`（195-236）。`lavaLine` 既是地狱岩浆高度，也参与 `TileRunner` 的液体判定。Remix 世界把 `rockLayer` 下移到 `0.5~0.6H`（68-73），是 Remix 地形改版的基础。

### 第 4 步：DSL 的执行模型

16. `WorldUtils.Gen(origin, shape, action)` 只是 `shape.Perform(origin, action)`（Terraria.WorldBuilding/WorldUtils.cs:40-43）。`Shapes.Circle` 采用逐行求椭圆交点的扫描：每行先算 `|dx| = r·h·dy` 再开方（Terraria.WorldBuilding/Shapes.cs:31-40），因此椭圆即使压扁也平滑；`Shapes.Rectangle` 用 `Rectangle.Left/Right/Top/Bottom` 偏移（Shapes.cs:168-177）。
17. 动作链的语义是"**每个点依次通过，前一个返回 true 才进入下一个**"：`Actions.Chain(params GenAction[])` 只负责串起 `NextAction`（Terraria.WorldBuilding/Actions.cs:624-631），`GenAction.UnitApply` 若存在后继就继续下探（Terraria.WorldBuilding/GenAction.cs:15-26）。所以 `Chain(A, B, C)` 不是"先做 A 再做 B"，而是"A 先当筛子，通过的点交给 B，再交给 C"。有副作用的动作（`SetTile`、`PlaceWall`）通常放在链尾。
18. 失败语义有一处反直觉：`Fail()` 返回 `!_returnFalseOnFailure`（GenAction.cs:34-37）。默认 `_returnFalseOnFailure = true` 即"失败返回 false"；调用 `IgnoreFailures()` 后失败变为返回 true，链不会断。形状侧只有 `QuitOnFail(true)` 才会中止整个 `Perform`（Shapes.cs:38-41），否则失败点被跳过、继续扫描。
19. 常用动作的工程含义：`Modifiers.Conditions` 对条件做 AND 过滤（Terraria.WorldBuilding/Modifiers.cs:188-210）；`IsAboveHeight/IsBelowHeight` 按 Y 坐标裁剪（Modifiers.cs:491-533）；`Blotches` 按概率把单点扩成随机大小的块（Modifiers.cs:88-148，注意它先空转一次 `NextDouble()` 再判定，会影响随机序列）；`Actions.Scanner` 只在链路走到时计数（Actions.cs:44-57），`Actions.TileScanner` 按瓦片 ID 分类统计（Actions.cs:60-91）；`SetTile` / `SetWall` 是落笔（Actions.cs:203、238）。
20. 最小实例（Terraria.GameContent.Biomes/HiveBiome.cs:24-28）：用 `Circle(15)` 扫半径 15 的区域，链上 `IsSolid` + `Scanner` 数出实心格总数，再用 `OnlyTiles(60,59)` + `Scanner` 数泥/丛林草，最后用 `OnlyTiles(60)` + `Scanner` 数纯泥；随后以"泥占实心格比例 ≥ 0.75 且纯泥 ≥ 2"作为放蜂巢的前置条件。一个"这里够不够湿润"的测试就被写成了一串区域统计加阈值。
21. 搜索侧：`Searches.Left/Right/Up/Down` 沿方向逐格找，`Searches.Rectangle` 在矩形内按行优先找（Terraria.WorldBuilding/Searches.cs:109-124）；`Check` 用 `_requireAll ^ cond.IsValid` 实现"全部满足 / 任一满足"（Terraria.WorldBuilding/GenSearch.cs:21-31），`RequireAll(false)` 即 OR。
22. `SimpleStructure`（Terraria.WorldBuilding/SimpleStructure.cs:5）把字符图当模板：`_data[i,j]` 是动作下标，`-1` 表示空白，支持水平/垂直镜像（SimpleStructure.cs:61-66）。`Place` 开头先 `structures.CanPlace`、成功后再 `AddProtectedStructure`（SimpleStructure.cs:68-87），模板结构天然带占位保护。

### 第 5 步：生物群系放置

23. **条带式摆位**（大理石、花岗岩）：`Marble`（WorldGen.cs:12739）把宽度 `maxTilesX - 160` 均分成若干段，第 k 段在本段的 X 区间内抽样（WorldGen.cs:12749、12769），Y 落在 `rockLayer + 20` 到 `maxTilesY - 240` 之间；若抽到世界正中 45%~55% 就重抽（12801-12804），避免压住出生点。
24. **放置成功才推进计数**：`Marble` 每次成功才 `num4++`，失败则累计尝试数，达到 `maxTilesX * 10` 强制推进（WorldGen.cs:12808-12819）。**用尝试上限保证世界塞满时也一定能结束**，代价是密度不可控。
25. **统一经 `GenVars.configuration.CreateBiome<T>()` 创建**（WorldGen.cs:12750）：按类名在 JSON 的 `Biomes` 节点反序列化，无配置则 `new T()`（Terraria.WorldBuilding/WorldGenConfiguration.cs:45-53）。同理每个 pass 拿到的是 `Passes` 节点下按 pass 名切出的子配置（WorldGenConfiguration.cs:55-65）。该 JSON 是嵌入资源，本仓库未导出，**其具体数值未验证**。
26. **微群系**（`MicroBiomes`，WorldGen.cs:20982）把许多小玩法合成一个 pass：先按 `DeadManChests` 数量把**已埋好的宝箱**改造成死人箱（`GetPossibleChestsToTrapify` 位于 Terraria.GameContent.Biomes/DeadMansChestBiome.cs:411），WorldGen.cs:20998-21012），再依次放薄冰、剑冢、营地、爆炸矿等。每项都是"`RandomWorldPoint` 抽样 → 放置 → 连续失败 1000 次后放弃"（WorldGen.cs:21038-21052）。
27. 所有群系落笔前都先调 `structures.CanPlace`，成功后 `AddProtectedStructure`（HiveBiome.cs:13、105）——这是"群系互不覆盖"的统一入口；丛林/冰原的原点 X 早在 `Reset` 中就确定，后续 pass 只是围绕它工作。

### 第 6 步：腐化/猩红与蛇形描刷

28. `CorruptionAndCrimson`（WorldGen.cs:13858）先全图扫描丛林（type 60）与腐化瓦片（147/161）的 X 范围（WorldGen.cs:13873-13902），再按 `0.00045 × W` 的循环生成若干条腐化带。每条带随机中心 `num15` 与左右界 `num16/num17`（中心 ± 100~300），失败则整条重掷（WorldGen.cs:13936-14037），检查项包括：越界与海滩避让 `evilBiomeBeachAvoidance`、与世界中心重叠、与地下沙漠矩形重叠、与丛林或已有腐化带的 X 区间重叠。**整条重来而非局部修补**，所以腐化带总是完整块状。
29. 带内先打核心（非翻转感染时调用 `CrimStart`，WorldGen.cs:14040-14043），再沿 X 逐列处理：碰到地表就用 `ChasmRunner` 打竖井（14046-14060），其余列把表层丛林草换成 662 号瓦片（14076-14094）。这种"沿一条线逐列处理"的写法在本文件里反复出现。
30. `ChasmRunner(i, j, steps, makeOrb)`（WorldGen.cs:76299）是**所有蛇形洞/竖井的通用原型**：位置点 + 速度向量（X 初始 ±1、Y 初始 0.5~1.5），每步半径在 7~20 间抖动并随深度收缩（76325-76355），每步按**曼哈顿距离** `|dx| + |dy| < r × 0.5 × (1±15%)` 清空方块（76343-76357）——并非欧氏圆，洞壁呈菱形，观感更自然。下到地表以下 20 格处分叉出左右侧通道（76350-76355），尽头放暗影珠/猩红之心（76368-76378）。
31. `TileRunner(i, j, strength, steps, type, ...)`（WorldGen.cs:77188）是矿脉、沙地、隧道的通用团块刷子，与 `ChasmRunner` 同源：每步有效半径按剩余步数衰减（77248-77250），速度随机游走，落笔前过滤：不覆盖帧敏感且不可切的瓦片（77294）；`overRide` 时若目标为石质且非石头、或不允许在生成期清除，则跳过（77328-77331）；随后对沙漠/丛林/地表做特例判断（77334-77347）。`type == -2` 是特殊值：只按 `waterLine/lavaLine` 灌液体而不落瓦片（77313-77326）。落笔后按 `addTile` 决定是否激活、按 `noYChange` 把地表墙改回泥土墙（77395-77401）。

### 第 7 步：宝箱与矿石分布

32. **矿石**（`Shinies`，WorldGen.cs:13172）的核心模型是"**数量正比于世界面积，位置在深度带内均匀抽样**"。普通世界分支（从 WorldGen.cs:13388 起的 `else`）：
    - 铜：`6e-5·W·H` 次在 `worldSurfaceLow~worldSurfaceHigh`，`8e-5` 次在 `worldSurfaceHigh~rockLayerHigh`，`2e-4` 次在 `rockLayerLow~maxTilesY`（WorldGen.cs:13390-13403）；
    - 铁、银、金重复同一三段式（WorldGen.cs:13451-13534），每段半径与步数逐级增大；
    - 顶部稀有银/金：`1.7e-4` 与 `1.2e-4` 次落在 `0~worldSurfaceLow`（WorldGen.cs:13536-13565），是浮空岛附近的矿源；
    - 地狱矿：type 204 与 22 落在 `rockLayer~maxTilesY`（WorldGen.cs:13566-13572）；
    - 魔矿/猩红矿按 `crimson` 二选一，type 204 或 22（WorldGen.cs:13371-13386）。
33. **"低阶矿浅、高阶矿深"不是硬编码深度阈值，而是多段三角分布叠加的结果。**
34. 需要强调：上面这些是**普通世界**的数值。同一 pass 的 Remix 分支（WorldGen.cs:13177-13386）在结构上完全平行——每一段都是"铜→铁→银→金"的四联循环，只是深度带与密度换了参数；醉汉世界则通过 `GenVars.copper/iron/silver/gold` 在 7/166、6/167、9/168、8/169 间二选一（WorldGen.cs:13188-13202），让同一世界混排两套矿。`TileRunner` 的"替换而非新增"语义（见第 31 条）保证矿石只会顶替普通土石。
35. 浮空岛附近的矿源仍是同一机制：在 `0~worldSurfaceLow` 这一段单独再循环一次银/金（WorldGen.cs:13536-13565），所谓"天空岛周围有矿"其实是深度带抽样的结果，而非岛屿专属逻辑。
36. 宝石、微光、宝石洞由后续独立 pass 处理（Gems 15048、Shimmer 15195、Gem Caves 17462），与矿石解耦，便于单独调参。
37. **宝箱**：`UndergroundHousesAndBuriedChests`（WorldGen.cs:17000）从配置读出 `CaveHouseCount / UnderworldChestCount / CaveChestCount / AdditionalDesertHouseCount` 四个 `WorldGenRange`（WorldGen.cs:17013-17016），分别生成洞穴房屋、地狱箱、普通埋箱与沙漠附加房屋。`WorldGenRange` 支持 `WorldArea / WorldWidth` 缩放（Terraria.WorldBuilding/WorldGenRange.cs:40-60），**大世界箱子更多就是在这一步按面积放大的**。抽样点落在地牢墙、蜘蛛洞墙或海底则本次作废重抽（WorldGen.cs:17034-17056）。
38. 所有箱子最终走 `AddBuriedChest(i, j, ...)`（WorldGen.cs:36093）：从 `j` 向下逐格找第一个 `SolidTile`，途中遇到微光、巨石或其它箱子直接放弃（WorldGen.cs:36109-36133）；找到后依据**深度、墙体类型（地牢/沙漠/雪原）与 `chestStyle` 参数**决定箱体样式与主物品——地下沙漠区域强制升级为沙漠箱（`IsUndergroundDesert`，WorldGen.cs:35969-35995、36260-36280），地表附近强制为地表箱（36066-36069）。随后 `PlaceChest(i-1, y-1, ...)`（36422）走 `TileObject.CanPlace → TileObject.Place → Chest.CreateChest`（WorldGen.cs:58117-58143），由 `Chest.CreateChest` 从空槽位分配全局箱索引（Terraria/Chest.cs:584-602）。物品在 `AddBuriedChest` 末尾逐槽 `SetDefaults`（WorldGen.cs:36424 起），主物品由深度/群系决定，其余按同一套表填充。

### 第 8 步：地牢生成（DungeonCrawler）

39. `Dungeon` pass（WorldGen.cs:14755）先 `SetupDungeonData` 与 `SetupDungeonGenVarVariables`，再按 `dungeonLocation` 在 `(worldSurface + rockLayer)/2 ± 200` 附近寻找第一个"下方 10 格全实心"的 Y 作为入口高度（WorldGen.cs:14770-14816）。
40. `DungeonCrawler.MakeDungeon`（Terraria.GameContent.Generation.Dungeon/DungeonCrawler.cs:340）是子系统主函数：置 `GeneratingDungeon = true`，临时取消裂纹砖实心（`SetCrackedBrickSolidity(false)`，DungeonCrawler.cs:349），总步数 `maxTilesX / 60 + rand`（DungeonCrawler.cs:360-364）。
    - **布局**：普通地牢用 `LegacyDungeonLayoutProvider`（DungeonCrawler.cs:381-386），双地牢用 `DualDungeonLayoutProvider`。前者（Terraria.GameContent.Generation.Dungeon.LayoutProviders/LegacyDungeonLayoutProvider.cs:20）就是"爬行"：先放起始房间，之后 `while(steps > 0)` 每步以 1/3 概率尝试放房间（其中一半先铺走廊），否则只铺走廊，`roomDelay` 控制节奏（同文件:44-97）。**地牢"岔路多、房间散"来自每步按概率决定放什么，而非预先规划平面图。**
    - **入口**：`while(!createdDungeonEntranceOnSurface)`（DungeonCrawler.cs:409-439）沿"当前高度 → 预计算地表入口点"逐段生成入口走廊；使用预计算入口时用 `Lerp` 求每段终点（DungeonCrawler.cs:498-525），保证入口一定落在 `dungeonEntrancePosition`；该位置的地表入口设置在此前通过 `MakeDungeon_GetEntranceSettings` 预先生成（DungeonCrawler.cs:210）。
    - **后处理**：先 `CalculatePlatformsAndDoors` 补平台与门（DungeonCrawler.cs:443-477），再按固定顺序叠 `DungeonGlobal*Features`：尖刺 → 门 → 墙变体 → 平台 → 生物群系箱 → 书架 → 普通箱 → 光照 → 陷阱 → 地面家具 → 画 → 横幅（DungeonCrawler.cs:478-494）。**顺序即依赖**：生物群系箱必须在墙变体之后，光照必须在陷阱之前。
41. 地牢样式由 `SetupDungeonGenVarVariables` 决定：`genRand.Next(3)` 选蓝/绿/粉三套砖与墙 ID（DungeonCrawler.cs:56-93），Remix 改为跟随 `Main.crimson`（DungeonCrawler.cs:56-59）。双地牢种子额外挂 Cavern、Corruption/Crimson、Jungle 或 Snow/Desert/Hallow/Temple 子样式（DungeonCrawler.cs:110-127），并把全部子样式的砖/墙类型并入 `isDungeonTile / isDungeonWall` 等判定数组（DungeonCrawler.cs:132-172）——这正是"双地牢的墙也能被认作地牢墙"的机制。
42. `GenVars.dungeonGenVars` 是列表（双地牢时长度 2），`GenVars.CurrentDungeon` 是"当前操作哪个地牢"的游标（`GenerateWorld_SetupDungeonGenVars`，WorldGen.cs:11000-11011）；`DungeonCrawler.CurrentDungeonData` 用同一个游标取 `dungeonData[GenVars.CurrentDungeon]`（DungeonCrawler.cs:20-31）。这是典型的"全局游标 + 列表"写法，改动时必须成对维护。

## 设计要点与取舍

- **直线流水线、顺序即依赖**。没有 DAG、没有声明式依赖；每个 pass 都假定前面的 pass 已放好该放的东西（例如 `Marble` 靠"扫瓦片"判断位置，前提是丛林/沙漠已经刷完）。插入新 pass 时必须人工推导它对后续所有 pass 的影响。
- **整张图就是一块 `Tile[,] Main.tile`**，`GenBase` 只是一层静态属性（GenBase.cs:9-15）。这让"暴力直接改方块"成为可能，也让世界生成难以并行、难以单测。
- **确定性优先**。每个 pass 结果都记录 `RandNext` 与世界哈希（GenPassResult.cs:7-19），`WorldManifest` 可精确复现一次生成；快照让调试能分段比对（`SnapshotFrequency`，WorldGenerator.cs:15-21）。代价是**任何随机序列的微小改动都会改变整个世界**，这解释了官方"只加不改"的补丁习惯。
- **概率碎片而非全局规划**。腐化带、地牢房间、浮空岛、大理石都是"抽样 → 检查 → 失败就用上限放弃"。代码短、鲁棒，但密度无法精确控制，只能靠 `maxTilesX * 10` 这类魔法数兜底（WorldGen.cs:12814）。
- **占位表是软约束**。`StructureMap` 只做矩形相交与瓦片白名单两件事（StructureMap.cs:24-63），粒度是块级而非格级，因此允许边缘重叠来换取过渡观感；真正"不重叠"只对 `AddProtectedStructure` 的矩形成立。
- **同一算法反复复用**。`ChasmRunner` 与 `TileRunner` 是一对"按步生长"的原型，腐化、矿脉、沙地、隧道、地狱裂隙几十处都在调用，只是参数不同。代价是 `TileRunner` 内堆满 `drunkWorldGen / remixWorldGen / getGoodWorldGen` 特判（WorldGen.cs:77190-77194、77313-77347），可读性差。
- **每条规则都有反例出口**。几乎所有关键位置判定都在最前面加了特殊种子分支（`SecretSeed.*.Enabled`、`remixWorldGen`、`drunkWorldGen`），例如沙漠/丛林/腐化 pass 在双地牢种子下被整体禁用（WorldGen.cs:22616-22619）。这是向后兼容改动妥协的产物，也意味着"某个 bug 只在某种子下复现"是常态。
- **DSL 只覆盖可组合的小操作**，大结构（地牢、神庙、生命树）仍用手写代码或字符模板（`SimpleStructure`）。抽象层薄、上手快，但表达力不足以描述"房间—走廊—入口"这类拓扑。
- **配置只外置了一部分**。数量、概率与部分结构参数走 JSON，但**矿石密度、地形起伏等核心常量仍硬编码在 C# 里**（如 WorldGen.cs:13390 的 `6E-05`），所以"改世界"多数时候仍是改代码。
- **随机化的两个来源**。世界生成大量使用 `WorldGen.genRand`（GenBase.cs:9），而 `RunPass` 重置的是 `Main.rand`（WorldGenerator.cs:507）；调试时若只替换其中一个，世界会"部分相同、部分不同"，这是排查"同种子不同世界"时最容易踩的坑。

- **pass 粒度与调试**。`Controller`（WorldGenerator.cs:20 起）把"暂停、回退到上一 pass、跳到指定 pass、载入快照"都做成了可复用能力（`TryRunToEndOfPass` WorldGenerator.cs:317、`TryResetToPreviousPass` WorldGenerator.cs:359），并依赖 `GenPassNameID` 的稳定名字定位 pass——名字就是稳定 API。

- **编译器语法糖提示**：`AddPasses` 里的 112 个 `AddGenerationPass(name, delegate {...})` 都是"构造 `PassLegacy` 并追加"，脑内折叠为"往列表追加一对 (名字, 函数)"；`WorldGenerator` 里的 `Passes.Where(...).Sum(...)`、`Passes.Take(n).Reverse().FirstOrDefault(...)` 是 LINQ 迭代器状态机，读作普通循环即可。
